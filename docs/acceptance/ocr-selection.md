# OCR 方案选择

用于比较当前本地识别方案与替代方案。产品范围仍以 [PRODUCT_SCOPE](../PRODUCT_SCOPE.md) 为准；以下是本轮选型规则，不增加用户必须购买的设备、服务或人工验收事项。当前授权与结论在[项目状态](../plans/run-state.md)。

## 冻结与输入

先冻结本规则，再固定输入及真值，最后开始模型实验。基线为 `16579877` 的完整 A+B；A 是官方 PaddleOCR-VL 管线，B 是额外 PP-OCRv5 CPU 复核。首先只移除 B 做消融，随后比较其他可行识别路线。用户偏好足够准确、等待更短的单路 A，允许零星可校对错误；不以疑点数量、第二路复核或零错误承诺作为胜出条件。

固定 12 张可读材料页，覆盖中文、稠密公式、轻斜扫描、真实教学表格、配图与图中标注。8 页用于开发，4 页用于留出验收；同一内容的变体及连续跨页内容按组分配，不跨两组。破损 F 另列，不加入普通质量、速度分母。固定文件摘要、来源、分组与人工真值后才运行模型；真值来自原图或作者源稿，禁止参照模型输出编造预期。

机器输入和真值归测试目录；公开外部原件提供下载位置及摘要。输出、截图和分段日志写 `test-results/ocr-selection/`。不可用旧 raw 回放代替本次真实推理，不可用历史 Git 对象或本机独有目录作为复现前置。 两条最终对照路线的冻结基线源码、公开安装来源与直接复测命令随[复测入口](../../apps/api/test/fixtures/ocr-selection/reproduction/README.md)入库；该入口仅供显式比较，不参与产品运行或默认 API 回归。

## 质量判据

评价输入页图到未经人工修正的原始识别输出；后续 Document 转换、拆题和人工校对另验，不能回填识别成绩。使用逐页分子/分母及分类汇总，不计算一个混合总分。

| 指标 | 本轮入围门槛 | 计算规则 |
| --- | --- | --- |
| 正文字符错误率 CER | ≤2% | 正文参考序列的编辑距离 / 参考字符数；统一空白与全半角，保留数字、文字和有意义的标点 |
| 公式正确率 | ≥95% | 以冻结的完整公式为单位，数学含义和条件完整才正确；等价 LaTeX 不扣分，负号、指数、端点、条件变化扣分 |
| 表格单元格正确率 | ≥95% | 内容和行列归属均正确；合并单元格按原稿逻辑区域计数 |
| 重要内容块召回 | ≥98% | 冻结的正文、公式、表格、配图区域是否保留；内容正确性按以上指标另计 |

整页、整栏遗漏，公式系统性乱码，或图中关键标注系统性丢失，不能被其他页平均稀释，直接淘汰。配图保留原始图像和可定位区域，不要求把图形本身转成可编辑矢量图。零星错误列出实际例子。F 仅报告可见内容保留、虚构和失败行为，不要求恢复被遮挡的信息；不把模型置信度当作正确性证明。

图内公式与正文公式按模型运行前真值中的 `scope` 区分，不能根据某个候选是否输出图片调整归属。正文和表格公式须有正确数学文本，嵌套表格也须恢复内容与行列，保留整张栅格不算转写成功。图内标注按原图保真核对，并单列文字转写数；报告同时列出全部公式清单的文本正确数，以及需转写公式的正确率，不能用原图保留冒充公式识别。开发集总计 65 个公式，其中 4 个预先标为 `figure`，正文/表格门槛分母为 61，表格单元格仍为全部 78 格。该歧义在首轮基线推理后、候选评分前明确，原始真值和 95% 门槛不变，报告保留全部 65 个公式的原始成绩。

入围者在产品中抽查最差两页和普通两页，验证能对照原稿定位、修改、保存、重开。记录修改点和是否需要整题/整段重录。agent 操作仅证明校对路径和修订量，不冒充教师人工速度。

## 等待与资源

固定同一机器、电源状态与页顺序，GPU 实验串行。冷启动指进程退出且模型未驻留、权重已下载；不声称清空了操作系统文件缓存。热测必须真正推理，不得命中识别结果缓存。记录页图就绪到 raw 返回的识别时间，同时用实际题库上传记录首次可用结果与整批完成时间。

记录冷首张、热单页中位/最慢、8 页连续批次总时长。初筛一轮，入围者和基线同配置各三轮；保留原始值，不能只选最好一轮。拆分环境校验、模型加载、A、B 与序列化，记录峰值显存/RAM、OOM、交换与失败重试。

最终候选在质量过线的前提下，热批次中位总时长应比完整 A+B 缩短至少 30%，冷首张不慢超过 10%，无 OOM，不依赖持续交换。热普通页中位 ≤10 秒、冷首张 ≤20 秒作为体验优化目标，未达到须明确报告，不可冒称承诺已满足。本轮只使用本机可运行、许可允许的路线；不调用收费服务或上传私人材料。

## 选择与停止

研究覆盖端到端文档 VLM、版面分析配合小模型的组合、通用 VLM 与商业 OCR。依据中文数学、表格、输出定位、许可、实际硬件和可获取性筛选，明确每个排除理由；榜单只用来筛选，不能代替本机成绩。短名单由调研证据决定，不预先锁定现有模型或任意数量的候选。

每条入围路线初测后最多两轮有明确失败原因的调参；新证据证明方案不适合时更换方案。先比较开发集质量与时间，再由前两名一次性运行留出集，按相同门槛检验。留出失败后不得用同一留出集继续调参并仍称留出验收；确需第二轮，先更换留出输入并记录原因。

满足质量、速度、资源和三个消费者的真实集成验证，且已覆盖有竞争力的可行路线后，可结束选型。连续三项有依据的实验均无至少 10% 速度收益且无质量改善，可判定当前搜索收益趋小。所有方案不达标时继续定位或更换路线，不修改门槛伪造成功；最终报告区分实测、仅调研、硬件不可运行和未验证结论。

## 当前选型证据

已选定接入候选为 MinerU 4.0.10 Standard、Pro-2605 Q8 与固定的表格 LaTeX 提示。以下是原始识别实验结果；真实产品接入、生命周期和独立检出验证仍在进行，尚未交付 preview。当前安装清单和提示随代码入库，不以实验目录作为运行前置。

只移除 B、再使 Paddle A 驻留，均没有改变主识别的原文；八页探索用时分别约 232 秒和 60 秒。基线 A+B 另完成三轮正式测量。去掉 B 能节省重复识别，但每页重载模型也是原等待时间的重要来源。

### 留出质量

只有一个替代方案通过开发门槛，故一次留出比较该候选和未改变的原 A+B 控制组，不为凑两个名额而提升已失败路线。各自 H1-H4 只运行一次，没有重复冷页或事后调参。

| 路线 | 正文 CER | 冻结公式分 | 表格单元格 | 重要块 |
| --- | ---: | ---: | ---: | ---: |
| MinerU 候选 | 14/1593，0.88% | 38/39 | 8/8 | 103/103 |
| 原 A+B | 11/1593，0.69% | 37/39 | 8/8 | 103/103 |

原稿 H2-f5 印的是 `3√3`，冻结真值录成了 `3√13`，两路线都忠实识别了原稿。原真值文件保持冻结，逐项勘误在 `apps/api/test/fixtures/ocr-selection/heldout.errata.json`。按同一勘误计算，候选为 39/39，原 A+B 为 38/39；其他指标不变。候选在勘误前后均达标。原 A+B 的 H4 末式还有多余符号和错排，这是实际识别错误。识别任务按原稿评分，不替教材纠正数学。

### 实际题库等待

同一组八页，从真实登录后的上传入口点击“开始整理”，原方案与候选各一轮。运行预检、模型加载、识别、机械转换和题库处理均计入；未使用识别结果缓存。

| 用户可见节点 | 原 A+B | MinerU 候选 |
| --- | ---: | ---: |
| 首次可见结果 | 36.52 秒 | 10.65 秒 |
| 整批处理结束 | 257.96 秒 | 34.06 秒，缩短 86.80% |
| 可以编辑题目 | 258.77 秒 | 34.87 秒 |

候选冷首张从页图就绪到 raw 返回为 7.72 秒，原为 32.77 秒；候选后续七页中位为 3.68 秒、最慢 5.96 秒。冷页和热批次满足预设门槛。八页 OCR 全部返回，但两路线都存在教学表格的题目/活动归属待处理，因此题库任务为 `partial`，不能把识别完成写成自动拆题全部成功。模型也可能忽略公式定界符要求，把部分表内公式作为普通文字返回；原始数学语义评分不证明其已是可编辑数学节点。校对、保存和跨模块消费另外验收。

截断 PDF 在真实题库入口明确失败，没有调用 OCR 或生成题目；刷新后仍能下载字节相同的原件。局部遮挡 F 保留分段函数、另一完整题及页注，把受损“求”字读成了“阈”，没有专门标出该错误；条件数字 3 仍有可见残片，不能把返回 3 称为恢复完全缺失的信息。F 不加入正常质量或时间分母。

### 调研覆盖与结论边界

实际比较包括 Paddle、OpenDoc、MinerU Basic/Standard、Logics、GLM、LightOn、Hunyuan、WeVisDoc 和百度 Qianfan，并覆盖原方案消融、提示和分辨率变化。其他路线仅依据官方资料筛选，不能列作本机失败：

- [PP-StructureV3](https://www.paddleocr.ai/latest/en/version3.x/pipeline_usage/PP-StructureV3.html)、[Surya](https://github.com/datalab-to/surya)、[Docling](https://github.com/docling-project/docling) 和 [FireRed-OCR](https://github.com/FireRedTeam/FireRed-OCR) 保留为未实测备选。已有多个专用组合及整页路线的对比和合格候选，不声称这些备选一定更差。
- dots.mocr、DeepSeek-OCR-2、Nanonets-OCR2、Jina-OCR 等关注了权重体积、量化/运行兼容、中文数学和原图定位；资源及结果结构风险使其优先级较低，没有用参数量直接判定 OOM。Qwen3.5/Qwen3-VL、InternVL、MiniCPM、SmolVLM 和 Granite-docling 也核对了通用/专用能力，未把文档问答成绩当逐字转写成绩。
- MinerU Flash 偏预览/索引，Advanced 增加计算；未声称它们与 Standard 的准确率相同。旧同族版本、Marker 包装和不同推理后端不重复算作独立模型实测。PolyOCR-Venus 的公开权重与许可当时未核实。
- Mathpix、百度商业文档解析及其他云 OCR 只调研，不调用、不上传材料。Qianfan 的本地公开模型已经实测，不与商业 API 混称。

[模型卡](https://huggingface.co/opendatalab/MinerU2.5-Pro-2605-1.2B)与[官方管线](https://opendatalab.github.io/MinerU/usage/tiers/)只用于选型和配置依据，本项目的推荐来自上述固定输入实测。12 页是小规模、定向样本，不证明任意老师材料都达到这些百分比，也不能证明市场上不存在更好的配置。
