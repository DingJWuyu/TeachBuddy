# 验证入口

执行者只读本任务相关场景和运行入口。完整范围矩阵位于 [mvp-matrix](mvp-matrix.md)，它是最终交付要求，不是每次 UI 修订都要执行的清单。

## 选择验证

| 变化 | 首选反馈 |
| --- | --- |
| 文档、导航、状态 | 文件/锚点、权威来源、受保护内容和适用范围；不运行产品测试冒充文档验证 |
| 业务 API 或存储 | 相关真实 HTTP/数据库集成用例，必要的迁移与重启 |
| UI/UX | 模块实际浏览器流程、生产构建、图像与动效过程；UI 不写单元测试 |
| 输出、预览、离线 | 真文件生成、下载、打开，必要断网冷启动；不以按钮可点为完成 |
| 公共组合变更 | 受影响跨模块路径和必要回归 |

具体 config / 测试文件由[模块入口](../README.md#功能规格)定位。`npm run test:api` 是 API 集合；`npm run build` 是构建；Playwright 使用任务对应 config。不要把只跑一条配置汇报成整个产品全部测试通过。

## 数据与执行边界

1. 核对当前候选、config、fixture 的目录和端口；真实用户环境见[运行指南](../SETUP.md)。测试不能读写用户运行库。
2. 部分既有脚本仍向 `docs/acceptance/evidence/` 写输出或引用旧绝对路径。执行前查看输出约定，改用支持的环境变量/独占目录；不覆盖旧证据。若当前脚本不可隔离，先说明具体阻碍。
3. 已移除的设置 UI 与旧脚本可能不一致，先核对当前用户要求再选择用例，不为旧断言恢复用户删掉的页面。
4. 配置为真服务还是替身、real-auth 还是 test-principal、真邮件还是 fake-mail，都写入结果。真实用户事件与机制探针分开。

失败保留候选和现场，记录原因与解除条件。成功后仅清理本次临时数据；所依赖工具、固定样本和用户文件保留。

## 证据怎么用

[当前证据索引](../plans/run-inputs.md)只列仍可消费的结论。已提交过程报告按索引中的 Git 路径追溯；`evidence/` 保留样本、机器结果、截图、下载物和相关脚本，不是当前状态或待办集合；不批量读入 worker 上下文。

self 是作者验证，independent 是独立验收，user 是具名真人反馈。PASS 只覆盖报告实际范围。新候选涉及改变时验证影响范围，未变部分引用已有证据；环境已暂缓时单列未知，不把它写成已通过。
