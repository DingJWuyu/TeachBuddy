- 目标：采用 pi 核心 runtime，真实查询题目并可靠写入已有业务服务；刷新页面可找到结果。
- 必读：[共同边界](../capability-checks.md#共同边界和交付)、[pi 样本](samples.md#pi-业务样本)、[环境与费用](environment.md)、[pi 与模型来源](sources.md#c24-pi-与模型)、[EMODEL](../evidence/EMODEL.md)。进入业务切片时再读 B16 的固定回执/运行入口及 [B11 业务接缝](../first-flow.md#模块与接缝)、[OpenAPI](../../contracts/workbench/first-flow.openapi.yaml)。
- 写入：`experiments/C24/`、`docs/arch/evidence/C24.md`、`docs/acceptance/evidence/C24/v1/`；不重造 runtime，不直接写业务库，不接管产品模块。结果交 C25 独立复核。

## 最多两条候选

| 候选 | 路径及要证实的假设 |
| --- | --- |
| A DeepSeek | 本机实际安装的 `@earendil-works/pi-coding-agent@0.85.1` SDK，注册 Command Code `openai-completions` provider，精确 ID `deepseek/deepseek-v4.1-flash`，只注册本实验必需的工具。 |
| B GLM | 同一个 pi runtime/provider 接入，换为 `z-ai/glm-5.3-flash`；A 在正常输出或工具循环有明确失败时验证此候选。两者都失败则回 C20/C25，不切换其他模型或自建循环。 |

实际包名不同于旧称 `@mariozechner/pi-coding-agent`；执行前核对 package.json、LICENSE、SDK/会话/扩展接口，固定实际版本。升级版本需要说明具体兼容问题并重跑受影响场景。B 是已授权候选而非产品中静默 fallback；DeepSeek 失败须保留，是否让 GLM 承担首条产品路线由 C25 裁决，不能据 B 成功声称 DeepSeek 已通过。

## 两个切片

| 场景 | 可观察通过条件 |
| --- | --- |
| PI-01 无业务前置，可立即做 | 读实际 SDK 源码/文档，确认 MIT 许可、工具注册/扩展、持久会话与恢复入口。隔离加载 provider 和会话目录，分别核查两个允许 ID 的短中文正常输出；检查非空内容、finish reason、usage 与必要的 reasoning 字段，不能只看 HTTP。实际计费配置/余额能只读取得则脱敏记录，否则明确未知。 |
| PI-02 无业务工具探针，可立即做 | 由真模型调用一个返回固定样本标识的无副作用工具，读取结果后回答；保存模型请求工具、执行、回填与最终回答轨迹。另用非法 ID 做本地拒绝检查，证明没有请求其他模型。该探针只证明接线，不算业务 PASS。 |
| PI-03 真读写，等待 B16 | 通过真实题目服务查询 P-Q，以返回 ID/版本调用一次幂等复制写入。首写响应丢失后使用原键/原体重试；真实页面刷新/重新进入后只有一份 P-C，内容与服务读回一致。工具适配器携可信 principal，使用同一业务操作和 mutations。 |
| PI-04 失败、冲突与恢复，等待 B16 | 一次工具明确失败时回答不能报成功；会话保存后重启 pi 能接续并核实实际结果。再让模型基于旧版准备写入，用户页面先修改原题后放行旧版写入；收到冲突、不覆盖人工内容，重新读取后说明冲突。另在请求未确认时中断，恢复后读取/幂等重放，不重复写。 |

样本操作和预期数据见索引，具体 prompt/工具 schema 和实验控制方法由执行者确定。业务切片只消费 B16 已验收的服务和测试身份入口；若 real-auth 尚未交付，明确标记 test-principal，不伪装真实登录验收。

## 立即工作、停止与回执

PI-01/02 可先准备并实测，不以 B16 或正式主机缺失阻塞。真业务调用必须等 B16 的版本与运行回执到齐；本设计基线没有这份证据，PI-03/04 当前为待依赖。先行报告可以交已完成切片，但 C24 总体不能 PASS。

每条候选限固定场景的一次主执行及一次有原因的修正复测；每场景限制工具轮数，避免模型自循环消耗额度，具体上限在开跑前写入报告。最终交付准确包/版本/许可、最小运行命令、provider 非秘密配置、脱敏工具轨迹、会话重开和页面证据、幂等/冲突恢复语义、调用次数/usage/计费未知项。
