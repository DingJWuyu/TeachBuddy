# 账户与身份

本页是账户与身份产品分区的行为入口，定义登录、注册、找回、会话恢复、退出及账户删除的身份处理。工作台内的账号展示和设置操作入口见[工作台与设置](workbench.md)，业务内容和设备资料的清理职责见[数据管理](data.md)。协议语义归[认证契约](../contracts/auth.md)，精确交换见其 OpenAPI 和用例；当前能力、设备清理接线的职责偏差、未集成候选与未验条件见[当前状态](../plans/run-state.md)。

## 用户目标

教师可以用保存昵称的账户进入工作台，收取验证码注册或重置密码，在网络和保存失败后继续原流程，并确认退出是否完成。账户行为拥有注册/登录/找回/恢复卡和删除核实状态；工作台拥有账号行、已有首次引导与设置退出按钮。协议的 pending、页面头、Cookie 容器均不出现在产品文案中。

设置中的昵称原位编辑消费身份公开能力，保存后更新账户资料并同步侧栏，邮箱保持只读。昵称修改不重新激活会话；输入校验、未知结果核实和迟到响应隔离见[昵称修改交换](../contracts/auth.md#昵称修改交换-i09)，具体交互归[工作台与设置](workbench.md#设置的有效边界)。

## 状态接线

| 用户所见 | 触发与下一步 |
| --- | --- |
| 启动 | 首次状态读取期间保持中性入口占位，不先渲染登录或工作台；确认没有恢复目标立即S14。只有确有恢复目标才显示S46恢复卡，随后提交restore。 |
| 登录/注册提交中 S38 | 业务成功pending仍属于交接过程，继续activate；active确认前不挂载工作台。记住我沿提交快照，注册默认true，不加新控件。 |
| 保存失败 S45 | 明确“账户操作已完成，登录状态未保存”；继续当前会话、重试保存、返回登录。前两个只调用会话操作，不重新创建账户/验证密码/消费验证码；已失效则回登录提示过期。 |
| 恢复等待/失败 S46/S47 | 等待卡不闪现其他内容；临时故障提供重试和返回登录。返回时定向放弃恢复目标，任何迟到结果不得改变当前表单。 |
| 未知结果 S44 | 注册或重置可能成功时保留输入，以中性提示说明未确认，提供回登录恢复。无已确认成功前不显示成功横幅、不自动重复业务。 |
| 退出等待/失败 | 设置按钮等待并禁用重复触发；204后回登录。失败保留上下文可重试，未知时停止业务交互并提示“退出结果暂未确认”，重试相同目标；不能伪装退出完成。 |
| 身份失效 | 收到当前身份失效的可信结果，锁住当前账户现场，清已登录视图，回S14说明过期；其他账户通知只触发核验，不直接清页面。 |

页面内提交快照和界面编辑代次分开。编辑字段/换邮箱/切用途/切卡后，旧响应仍可能有业务副作用，但不能清新输入、安装旧挑战或跳入工作台。S45离开后须解绑旧pending及事件监听，覆盖 CA120。请求取消只停止等待，不作为业务回滚证明。

## 保持既定呈现

- 字段错误落字段下；非字段问题用可关闭顶部横幅。只有凭据拒绝清密码，其他可恢复失败保留输入。
- 找回第一步成功发码后才进入第二步，邮箱只读；更换邮箱返回第一步清挑战并重新发码。不使用保留状态S42。
- 发码结果只说明已发送请求被接受；未收件时保留有效期、冷却、重发及换邮箱路径。长地址省略且全文可访问。
- 昵称完整值交工作台，账号行省略、无障碍名完整，头像保留完整Unicode字符；邮箱不作昵称替代。
- PC 1440×900、平板768×1024、手机390×844均检查错误、等待、S44-S47及设置退出的可见状态、焦点、键盘、触摸和溢出。UI只做浏览器交互验证，不写单元测试。

产品设置调用真实退出，账户与工作台入口已组合。当前接线与验证缺口见[项目状态](../plans/run-state.md)。真人邮件须在目标环境实际收发核验，不能从 API 替身结果推断三端、跨设备和目标网络全部通过。

## 实现与验证入口

Web `apps/web/src/features/auth/`，API `apps/api/src/features/auth/`；邮件 `apps/api/src/core/mail.js`；组合 `apps/api/src/app.js`。接线细节见[技术接线](#技术接线)，恢复撤销见[数据管理](data.md)。

隔离真实组合入口 `apps/web/e2e/auth-integration.config.mjs`、`apps/api/test/auth-integration.test.js`。测试收件器不能证明真实邮件送达；发信故障分别核查应用、SMTP 和网络分流，不能以修复为由更改整机代理或向未授权地址发信。

设置提供独立邮箱确认后的永久删除；提交后锁定业务，失败或未知保持原请求核实，服务端确认后清理本设备并进入默认中文匿名页。详见[账户删除交换](../contracts/auth.md#账户删除交换-i08)。登录后的产品语言读取账户偏好，身份失效后不沿用上一账户语言。

## 技术接线

认证拥有账户、挑战、会话和来源防护，工作台只取得可信 principal。具体工厂、transport 和导出类型以 `apps/api/src/features/auth/index.js`、`apps/web/src/features/auth/index.jsx` 为准；组合入口在 `apps/api/src/app.js`。

- 认证路由先于通用 JSON/CORS 中间件挂载；邮件提供者由组合入口注入，网络投递留在 SQLite 事务之外。
- 身份交接先失效旧请求代次，再读取工作台 context；可信 accountKey 一致后才挂载账户数据。认证存储故障映射为工作台暂不可用，不能当作匿名或退回旧身份。
- 业务请求经认证 transport 附加页面绑定及来源保护，保留原 body 和幂等键；每次请求重新验证身份，不自动重试业务写入。
- 旧库迁移保留稳定账户与资料；昵称不能从邮箱臆造。旧密码可验证时兼容并升级，无法验证时给出找回路径；迁移须用隔离旧库验证。
- 备份还原使用[认证恢复契约](../contracts/auth.md#部署恢复的认证撤销)，外层按[数据恢复顺序](data.md#部署备份与还原)调用，不自行清认证表。
