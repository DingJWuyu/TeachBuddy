# 个人数据、备份与恢复

个人资料包是可阅读、可带走的资料；模块内的误删恢复保留原对象；部署备份用于停服后恢复整个实例。三者目的和格式不同，个人 ZIP 不能直接覆盖账户。

手动导出、误删恢复、维护还原及旧身份撤销已有本地独立切片。设置不提供最近删除聚合、设备草稿、恢复隔离或备份说明 UI，见[设置边界](settings.md)；下文的底层保护继续有效。主题、背景和头像的账户持久化由[账户外观](settings.md#账户外观与共享呈现)定义，语言与周起点不在偏好接口内。

## 实现入口与格式

- API：`apps/api/src/workbench/reliability/`，偏好 `apps/api/src/reliability/preferences.js`；Web `apps/web/src/features/reliability/`。
- 当前手动制品格式：`apps/api/src/workbench/reliability/archive.schema.json`；schema 装配 `schema.js`。完整未来可靠性设计源为 `31575c5c9d386c03a1f9fcde38b9a216f87a5b08:docs/contracts/reliability.schema.json`，Agent 部分的接续仅在[Agent 规格](agent.md)。
- 维护命令：`node apps/api/src/scripts/reliability.js --help`，提供 backup / restore / activate；实际运行参数以 CLI 为准。维护前固定停服、独占目录和原数据保全范围。
- 认证离线操作：`apps/api/src/features/auth/recovery.js` 的 `prepareRestoredAuth`，外层不得自行拼认证表清理 SQL。

下文定义恢复必须遵守的行为，其中 Agent v2 恢复衔接仍属待实现要求；当前 UI 未提供的恢复入口也不能当作已交付功能。实现、验证及授权统一见[项目状态](../plans/run-state.md)，不凭契约存在推定能力可用。

## 恢复层次与冲突

| 层 | 保存位置与承诺 | 刷新/重登/第二设备 |
| --- | --- | --- |
| 已保存内容 | 同一 SQLite + File 原字节，包括原稿/校对草稿、输出、数学版本、引用、对话/工具记录 | 经真实身份读回相同对象；不依赖原浏览器 |
| Agent 已保存输入 | C25 每对话服务器 Draft，版本冲突原样保留 | 同账户跨设备可读；新输入未上传时只是设备草稿 |
| 编辑草稿、未确认请求 | 本设备账户分区；每个编辑分支独立保存完整输入、基线、原请求及内容/schema 版本 | 同设备刷新、退出后同账户可恢复；不承诺跨设备或清除浏览器后恢复 |
| 设备现场 | 账户分区中按模块/标签页分支保存 | 同设备恢复，第二设备使用自己的现场/默认布局 |
| 账户偏好 | 服务端版本化值；日程时区与已有导航布局仍归各自原拥有者 | 第二设备登录/回前台重新读取；不覆盖正在编辑的偏好草稿 |

不新增云端全模块草稿库。文件尚未上传的字节不写 localStorage；只保留名称/选择提示，重开需重选。上传成功的不可变 File ID 留在草稿，账户归属由服务端重新检查。

上传结果未知时，保留原 key、文件名、长度、SHA-256 与恢复点；原 bytes 尚在内存可按原键确认，刷新后须重选同名且摘要匹配的文件才能确认。不能换字节配原键，也不能默认为未上传而新建一份。设备 pendingRequest 只可重放绑定表/原模块允许的规范操作，恢复前验证源版本、方法、路径参数、body 和账户代次；草稿字符串不能指定认证或任意 URL。

设备草稿同步写入沿现有 storage seam。每次文档加载分配独立 editorBranchId，并复制用户选定的上一现场，后续只写自己的分支；刷新时旧分支成为可恢复候选。双标签页不共写一个 draft key，不通过 storage event 自动覆盖。草稿无自动 TTL；成功保存仅清除本次已确认且无新输入的那份，舍弃/清理须明确操作。旧 v1 数据首次读取无损迁入新 envelope，保留原键至迁移读回完成；损坏/未来版本原文保留并显示不可自动恢复，不当作不存在清空。

新 HTTP 偏好用完整 PUT + baseVersion。读取未设置账户返回稳定默认版 1，首次写入与并发初始化原子；时区仍是 schedule-settings，不复制到新偏好。导航分组/隐藏属于现有账户布局；面板宽度/开合属于设备，不扩大原布局契约。保存偏好 409 对照后新键，不能最后写入获胜。

无新输入时，前台恢复/对象重新打开读最新内容；有草稿时读取只形成对照候选。保存中的新输入不被迟到 2xx 清空。身份隔离沿 A11 代次，退出只锁分区，清理只触及当前账户且只在确认存储删除成功后报告完成。清理草稿/现场保留仍未确认的请求记录及其必要输入，界面列出保留数量；先核实后才能删除这些记录。

### 逐模块设备现场

设备层设计字段在 `31575c5c9d386c03a1f9fcde38b9a216f87a5b08:docs/contracts/reliability.schema.json` 的 Scene 中定义；当前实现和 UI 范围须分开核对。内容草稿用原请求 schema，尚不合法的输入以原始表单字符串保存，不尝试作为有效业务请求发送。

| 页面 | 必须保留的现场与返回上下文 |
| --- | --- |
| 题库/收录 | q、题型/标签/标记过滤、列表与当前题、批量选择顺序、原稿 file/page/缩放/区域、校对 draft、原题对照侧、各区域锚点 |
| 备课 | 课题/环节/引用、目录展开、本课材料、取材类型/选择顺序、返回目标与 baseVersion、文稿/取材两套锚点 |
| 数学 | 当前 work/version、工具展开、预览参数/当前步/视窗、源码编辑草稿、制作返回目标；预览参数不自动保存为作品 Source |
| 资源 | q/文件夹/标签、列表或缩略图、选择、预览 file/page/缩放、备注草稿、列表/预览锚点 |
| 班级 | class/record、日期过滤、展开项、来源选择和返回目标、记录草稿及列表/编辑锚点 |
| 日程 | from/to、选中 entry/originDate/拖选时间、月份/未排期/优先视图、表单草稿、网格横纵锚点 |
| 全局/Agent | 当前业务路由、辅助栏关闭/工具/AI、分栏比例、侧栏开合、活动对话与消息锚点、未发送文本/引用、取材前现场 |

恢复按稳定 ID 优先，像素偏移只作同区域补偿；布局改变时夹到当前可见范围。普通查阅不切走 AI，明确进入编辑可切工具并保存 AI 输入。

### 从较旧部署备份恢复后的设备

F62 每次恢复生成新的非秘密 `recoveryId`，记录在恢复库和 `GET /api/reliability/v1/context`。初始数据库也有该标识。它只识别恢复点，不授权身份、不替代认证撤销。设备草稿、请求和 Agent 运行记录记住创建时的 recoveryId。

同账户登录后若 recoveryId 改变，冻结旧未确认请求的执行资格，显示“工作台已从备份恢复，请核对这份草稿”。旧请求下载/查看可用，不自动重放、不把数字相同的 version 当同一基线。老师读取恢复后内容，对照后才以新键提交草稿。新恢复点中 Agent 写操作 executing 转 unconfirmed，但只能核对该备份内成功账本：有匹配回执则确认，无则保持未确认并告知需基于当前内容另发明确请求；不能把恢复前操作再次执行。普通进程重启不改变 recoveryId，仍沿 C25 原键核实。这是恢复语义的新增保护，不改原业务接口。

恢复点核实遇无匹配成功账本返回 409 `recovery-review-required`，保留旧操作而不执行。老师阅读该操作后可显式放弃这个待确认意图，状态变 cancelled，保留原请求/理由，不删事实；随后才能以新回合基于当前内容重新请求。普通 unconfirmed 仍必须先原键核实，不能利用此动作绕过活跃请求。

该动作仅在 `abandon-after-recovery` 入口接受当前 recoveryId，要求无运行中 turn、目标是恢复隔离的 unconfirmed 且恢复库无成功账本；否则 409 `recovery-review-required`，不改变状态。来源/身份/幂等顺序沿共同约定；取消、关联工具卡/事件与原生结果同事务保存，重复成功原键返回原结果。它只取消旧执行意图，不声称恢复前没有发生过写入。

v2 Operation 的 recoveryDisposition 在普通流程为 null，恢复隔离为 review-required，显式放弃后为 abandoned。工具卡从关联 Operation 取得这一状态来显示操作；不能仅凭某次 HTTP 409 猜出可以放弃。旧历史通过 v2 读取时补当前可证明的投影，不改旧原生记录。

<a id="portable"></a>
## 个人资料包

`POST /api/reliability/v1/exports` 受理本账户一次逻辑导出并返回 202 Export；GET 只查询，下载仅成功后可用。创建时以 SQLite 一致读事务固定 snapshot；之后复制不可变文件，生成 ZIP，全部文件长度与 SHA-256 核对后标 ready。并发编辑不进入该快照，缺文件/磁盘不足/进程中断标失败或 interrupted，保留原业务；同键重放原记录，新键重试建立新快照。导出制品与临时目录不进入下一次个人导出或部署业务文件清单。

原键重放仍返回原受理结果，当前状态由 GET 获取。下载未 ready 返回 409 archive-not-ready，不存在/外账户为原 404；下载过程中 I/O 失败中止响应，浏览器不得标完整下载。终态 completedAt 非空，failed/interrupted 提供 Problem；列表按 createdAt 降序、id 升序。运行时导出记录与 manifest 的 schema 由 [archive.schema.json](../../apps/api/src/workbench/reliability/archive.schema.json)维护。

ZIP 根含 `manifest.json`、`index.html`（纯静态、无脚本）、`data/` JSON、`readable/` Markdown/转义 HTML、`files/` 原字节。manifest 的 path/长度/摘要、对象 kind/id/version/状态和关系清单按 schema。完整包含：

- 活动及软删除的题目、题型/标签、原稿和定位、收录校对草稿/未分配片段、来源与复制链。
- 备课当前稿及历史列表中现存的最多 50 个版本，含正文/环节/全部引用快照/本课备注与材料、混排位置、历史独有附件、历史输出及选项；资源元数据/分类/每个被保留的文件版本及预览。
- 数学所有已保留 revision 的 Source、rendererVersion、海报/展示/导出文件；外部 HTML 保持字节，阅读索引只链接下载，不自动运行。
- 班级、实际记录与首次标题/当前对象链接；日程模板/例外/原始日期/通知原时间和已读/清空状态；账户偏好与已有导航布局。
- 对话、历史引用、公开消息/工具卡/操作结果、服务器已保存输入；原 pi entries、内部指令、请求头、密钥、会话和验证码均不进入个人包。公开对象中的真实教师文本仍原样保留，不用字符串删词破坏用户资料。

可读层按对象给出名称、正文/LaTeX、关联目标相对路径、删除标记、快照与当前版区别；机器 JSON 保留唯一源，不声称 Markdown 可无损表达全部版式。附件齐全，可脱离服务打开索引并找到源码与关联。个人包不携认证内部数据，也不包含尚未上传的设备草稿；草稿可在本设备另行下载。

题目改编来源、备课已采用材料的来源彻底删除后，资料包仍保存其快照和附件；仅为包内仍存在的来源生成关联链接。完整备份同样允许独立快照的来源已删除，但拒绝现存跨账户来源、缺失或跨账户附件。备课历史表及其中的正文、材料快照、文件与账户归属也纳入完整备份校验。

每个 dataPath 保存 `{kind, value}` JSON。数学 revision、备课 `lesson-revision`、输出、Job 和 File 元数据独立列出；同对象历史键的 version 区分版本，日程使用 `ScheduleExport` 保存 Entry 和完整 Exception 数组。内部 armedAt/执行去重账本只进入部署备份，个人包能解释已保存日程与历史通知，不声称可重建内部执行账本。历史文件只按已保存的原稿/版本/快照关系标明归属，不为未记录的替换历史编造关联。

备课历史按 `(lessonId, version)` 去重，保留公开课稿投影并附 `savedAt`，不打包数据库内部账户字段。当前课稿与同版本历史对象可并存，kind 不同；历史索引显示标题/版本/时间，并链接当前课稿和附件。历史正文按环节和材料位置阅读；开头文稿、题干和答案中的文字、公式源与图片保持原块及嵌套顺序，公式保留可复制 LaTeX，完整版式以 JSON 为准。来源可用性是导出时状态，不冒充当时状态。归档课稿的历史纳入，超过保留上限或彻底删除的课稿历史不重建；导出不新增历史版本，已经下载的 ZIP 独立保留。验收见 `apps/api/test/reliability-material-snapshots.test.js` 和 `apps/web/e2e/lessons-portable.config.mjs`。

**导入策略确定为内容取回，不提供 ZIP 批量覆盖账户。** 同账户或另一账户都可手工将包内原文件经资源/收录入口重新上传、HTML 经数学入口导入、正文/公式复制到编辑器；新账户生成新 ID 和新归属，不沿包内 accountKey/ID 授权或恢复旧关联。UI 说明此限制。直接上传个人包到恢复命令必须因 kind 不符拒绝，部署备份也不能作为个人导入。整体原 ID/关系还原只由部署级恢复承担，满足“资料可带走”而不额外建设账户迁移平台。

<a id="deletion"></a>
## 误删恢复

各模块通过自身的 deleted 列表及 deletion 操作提供误删恢复，版本、幂等和归属规则沿原模块契约。设置无跨模块最近删除入口，也无 `GET /api/reliability/v1/deleted` 聚合接口；不设通用墓碑表。个人资料包仍包含软删除对象，不能把删除聚合入口解释为永久删除资料。

| 对象 | 删除及恢复后关系 |
| --- | --- |
| 题目/资源/作品 | 原 ID、来源、文件、历史版本保留；备课已采用快照仍可用，恢复不自动采用当前版 |
| 备课 | 原环节/引用/快照/导出保持；不删除源材料，恢复后使用位置重新可见 |
| 班级/记录 | 删班不删记录，记录只读；恢复班只解除班级停用，独立删除记录仍留回收列表，须分别恢复 |
| 日程 | 整组恢复原 ID 与例外；到点通知按原规则保留，停用期间不补发；单次取消/恢复沿 exceptions，不混成另一 Entry |
| 收录 | 原稿及草稿/入库映射保持；已入库题不级联删除，重新整理不重复入库 |

上表描述可恢复的删除。题目、资源、作品、备课、班级及课堂记录另有须确认的永久删除，条件与影响由对应[模块规格](../README.md#功能规格)定义；永久删除后不再提供恢复，已采用快照、受管文件和已下载副本按各自保留规则处理。文件物理回收与自动 TTL 尚未提供，不能与业务条目永久删除混称。分类词/文件夹沿原 taxonomy 语义，不承诺从回收站恢复。来源永久删除后按缺失来源处理；读取失败不能伪装成合法 tombstone。

<a id="backup"></a>
## 账户永久删除

设置经[认证删除交换](../contracts/auth.md#账户删除交换-i08)删除当前教师账户。范围包含六模块的活动/已删除资料、历史与关系、原稿/附件/导出文件、识别结果、账户偏好和导航、幂等回执、Agent 对话及内部恢复记录、认证凭据及挑战。清理显式跟随账户归属，包括通过父记录归属的版本和事件表，不删除另一账户数据。

先锁定该账户并撤销所有登录，再取消并等待其 Agent、Job、个人导出、转换和 OCR 的真实执行结束，清理该账户受管工作目录与字节，最后删除数据库记录。同步前已授权的迟到写入重新检查账户状态；结果未知和物理清理失败保持锁定，由原请求继续，不能显示成功。OCR 实例归属和清理保证由[识别契约](../contracts/recognition.md)定义。

浏览器在服务端确认后清理本设备该账户的缓存与待上传文件。已经下载的副本、外部资料和维护者持有的部署备份独立存在，不由删除接口搜索或销毁。来源不明的历史临时目录不猜测归属。维护恢复是时间点恢复，采用删除之前的备份可能重新带回该账户及资料，须按恢复流程明确选择备份时间点。

## 部署备份与还原

唯一运行策略是**维护停服后一致备份**，用现有单进程/单 SQLite 与文件目录。维护者停止 API 及其转换/Agent 子任务，关闭 DB 连接后执行备份命令；备份工具必须独占数据目录，与正常 API 启动互斥。运行中无法取得独占权即失败，不边跑业务边复制 DB。正常停服不自动重发模型；未决写入、Job 和 Agent journal 原样保留。

删除意图尚未完成时禁止创建部署备份，也禁止恢复包含未完成意图的副本；先在原实例使用原请求完成删除。已完成最小回执允许账户标识为空，不视为业务孤儿；其他带账户归属的数据仍必须对应真实账户。

备份覆盖整库（业务、认证全部内部状态和 migration ledger）、所有登记/保留的 File 字节、Agent 内部恢复数据、可靠性状态。将 SQLite 完整一致副本写入 staging，再按文件元数据核对原字节和摘要；完成后写 manifest、同步并原子发布备份目录。只保存主库而遗漏未 checkpoint 的 WAL 不合格。manifest 不含秘密，也不保存可复用的“认证已清理”许可；配置按[运行配置](../SETUP.md)另行受控保管，清理只写恢复副本，不改备份源。个人包仍排除全部认证内部材料。

恢复命令只接受受控本地部署备份目录和不存在的目标数据目录。精确认证 Interface、清理事务、返回计数及四类错误唯一归[认证恢复契约](../contracts/auth.md#部署恢复的认证撤销)，当前验证入口见[核查入口](../plans/run-state.md#核查入口)。恢复顺序如下，每一步完成才进入下一步：

1. 关闭外部入口，停止旧 API、转换/Agent/邮件等后台写者，抑制自动重启并排空或终止在途请求。保存原库、文件及原配置，确认原库/备份/目标物理分离且无链接别名；数据目录锁不代替停服证明。
2. 校验 manifest 的 kind/路径/版本/摘要和完整迁移集合，在新目标写 pending 后复制一致 DB 与文件；要求目标 DB 已存在，不能错路径建空库。原库和备份源保持不变。
3. 执行 SQLite integrity/foreign-key 检查、受支持的追加迁移，再核对完整账本/必需结构、accountKey、六模块对象、历史文件/源码/对话及跨模块引用。认证支持集合与 legacy gaps 停止条件沿认证契约；更高 format/schema、未知模块/迁移、缺失升级链或必需内容版本均停止。支持的旧版本必须由固定候选及升级 fixture 枚举。
4. 离线同步调用 `prepareRestoredAuth({db})`，验证 `contractRevision=auth-recovery/2`、`outcome=cleared` 及五项 remaining 为零。关闭连接，以同一物理目标重新打开再调用，五项 removed/remaining 均须为零；非零立即停止调查持久性或额外写者，不能以第二次清理成功掩盖首次问题。保留账户/引用核对合格后关闭认证恢复连接。
5. 在目标更新新的 recoveryId，并按本契约 B 及原 Job/通知规则裁决运行状态；复核完整性并关闭全部恢复连接。持久记录本次备份/目标/候选、操作 revision、两次脱敏结果及核对证据，只标 prepared，命令退出 0 表示离线准备完成，不表示已经开放。
6. 维护者按维护 CLI activate选择该目标库、files 与必需配置，核对准备回执与物理目标，执行正常初始化后才开放；不得重新复制未清理库、复用旧连接或以旧日志代替准备回执。启用完成前进程/主机重启默认保持维护停服。成功启用后的普通重启维持原恢复点和新会话，不重跑清理。

认证操作失败、锁竞争、结果未知、复制/迁移/切换/初始化失败均停止候选开放。已知回滚只承诺该认证事务的前态；I/O 或提交回执丢失不推断已回滚。未知结果须重新独占检查未开放副本，再按认证契约重做或从原备份新建目标；不无限重试、不用 recoveryId 代替认证成功。数据库、文件、配置和入口不是一个全局事务，原库保全依赖物理隔离。

原路径未切换可正常启动原部署；路径已切换则先停候选，恢复原 DB/files/配置集合，再启动原部署。保留失败副本供诊断，不覆盖写回原库。一旦恢复库接受新写入，再切回旧库属于新的时间点恢复，须先保存新资料并由维护者明确选择；无自动跨库合并或跨账户重映射。

这是时间点恢复：备份后账户创建、密码修改及业务写入不自动合并；启动前报告备份时间点和凭据回滚影响，教师用备份内密码重新登录原 accountKey。旧 Cookie、page/remembered/pending、备份后撤销或新签发凭据及旧挑战的拒绝语义沿认证契约，重新发码按既有流程。AUTH_CODE_SECRET 无须为清理而读取或轮换，密钥不变时旧 Cookie 仍须失效。旧页面在确认失效后锁定、同页重新准备登录及迟到响应隔离由原认证前端保证；recoveryId 继续只保护设备/Agent 的旧意图重放。



## 外部 AI 衔接

从当前账户可见对象/草稿在客户端生成提问文本，老师预览后复制，使用白名单普通 HTTPS 外链并加 `noopener,noreferrer`；不把正文塞进 query、不内嵌或自动登录第三方网页、不共享 API 会话。成果由老师粘贴/上传，仍走原业务校验。外部 AI 默认目标的旧偏好设计不扩大当前设置 UI。
