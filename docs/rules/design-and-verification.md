# UI/UX 设计与验证

只在界面、交互或视觉验收任务中读取。根 AGENTS 的规则继续有效；当前页面授权与暂停状态读[台账](../plans/run-state.md)，实际领域入口见[文档地图](../README.md#功能规格)。

## 参考与不可丢失的边界

- 顶栏、侧栏、首页和登录注册有已确认原型。功能模块任务保留这些 UI/UX，只替换任务范围内的模块；不把重画整个外壳当成模块接入。
- 外壳和支持页参考真实登录态 EMStudio，使用只读观察与真实数值。功能模块沿已采用的 Impeccable 方向重组，以清晰、紧凑和实际工作为依据。
- 用户指定参考模块时，实际体验其首屏、展开、编辑与返回路径。提取任务分组、信息层级和操作出现时机；日程的独立浮层、字号层次与按需展开可作为模块重组的参考，具体控件随任务调整。
- 参考站的订阅、Pro、额度、套餐、学生统计、商业协议等不会自动进入 TeachBuddy。未授权的能力不为“复刻完整”而开发。
- 已确认范围内的细节自主完成，不要求用户逐按钮拍板；新范围与权限缺口才交用户。issue/ticket 等外部动作须有明确指令。
- 原型数据不进入生产作为固定回复或虚假文件；所有已实现手动功能、后端接线和用户数据随 UI 变化保留。

## 尺寸、留白与信息

先测最近的参考同类控件，再选尺寸。以下是既有 EMStudio 同类件实测锚点，不是要求所有页面套同一尺寸：

| 项 | 值 |
| --- | --- |
| 导航行 / 菜单项 | `36px`（导航）、`30px`（菜单） |
| 行内边距 | `10px`（导航行）、`6px 12px`（菜单项） |
| 正文字号 | `14px / 20px`，字重 `500`（导航）/ `400`（菜单） |
| 最小标签字号 | `10px / 15px`，大写，`0.5px` 字间距，70% 不透明 |
| 面板内边距 | `4px`（支持菜单） |
| 面板宽度 | `167px`（支持菜单）、`156px`（自建菜单） |
| 圆角 | `6px`（账户行）、`8px`（导航行）、`10px`（浮层）、`12px`（卡片/面板） |
| 卡片阴影 | `0 4px 12px 0 #0000000d, 0 2px 4px -1px #00000008`，不用大 blur |
| 细线 | `1px #e3e3e3`；面板细线用 **inset 阴影**绘制以免占用布局 |

- 紧凑轻盈，避免默认大行高、厚边框、重阴影、整屏空框和层层套卡片。空态为工作服务，不靠大框填满页面。
- 相关元素间距等大；调整时保留已确认锚点，用实际边界计算差值，不整体挪动不相关控件。
- 模块标识用图标与清晰标题，当前作品名次之，正文易读，辅助信息退后。紧凑通过分组、间距和按需展示获得，保留标题与正文的字号差异；主操作通过位置和适度强调突出。
- 图标与文字按理解成本分工：箭头、关闭、更多可用纯图标，并提供可访问名称和悬停提示；“上传资料”“加入备课”“下载图片”等需要理解结果的操作保留文字。
- 按任务拆分职责明确的独立浮层，以轻边框、圆角和浅阴影区分，浮层之间露出页面背景。桌面并列的主面板与辅助栏上下对齐、外框等高，各自内部滚动；内容较少时也保持框架稳定。操作放在其作用对象附近，避免跨区工具栏、重复标题和多余说明。
- 删除不帮助完成任务的按钮或说明时，同时重新平衡留白。UI 不显示开发实现细节、任务编号、验收状态或原型免责文案。
- 不采用对角翻页 clip-path；拖拽不允许列表抽动或插入线乱跳，侧栏不用全宽大表单。

## 用途与渐进披露

- 首屏让用户知道“这里能做什么、第一步做什么、操作后得到什么”。空态用一句用途说明和一个明确主操作引导；按钮使用“动词 + 对象”，如“上传资料”“加入备课”。
- 模块有多种成果类型时，入口配简短用途与成果示意，帮助用户选择。进入后可提供能立即操作的示例，示例中的内容仍可修改、增添和删除；用户无需先理解源码或配置才能体验基本效果。
- 按浏览、查看、整理的任务顺序暴露操作。先展示内容和当前步骤需要的工具，筛选、属性编辑等在用户主动使用时展开；单页内容只显示页数，多页才出现翻页控件。
- 编辑工具先显示当前对象的必要字段，样式、范围及进一步设置按需展开。常见结构可用有名称的输入项表达，例如分子、分母；支持源码编辑的功能提供明确切换入口，切换保留已有内容，替换内容前说明影响。
- 可选信息按用途逐项添加，避免一个“展开更多”同时放出整套表单。已有内容直接显示；用户清空正在编辑的字段时保留该字段和焦点，由明确的关闭操作收起空项。关联资料等独立任务保留独立入口，说明选中后是否还需保存。
- 摘要名称必须与实际数据一致：记录摘录不能称为教学进度，空值不能靠推断补成事实。来自不同记录的摘要分别标明日期，帮助用户判断信息是否仍适用。
- 让操作范围可见：浏览区的文件夹和标签用于查找，当前资料的信息栏用于修改归属。标题、位置与选中反馈应帮助用户区分，避免相同控件同时承担筛选和编辑而没有说明。
- 画布、对象列表和属性栏共享当前选择：点击图形或标注后高亮对应对象，右栏显示它的属性，反向选择也能在画布定位。细线和小点提供足够的命中范围及键盘入口，点击选择与拖动操作分别处理。
- 试演、编辑和课堂展示有明确边界。用户应能判断滑杆或拖动是在临时试演还是修改作品；将试演结果写入作品时使用明确操作，退出展示回到原编辑现场。
- 在需要分类或选择对象的位置提供就地创建入口，完成后继续当前任务，保留输入。明确新建对象是否已经保存、当前资料的关联是否仍需保存。
- 常用操作保持可见，低频维护操作收进更多菜单；遇到预览失败等具体问题时，就近展示可执行的补救操作。删除前说明影响，删除后给出清晰的恢复入口。
- 区分各步骤的完成状态。例如上传成功表示原文件已保存，预览生成和资料信息修改各自反馈结果；错误说明已经保留什么以及下一步能做什么。加载中、无内容、无匹配结果和失败使用不同提示，避免用户误判数据丢失。

## 动效与键盘

弹窗、菜单、气泡、抽屉、面板展开与收起都必须在视觉上连续变化。打开和关闭都保留过渡；退出完成再卸载，快速反向时从当前位置继续，不闪烁或先跳终态。

- 优先复用当前动效组件与令牌；既有浮层可从约 `0.96` 缩放、`4px` 位移过渡，约 `180ms`，时长根据组件角色统一。
- transform-origin 对齐触发位置；居中元素的位移与动画 transform 一起处理，不能因覆盖 transform 横跳。
- 焦点、Escape、外部点击及嵌套弹窗按层处理；关闭恢复原触发控件，单次 Escape 不把所有层一并关闭。
- 同一任务区只保留一个活动编辑目标，用“保存记录”“保存修改”等文案区分新建与编辑。收起的编辑器保留草稿，但不接收焦点或保存快捷键；弹窗打开时，底层编辑器也不能响应保存快捷键。
- 对话框先记录触发控件，再聚焦首个可编辑字段；统一处理初始焦点，避免字段的 `autoFocus` 抢先执行，导致关闭时无法恢复焦点。
- `prefers-reduced-motion: reduce` 使用可访问的终态，遵循用户的减弱动效偏好。
- 动画不能吞掉保存、关闭或返回操作，也不能靠固定 sleep 让测试“看似通过”。

## 布局与现场

- 外壳稳定；列表、正文、预览、时间网格和对话分别滚动。滚动完整工作区，不给每个小卡片加滚动条。
- 桌面辅助栏占实际布局空间，工具与 AI 共用同一列；普通浏览不抢走现有工具/对话现场，明确选择对象或编辑操作时再打开对应工具。作品浏览与当前对象编辑各有入口，辅助栏围绕当前任务显示内容。设置、帮助、更新日志使用适合内容的独立布局。
- 每个编辑入口都有可见的返回路径，关闭辅助栏与退出编辑是不同操作。未改动的空白稿可直接返回；有内容的草稿返回后可继续，保留输入和设置。丢弃或覆盖未保存内容前确认，取消后保留原现场；返回、继续和刷新后的状态分别验证。
- 跨模块取材、对照、编辑与返回保留对象、选择、搜索、草稿、滚动、面板和布局现场。服务端内容与本地草稿分开验证，保持挂载不代表持久保存。
- 从长列表进入编辑再返回时，保留原记录在视口中的位置。展开与收起会改变内容高度，仅恢复旧的 scrollTop 不足；以记录为锚点，在过渡完成后核对位置并恢复操作焦点。
- 助理开发目前暂停；后续涉及入口时遵守用户指定的稳定图标，不增加侧栏底部多余“AI 助理”，也不因打开不同模块让顶栏忽有忽无。
- 设置和更新日志的具体删减按[当前页面边界](../features/settings.md#设置的有效边界)执行，不从旧截图恢复用户已删除的区域。

## 采集与验证

1. 先复现真实用户路径。使用可见可点击控件、普通键盘/指针操作；DOM click、dispatchEvent 和种子只能作机制探针，不能冒充用户操作通过。
2. 测量实际面板而非透明定位容器；区分普通行与选中行。图标还需检查实际图形在 SVG 内的占比，外框尺寸正确不代表视觉大小正确。终态截图等待字体、数据和展开过渡完成，避免把动画中的裁切误判为最终布局；动效仍按第 4 项另验。必要时用截图像素检查，不凭记忆推断参考值。
3. 自动重试断言等待可观察结果；操作前确认 aria-expanded 等当前状态，避免重复切换。拖拽实际手势与合成事件的中间态探针分开报告。
4. 动效使用页面内 requestAnimationFrame 或连续帧取样，包含进入、退出、快速反向、焦点恢复；只看终态截图不足。
5. 客户端路由按 URL/元素验证；“无页面重载”先证明文档标识存在，再比较前后。跨刷新现场另验存储。
6. CSS 变更逐项查看 diff，并在实际候选上做生产构建，不能用 dev 热更新结果代替构建。验证不会修改在线用户实例，隔离方式见[运行指南](../SETUP.md)。
7. 浏览器连接能力按当前工具实际检查，使用用户真实登录态参考，避免反复建立调试连接打扰用户；不把旧浏览器版本的连接故障当永久规则。
8. 失败先区分产品、输入和脚本，保留证据；不削弱断言换绿，也不为旧测试复活已否定的行为。
9. 从首次进入走完模块的主要任务及保存、重开，核对仅凭界面是否能判断用途、下一步及保存结果；例如资源库从空态收录资料，再查看与按需整理。另走一次进入后不输入直接退出、有内容时返回再继续；涉及对象编辑时验证选择与侧栏联动，以及长列表编辑返回的位置和焦点。验证清空可选字段后能继续输入、新建与编辑切换后快捷键只保存当前内容。正常路径之外，验证无搜索结果、内容无法展示和保存结果未确认时的解释与恢复操作。
10. 深浅色、桌面与窄屏分别检查主操作、工具栏和辅助栏展开后的布局。核对并列面板的上下边界、背景间隙，以及可用高度内主要画面与必要控件是否可达。除页面横向溢出外，还要检查控件是否被父容器裁切、标签是否异常换行；从实际边界与 CSS 优先级定位问题。

结论分别说明视觉、交互和持久数据的证据。与当前任务无关的目标环境暂缓项单列，不用流程数量代替实际使用质量。
