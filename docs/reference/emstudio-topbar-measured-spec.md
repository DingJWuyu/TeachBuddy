# EMStudio 顶部栏实测规格（Issue #22 视觉对齐参考）

本文件记录**实测**的 EMStudio 顶部栏及其五个入口弹层的几何、类型、颜色与状态值，用于 Issue #22 的像素级对齐。侧栏部分见 `docs/reference/emstudio-sidebar-measured-spec.md`。

- 采集时间：2026-09-18
- 采集方式：连接用户已登录的 Chrome（DevTools remote debugging），读取 `getComputedStyle` 与 `getBoundingClientRect`，配合截图像素测量；单个 CDP 长连接一次采完所有状态
- 采集脚本：`tools/ref-capture-topbar.mjs`
- 页面：`https://emstudio.pro/dashboard`（简体中文界面）
- 视口：1440x900、768x900、500x844，`deviceScaleFactor: 1`

设计原则、美学要求与验证陷阱见 `docs/rules/design-and-verification.md`，那些要求同样适用于本文件描述的视觉系统。

## 新增设计令牌

除侧栏规格已记录的令牌外，顶部栏还用到一个此前未记录的令牌：

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--muted-foreground` | `lab(36.2% 0 0)` = `#555555` | 顶部栏图标描边、未选中导航文字、弹层说明文字 |

`lab(36.2% 0 0)` 精确换算为 `#555555`（不是近似值）。红色与琥珀色角标未使用令牌，是写死的 `#fb2c36` 与 `#fe9a00`。

## 参考自身的不自洽（TeachBuddy 需要归一化）

实测发现参考内部存在四处不一致，照抄会把这些不一致一起带进 TeachBuddy：

1. **盾牌按钮与其他三个不同尺寸组件。** 三个入口是 `32x32` 圆角 `6px`、字号继承 `16px/24px`；盾牌是 `36x36` 圆角 `8px`、字号 `14px/20px`。看起来是两个不同组件被放在了同一组里。
2. **弹层圆角混用三档。** 搜索 `8px`、反馈 `12px`、教程 `12px`、Privacy `16px`。找不到规律。
3. **只有教程弹层压暗页面**（20%），反馈与 Privacy 完全不压暗。三者都是锚定弹层，行为应当一致。
4. **盾牌既无提示也无无障碍名**，另外三个都有提示，反馈按钮的无障碍名还退化成了角标文本 `!`。

## 采集方法备注（给后续 agent）

`tools/ref-capture-topbar.mjs` 已把踩过的坑固化进去，重新采集时直接复用，注意以下三点：

- **必须单连接。** 每建立一次 CDP 连接 Chrome 都会弹一次调试授权确认，用户明确要求不要反复打扰。脚本把所有状态串在一次会话里走完。
- **探针命中的是 Radix 的定位容器，不是面板本身。** 该容器 `background: transparent`、`border-radius: 0`、`box-shadow: none`，直接读它会得出「圆角 0、无阴影、透明底」的错误结论。面板样式只能从截图做像素测量补齐。
- **像素测量要从未被遮罩影响的一侧向内扫。** 搜索弹层把页面压暗 50%，教程压暗 20%，反馈与 Privacy 完全不压暗；同一个亮度阈值在四个弹层上不可能同时成立。做法是从面板内部一个确定位置向外扫，而不是从外部向内扫。

### 第二轮评审修正

用户复看后指出五处缺陷，其中三处是因为第一轮漏看了参考自身的细节：

1. **教程弹层的进度条被漏掉了。** 参考的标题下方不是一行文字，而是一条 `6px` 的胶囊轨道、橙色填充，间隔 `13px` 后跟标签。补上后填充比例等于完成比例（实测参考 `208/235 ≈ 88.5%` 对应 `8/9`），并给它加了 `progressbar` 语义。
2. **支持菜单是悬停展开的，且每行前面有图标。** 参考实测每行有 `16px` 图标，标签在图标后 `10px`（行内缩 `12px`，故标签落在 `38px`）；展开方式是鼠标悬停而非点击。原型照此实现：指针进入即展开、离开即收起，点击只负责展开，否则会把自己刚悬停展开的菜单关掉；触摸没有悬停，因此除非指针类型是鼠标，离开事件一律忽略。
3. **首次引导需要聚光遮罩。** 参考没有这个机制，但用户明确要求「全屏变灰，只有那一块是白的」。实现为整屏 `rgba(0,0,0,.5)` 遮罩加被点亮的入口：遮罩是被点亮包裹层的兄弟节点而不是子节点，因为该包裹层在引导期间带有 `z-index`，若把遮罩放进它内部，遮罩会反过来盖住它本该露出的入口。遮罩同时吞掉指针事件，所以引导无法被点穿，点击遮罩本身即关闭。
4. **四个反馈类型各有自己的颜色。** 参考只截到过第一个类型被选中的样子，所以紫色取自参考，另外三个按普通语义色选定；未选中的一律灰色。
5. **全部完成时要有庆祝。** 参考账号停在 `8/9`，这个状态没有参考可采，因此文案与烟花是 TeachBuddy 自己的：橙色进度打满、角标消失、整屏遮罩上浮出一张卡片写「恭喜您完成了所有引导！请尽情享用吧～」，背景是多点循环烟花。

修正过程中又发现一个上游缺陷，已修：

**`<button>` 的 UA 内边距从未被重置。** `global.css` 重置了字体的 `font: inherit`，却没有碰 `padding`，于是浏览器默认的 `1px 6px` 一直生效。任何定宽图标按钮都会在一个 `20px` 的内容盒里居中，而不是整个 `32px` 盒，实测每个顶栏图标因此比它的悬停框偏右 `1px`。修法是 `.tb-prototype :where(button) { padding: 0 }`：`:where()` 让这条规则只有 `.tb-prototype` 的特异性，任何自己声明内边距的规则都能压过它，不受源码顺序影响。

### 已记录的有意偏差

1. **右侧五个入口而非参考的四个。** 参考把反馈与通知合成同一个红角标按钮，并且根本没有通知入口。TeachBuddy 给通知独立的闹铃图标，保留反馈独立成项，向左侧扩展而不是压缩间距与尺寸。红色角标随之从反馈移到通知，语义由「该发反馈了」变成「有未读通知」。
2. **每个入口都有悬浮提示与无障碍名。** 参考的 Privacy 入口两者都没有，反馈按钮的无障碍名还退化成了角标文本 `!`。
3. **参考的图标不是 Lucide。** 实测四个图标的墨宽是 `17 / 18 / 22 / 16`，而 Lucide 在 `20px` 下的理论墨宽是 `16.7 / 15 / 15.7 / 13.3`，说明参考用的是一套自有比例的字形。原型统一采用 Lucide 等价路径，实测墨量接近但不可能逐像素相等。
4. **图标描边由 `1.7` 改为 `2`。** 实测参考的描边渲染出约 `3px` 墨迹而 `1.7` 只有 `2px`，`24` 视图盒在 `20px` 下渲染时 `2` 才等于参考的 `1.67` 设备像素。这条同时影响侧栏图标，是 Issue #16 遗留的保真度缺口。
5. **右侧入口图标按 `22px` 渲染，侧栏仍为 `20px`。** 实测顶栏图标的墨宽（`17/18/22/16`）明显大于侧栏的 `20px` 图标，两者在参考中本就不同尺寸。
6. **Privacy 弹层收窄到内容宽度（约 `289px`）。** 参考是 `352px`，但正文、行动按钮与三张证书图按既定要求全部删除后，保持 `352px` 会留下大片空白。圆角保留参考的 `16px`，标题保留 `w800`。
7. **通知弹层没有参考可依。** 语法取自教程弹层：右锚定、`320px` 宽、`16px 20px` 内边距、`36px` 行距、图标瓦片加标签。行尾多一个时间。空状态为图标加「暂无通知」。
8. **教程弹层的文案改为中文。** 标题「快速上手」，进度「已完成 0 / 9」；参考是英文的 `Getting Started` 与 `8 of 9`。角标语义与参考一致，显示的是剩余数而不是完成数。
9. **教程条目由模块注册表生成，且首次引导是一次性的。** 参考的教程列表写死为它自己的九项。TeachBuddy 从模块注册表生成，因此新增模块会自动出现在列表里；首次进入时有一个气泡指向教程入口，文案「想了解什么功能，就点击对应项来学习吧～」，关闭或完成任一条目后不再出现。参考没有这个机制。
10. **反馈类型标签的选中色用 TeachBuddy 自己的紫 `#7160a7`。** 参考的选中态是它自己的品牌紫 `#842bfe`，属于品牌素材而非通用模式。
11. **搜索面板的内容是原型固定数据。** 分组与条目写死在 `TopbarSurfaces.jsx`；结果行用模块图标替代参考结果行里的 `12px` 灰点，与侧栏的行语法保持一致。
12. **中部导航保持中列居中。** 参考的锚点无法解释（1440px 下整体中心 `x=824`，视口中心是 `720`；试过视口居中、内容区居中、flex 自适应三种模型均不吻合），因此保留已验收外壳的锚定方式，不照抄一个解释不通的位置。
13. **窄屏保留全部五个入口。** 参考在 `500px` 丢弃教程入口；原型保留，因为 `390px` 下五个 `36px` 入口加汉堡按钮仍然放得下且不产生横向溢出，而首次引导正指向教程入口。
14. **搜索输入框抑制共享焦点环。** Chrome 对任何获得焦点的文本输入都匹配 `:focus-visible`，自动聚焦会画出参考没有的焦点环；模态内唯一可聚焦控件的指示由光标承担。
15. **窄屏把三个导航入口全部搬进抽屉。** 参考在手机断点下把顶栏导航整个删掉，只在抽屉里重新露出「首页」一项（作为导航列表的首行、深色胶囊选中态），日历与支持在参考里没有落点。原型沿用「顶部导航降级为抽屉首行」这个模式，但把三项全部搬过去，支持行展开后内联列出与顶栏支持菜单相同的三条，避免两个入口在窄屏彻底不可达。行几何复用侧栏自己的 `36px` 行与 `12px` 内缩，因此与紧随其后的模块行完全对齐。
16. **教程进度条的填充色沿用角标的琥珀色。** 参考的填充实测就是 `#fe9a00`，与它的角标同色，所以这里不是新选的颜色。
17. **庆祝卡片与烟花没有参考。** 参考账号停在 `8/9`，该状态无法采集；卡片沿用弹层语法与琥珀色强调，烟花是纯 CSS 的多点循环，并在 `prefers-reduced-motion: reduce` 下整体关闭。

### 第三轮评审修正

1. **引导入场改为分阶段浮现。** 之前遮罩、被点亮的入口和气泡同时出现，很突兀。现在三段错开：遮罩 `0.24s` 淡入（`0s` 起）、入口从 `scale(.84)` 长回原位并浮出一圈白光（`0.06s` 起）、气泡上浮 `8px` 淡入（`0.3s` 起）。每一段都用 `animation-fill-mode: both`，这样它在延迟期间就停在自己的首帧，不会先以最终样子闪一下再动。`prefers-reduced-motion` 下三段全部关闭，直接落到稳态。
2. **点击顶栏空白处现在也会关闭弹层。** 之前按下处理直接豁免了整个顶栏，于是按住品牌或导航时弹层关不掉。现在改成：只要按下位置既不在当前弹层内、也不在该弹层自己的触发按钮上，就关闭。按另一个入口仍然正常切换，因为关闭发生在 `pointerdown`、切换发生在之后的 `click`。
3. **支持菜单的箭头会翻转。** 悬停或展开时向左旋转 `180deg` 变成向上，离开时转回向下，`0.25s` 缓动。选左旋而不是右旋，是为了让它看起来像箭头翻过去，而不是原地打转。
4. **修掉「悬停后点不到菜单项」的严重缺陷。** 面板挂在触发按钮下方 `8px` 处，指针下移时会经过一段不属于任何元素的空隙，包裹层因此收到 `pointerleave` 并把菜单卸载掉，用户还没碰到「设置」菜单就没了。修法是在面板上加一个覆盖其上方 `8px` 的透明 `::before`：它属于面板，所以指针经过时仍算在包裹层内。挂在面板而不是包裹层上，是为了让它只在菜单打开时存在，关闭时不会在页面上留一条吞点击的透明带。

顺带修掉一个此前没人发现的无障碍缺陷：

**两个 live region 抢同一个播报位。** 之前渲染的是 `model.announcement || surfaceAnnouncement`，而布局模型的消息初始化成「工作台布局已载入」且永远为真，于是所有入口动作（点支持菜单项、点通知、发送反馈、完成教程、打开搜索结果）的播报**从来没有被读出过**。现在只留一个播报槽，由布局模型持有并暴露给各入口共用。
