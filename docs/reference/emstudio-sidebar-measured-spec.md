# EMStudio 侧栏实测规格（Issue #16 视觉对齐参考）

本文件记录**实测**的 EMStudio 侧栏与顶栏几何、类型、颜色和状态值，用于 Issue #16 的像素级对齐。

- 采集时间：2026-09-18
- 采集方式：连接用户已登录的 Chrome（DevTools remote debugging），在真实登录态页面上读取 `getComputedStyle` 与 `getBoundingClientRect`，并截图
- 页面：`https://emstudio.pro/dashboard`（简体中文界面）
- 视口：1440x900、1675x914、1024x768、768x900、500x844，`deviceScaleFactor: 1`
- 截图目录：`docs/reference/shots/`
- 原始度量：`docs/reference/measurements.json`

设计原则、美学要求与验证陷阱见 `docs/rules/design-and-verification.md`，那些要求同样适用于本文件描述的视觉系统。

与 `docs/research/emstudio-ui-ux-baseline.md`（`a3ee7a8`，人工观察，非实测）的差异见文末。

## 与研究基线的差异更正

研究基线（`a3ee7a8`）是人工观察，以下各点经本次实测更正：

1. 顶栏高：基线写"约 65px"，实测 `65px`（含 0.67px 边框），一致。
2. 收起态轨道：基线写"约 72px"，实测 `72px`，一致。
3. 侧栏宽度：基线写"约 256px"，实测 `256px`，一致。
4. 新增实测值：导航行 `36px`、行内边距 `10px`、圆角 `8px`、图标 `20x20`、间距 `12px`、正文字号 `14px/20px` 字重 `500`。
5. 新增实测值：分组标签 `10px/15px` 大写 + `0.5px` 字间距 + 70% 不透明，这是基线完全没有记录的类型层级。
6. 新增实测值：收起态**隐藏分组标签**，基线未记录该项行为。
7. 新增实测值：侧栏**没有右边框**，靠底色与内容区 `#f9f9f9` 的差异区分。
8. 新增实测值：收起/展开**无过渡动画**（`all 0s`）。
9. 新增实测值：收起态图标有 tooltip（`#2d3037` 底、`#f9f9f9` 字、`12px`、`6px` 圆角）。
10. 新增实测值：账户区底色透明、圆角 `6px`、内边距 `4px`，语言入口是独立 `32x32` 按钮而非行内下拉。

### 已记录的有意偏差

1. **收起态轨道行起点 x=18 而非参考的 x≈17。** 参考的 72px 轨道带约 2px 滚动条槽，行因此落在 17..53；原型轨道无需滚动，行居中落在 18..54。两者都是各自内容盒的居中结果，1px 差异属于取整，故保留。
2. **纵向节奏存在约 6px 漂移。** 参考第一个分组标签位于 y=188.79；原型因 DM Sans 字体度量与参考回退字体不同，会低几像素，且随后按行高倍数累加。横向几何（用户最容易感知的轴）已完全对齐，纵向漂移为字体度量所致。
3. **「工作台」标题行不存在于参考。** 参考的分组标签是纯静态标题，没有总标题、没有新建入口、没有折叠箭头。这三者都是 Issue #16 已接受交互模型的一部分，按参考的标签类型层级从零构建：`10px/15px`、`0.5px` 字间距、大写、70% 不透明，与参考分组标签同级。
4. **收起态分组细分隔线不存在于参考。** 参考没有用户自定义分组，收起后就是一列无分隔的图标。原型保留一条 1px `--sidebar-border` 细分隔线（上下各 18px 间距），让用户自定义的分组结构在收起态仍可感知。
5. **收起/展开无动画**，与参考一致（参考为 `transition: all 0s`）。
6. **焦点环为 3px 而非参考的 2px。** 原型同时用焦点环标记拖放落点，需要更强的可见性；颜色改用参考自身的 ring 令牌 `#2e3137` 而非原型的紫色。
7. **顶栏与侧栏解耦。** 参考的顶栏是固定外壳，侧栏收起时顶栏不动。原型起初把顶栏第一列绑在 `--tb-sidebar-width` 上，导致收起时中部导航左移、品牌被挤压。现已引入独立的 `--tb-shell-brand-column` 固定顶栏第一列，收起键也挂在该列上（展开与收起都停在 x=220）。
8. **收起/展开为纯列宽动画。** 参考是零时长切换，TeachBuddy 使用 `0.2s cubic-bezier(.4,0,.2,1)` 的列宽过渡（顶栏第一列固定不动）。曾经尝试过叠加对角 `clip-path` 扫掠，用户判定像"翻页"且难接受，已移除；现在不存在任何遮罩。
9. **创建学期按钮圆角 10px。** 参考为 `6px`，但该按钮较宽，实测在其宽度下 6px 显得过于方正。
10. **垃圾桶面板与垃圾桶行严格同尺寸。** 面板宽高与垃圾桶行一致（`232x36`），自身无内外边距，1px 细线用 inset 阴影绘制而非 border，否则 border-box 会把内容盒压成 230px 而比垃圾桶行窄 2px。面板内每一行铺满全宽，拖入的模块与侧栏中的模块行等高等宽；面板空时同样是一个 `232x36` 的方框，footprint 不随空满变化。
11. **新建分组改为右侧浮层。** 参考没有该入口，故复用参考的浮层语法（184px 宽、10px 圆角、卡片阴影、白底 1px 边框），从触发器右侧展开，不显示 Enter 提示。
12. **设置移入顶栏「支持」菜单。** 参考把账户级入口放在顶栏支持菜单里，侧栏底部没有设置项，原型的侧栏 footer 已删除。支持菜单几何取自参考实测：`167px` 宽、`12px` 圆角、`4px` 内边距、条目 `30px` 高 / `14px` 字号 / `6px 12px` 内边距。参考的「订阅」属于付费能力、「反馈」需要后端，按研究基线排除。
13. **已知未解决问题：插入线在特定指针轨迹下仍会跳动。** 当前实现（绝对定位插入线 + 半行高滞回 + 组末尾线压制重复行线）在 1px 逐行扫掠下是单调稳定的（5 个目标、上下行镜像、任一时刻仅一条线），但用户在实际拖拽中仍观察到跳动。尚不清楚触发条件，疑似与真实指针事件的采样频率和 `dragover` 的目标重定向有关，而非几何计算本身。经用户同意暂不修，记录在此，接受 Issue #16 时可作为遗留项。复现尝试：`node tools/verify-drag.mjs`（合成事件下不复现）。
15. **插入线与拖拽反馈。** 参考没有分组拖拽，故这套反馈独立设计：插入线为绝对定位的 2px 细线，完全不参与布局（流内元素会撑高容器并把相邻行推走，造成抖动）。目标解析使用半行高的滞回，避免指针停在中线时来回翻转；组末尾线的位置与下一组首行的"插入到之前"线重合，此时后者被压制，保证任一时刻只有一条线。分组交界处按指针与两组的距离归属，落点与横线位置由同一函数解析。

### 实现过程中发现的上游缺陷

`apps/web/src/styles/global.css` 用 `button, input, select, textarea, a { font: inherit }` 这类通用选择器重置字体。因为 `font` 是简写，它会静默清掉原型按钮自己的字号声明，而原型此前基准字号恰好是 14px，所以偏差一直不明显。修法是让原型的按钮排版规则全部加 `.tb-prototype` 作用域前缀，在不使用 `!important` 的前提下压过这些重置。这条约束对后续任何接手原型的人是必需的，否则改字号会没有效果。

## 采集方法备注（给后续 agent）

连接用户已登录 Chrome 的正确方式，踩过的坑记录如下：

- Chrome 152 的 `/json/version` 与 `/json/list` 返回 `404`，HTTP 发现接口不可用。
- CDP WebSocket 握手**带 `Origin` 头会被 403 拒绝**，因此 `playwright.connectOverCDP` 不可用。
- 不带 `Origin` 头的裸 `ws://` 握手返回 `101`。浏览器级 ws 路径可从 `~/.config/google-chrome/DevToolsActivePort` 第二行读取。
- 可直接用 `chrome-devtools-axi`（已全局安装）配合 `CHROME_DEVTOOLS_AXI_AUTO_CONNECT=1`，但该模式附着的是一个**独立的 headless 实例，不带用户登录态**；`CHROME_DEVTOOLS_AXI_BROWSER_URL=http://127.0.0.1:9222` 同样受限。
- **每次建立 CDP 连接，Chrome 都会弹一次调试授权确认。** 必须把所有采集合并进单个长连接脚本，避免反复打扰用户。
- 用户登录态在 `Profile 1`（`~/.config/google-chrome/Profile 1`），不在 `Default`。
