# MVP 产品范围

[返回主 README](../README.md) · [路线图](ROADMAP.md) · [工作台页面设计](WORKBENCH_DESIGN.md)

本文是 2026-09-21 用户逐项确认的 MVP 范围基线，记录必须交付的能力、模块关系和边界。推进方向见路线图；页面布局与跨模块取材见工作台页面设计；共同设计约束见[设计规则](rules/design-and-verification.md)。后续行为契约、数据与接口定义以本文为范围依据。

交付目标是具有真实前后端、持久数据和跨模块使用过程的产品。范围内的能力必须能完成实际工作、保存结果、再次找到和复用；内存样例、固定 AI 回答或仅可点击的页面不构成交付完成。

当前正式应用提供账户与工作台底座，业务模块仍主要存在于 `prototype/` 的首轮内存交互稿中，覆盖与限制见[模块原型行为](../prototype/behavior/modules.md)。用户已体验并指出视觉层级、冗余操作、支持页面套用工作区布局等问题，当前稿未通过整体视觉与产品验收。本文描述已确认的交付要求，不代表功能已经实现。

## 产品定位与长期方向

TeachBuddy 是面向中国大陆高中教师个人的教学事务工作台。第一位使用者是一位重点高中高一理科强基班的实习数学教师。产品既要支持他的日常教学，也要让题目、课件、演示和教学经验逐渐形成属于他自己的积累。

通用模块围绕高中教师共同的工作设计；数学特有的需求主要由题库中的数学内容处理和数学工坊承担。强基班是当前使用背景，不据此扩展竞赛训练等独立功能方向。

第一版确定六个功能模块：**题库、备课、数学工坊、资源库、班级教学、日程**。其中前五个从侧栏进入，日程从顶部进入，不在侧栏重复设置。首页是 Agent 完整工作区，Agent 也是贯穿这些模块的超级入口。

长期围绕这六个模块及已确认的跨模块能力持续优化，改善完整性、易用性、可靠性和协作体验。暂不增加新模块或新的功能方向；下文保留的后续候选不进入当前计划。

## 功能模块总览

| 模块 | 核心用途 | 通用性 |
| --- | --- | --- |
| 题库 | 收集、自动整理、查找、自建和改编题目，积累个人标记与备注 | 管理方式通用，数学公式和配图需要专门支持 |
| 备课 | 按课题、专题或课时组织教学思路与材料 | 适用于高中各学科 |
| 数学工坊 | 制作与复用公式、静态数学图形和动态演示 | 数学特色模块 |
| 资源库 | 整理与复用课件、模板、图片、文档等教学资料 | 适用于高中各学科 |
| 班级教学 | 记录实际教学进度与班级共性问题，反馈给后续备课 | 适用于高中各学科 |
| 日程 | 在统一视图中安排课程、时间段和手动待办，并设置提醒 | 适用于高中各学科 |

六个模块、能实际操作这些模块的 Agent，以及下文的基础交付要求，均进入本次 MVP。能力的具体交互或实现方式尚待设计，不构成把该能力推迟到 MVP 之后的理由。

## 1. 题库

让老师把不同来源的好题收集起来，整理为可查找、可编辑、可复用的个人题库。

- 第一版支持图片、PDF、Word 和粘贴文字作为收录入口。纸质教辅和试卷通过拍照或扫描，网页、学科网等来源通过截图、下载文件或复制文字进入。
- 自动提取、拆题和整理是 MVP 必须具备的能力。一份材料中的多道题整理为独立、可编辑的题目，保留公式、配图，以及材料中已有的答案解析。
- 提取后的文字和公式可以编辑；老师能对照原稿修正识别错误。原始材料和出处与整理后的题目关联保存，之后仍可回看；自动处理不完整时，仍能保存材料并由老师补充。
- 题干、选项、小问、配图、答案解析等内容按实际题目需要组织，不把编辑能力锁死在固定题型模板中。
- **题型与标签均由老师自定义**，支持创建、查看、修改和删除；不预设题型，也不预设知识点、解法或难度标签体系。自动整理应尊重老师自己的分类方式。
- 支持个人标记、备注和检索，让收藏的题目方便再次找到。
- 支持从零自建题目，也支持直接修改已有题目。
- 支持保留原题、复制一份进行改编，保留原题与改编题的联系，方便对照；直接修改与复制改编两种方式都要有。
- 支持把题目关联到备课内容及班级教学记录，积累使用场景和教学反馈。

自动识别的准确性、不同材料的拆题方式和校对交互需要用真实题目验证。备课和练习材料的 Word、PDF 输出见下一节，题目直接取用到 PPT 的具体方式由后续行为设计确定。输入任意网站链接后自动登录、抓取题目不作为 MVP 交付要求。

## 2. 备课

围绕一节课或一个专题组织教学设计，让相关材料能一起找到和复用。

- 按课题、专题或课时组织内容，梳理讲解思路、内容顺序和选题。
- 形成三类实际成果：教案与教学提纲、导学案与讲义、练习材料。兼顾老师自己参考、学生使用、指导老师或学校审阅等用途。
- 将题目、PPT、数学图示、动态演示及其他资料关联到对应的备课内容。
- 同一道题或同一份材料可以用于不同课题、课时，避免为了归档而重复保存多份。
- 教学环节由老师自行命名、增删和排序，允许先记录粗略思路。题目、图示、演示与本课讲解备注可以放在实际使用的环节，尚未安排位置的材料可先放入本课材料。
- 从当前教学环节就地选题或取材；需要制作数学作品时，保留目标课题与环节，方便完成后插入并返回。
- 结合课后留下的教学进度和共性问题，调整后续备课。
- 老师可以手动编写，也可以让 Agent 根据已有题目、资料和要求生成初稿、选题和调整教学顺序，再继续修改。内容结构可自定义，适应个人习惯与学校要求。

上述三类成果均支持 Word 和 PDF 输出，这是 MVP 交付要求：

- Word 用于继续编辑，导出后文字、题目中的文字内容及公式仍可修改，方便继续使用已有文档格式；配图按图形材料处理。
- PDF 用于打印和分发，保持排版。
- 输出时可以选择是否包含答案解析和教学备注，分别形成学生用题面与教师用材料，避免混入不应分发的内容。

尊重老师继续手工制作 PPT 的习惯，以及已有的配色、版式和可复用元素。第一版通过组织材料、辅助构思和提供数学素材支持这一流程，不把自动制作整套 PPT 作为交付要求。编辑器、排版方式与文件衔接由后续契约和实现设计确定。

## 3. 数学工坊

帮助老师制作、修改、保存和复用数学表达与可视化作品。

- 公式：输入、修改、保存，提供可编辑的公式内容，也能导出透明背景图片用于 PPT。
- 静态图形：制作函数图像、常见平面与空间几何示意图，调整标注和样式，导出 PNG、SVG。
- 动态演示：根据教学意图制作、修改、保存和展示，支持作品所需的参数调整、拖动或分步展示。
- Agent 参与真实制作和后续修改，例如根据要求绘制函数图像、标注单调区间或制作参数变化演示。
- 作品保留可继续修改的制作内容，既能独立保存和使用，也能关联到具体课题、课时。从备课进入制作时，完成后能带回原来的教学环节。
- 动态演示可以下载，在约定支持的浏览器中离线打开；课堂展示无需登录工作台。支持环境与离线依赖由后续验证确定。
- 接纳外部 AI 生成的 HTML，支持导入、保存和展示；外部文件的后续编辑能力按实际情况处理。

三类作品的真实制作、修改、导出和课堂使用均在 MVP 内。以作品为中心的页面框架继续有效，具体制作与编辑流程在考察合适的 skill 和工具后确定。参数配置和演示步骤编辑的布局不预先锁定，不假定所有导入作品都能自动获得统一编辑能力。

教室设备和浏览器条件尚未验证。离线展示需在明确的支持环境中验证，不将 HTML 直接嵌入 PPT、任意导出图形在 Office 中继续编辑或在所有教室设备上运行视为已解决的能力。

## 4. 资源库

整理老师已有和持续积累的教学资料，让成果方便找到、再次使用。

- 上传和保存真实的 PPT 课件、模板、图片、文档及其他可复用教学素材。
- 保存已有的课件配色、版式和可复用元素所对应的资料，支持老师自己的制作习惯。
- 支持自定义分类、标签和备注，搜索、预览、下载和复用资料，并从备课中直接取用。
- 常用 PPT、Word、PDF 和图片必须能实际预览内容，不能只用文件类型封面代替预览。
- 支持接收外部工具和 AI 网页端产出的材料。
- 允许先收录后整理；支持更新已有资源的文件，保留条目名称、分类、标签、备注与关联。老师继续用外部工具编辑 PPT、Word，完成后上传更新。已引用内容如何采用更新由后续契约确定，不预设本地文件自动同步。

题目的专门编辑与管理由题库承担，数学作品的专门制作与交互由数学工坊承担。老师应能从相关课时找到这些内容，无需为了模块归属反复搬运文件。

实体书籍管理不在本版范围内。

## 5. 班级教学

记录实际发生的教学情况，让备课材料带上课堂使用后的经验。

- 创建和管理自己的班级，按班级记录实际讲到哪里、哪些内容尚未讲完。
- 记录学生普遍卡住的题目、概念或讲解环节，以及下次需要补充的内容。
- 将记录关联到对应的备课、题目或数学作品，方便回看；在备课中能查看对应班级的反馈，用于下一次备课。
- 允许只记一句话，之后再补充教学位置和关联；不要求逐项填写完整表单。同一份备课用于不同班级时，各班实际教学记录分别保存。

备课描述准备如何教学，班级教学记录实际进展和反馈。日程中的课程安排不直接等同于已完成授课。

学生个人的成绩变化、错题和薄弱点追踪仅保留为后续候选，当前不做。

## 6. 日程

以一张统一的日程表承载课程安排、自定义时间段和手动待办，让老师记录、安排自己的时间。

### 记录与安排

- 顶部日程进入完整页面，可选择连续日期范围或天数，不限制为自然周。
- 在时间网格中拖动选择具体时间段，旁侧编辑对应安排与待办；可见日期范围与具体时间段是两种不同的选择。
- 可以记录排课时间，也可以自由创建其他时间段和教学事务。
- 待办由老师手动记录，不预设教师任务清单，也不要求先归入某种任务类型。
- 允许先记下尚未安排时间的事项，之后再放进时间段。
- 一个时间段可以容纳多件事项，不要求为每件琐事分配精确时长。
- 同时支持任务的全局优先级，以及同一时间段内的执行顺序；两者可以独立调整。
- 课程可以关联班级、备课内容和教学记录，普通记事不必建立关联。
- 支持按周重复安排课程，并设置结束日期；临时调课可以只调整某一次，其他课程保持原安排。

待办记录本身保留在那里，不引入需要老师持续维护的任务进度、逾期、催办或自动顺延流程。任务状态不应额外占用老师的注意力，也不作为提醒是否触发的依据。

### 自选提醒

- 老师可以自行设置在某个时间段结束前或结束后，间隔多长时间发出提醒。
- 没有设置提醒的记录保持安静；提醒按设定时间触发，不判断事项是否完成。
- 时间段调整时，相对它设置的提醒随之调整。
- 通知文案说明老师设置的安排，不擅自将其中的事项描述为未完成任务。
- 提醒只进入工作台现有的顶部通知栏，不扩展到工作台外的通知渠道。
- 提醒到点时未打开工作台，下次进入时仍可在通知栏看到，并保留原定提醒时间；不连续弹出补发提醒。
- 点击提醒可以回到对应的时间段。

例如，15:00-16:30 的备课时间段，可以选择在结束前 10 分钟于 16:20 提醒，或在结束后 20 分钟于 16:50 提醒。这些是配置示例，不是默认提醒规则。

## 跨模块能力与外壳

### 工作台 Agent

MVP 包含能实际操作六个模块的 Agent，采用 **pi agent 作为核心运行时**，在其基础上接入工作台能力。自建 skill、plugin、connector 等扩展的具体分工和适配方式由后续技术验证确定，不重新自研核心 Agent runtime。

Agent 是工作台的超级入口，能够结合老师的已有内容，串联各模块完成查找、整理、创建、修改和关联等任务。操作结果真实保存，并体现在对应页面；手动操作与 Agent 操作遵守同一套业务规则。仅讨论、输出建议或生成未实际写入工作台的固定样例，不满足这一交付要求。

首页直接承担 Agent 完整工作区，侧栏底部保留固定 AI 入口，在业务工作页面中打开右侧助理。两种形态延续同一对话与工作内容，不单列第七个业务模块。

典型任务包括整理导入的试卷、寻找适合某节课的题目、保留原题进行改编、结合备课材料调整讲解顺序，以及实际制作数学演示。跨模块示例：“找到昨天收录的那道函数题，复制改编，加入明天的备课，再安排半小时准备时间。”

老师也可以直接操作各模块。内置 Agent 通过 API Key 接入，当前意向使用 DeepSeek，由赠送者承担使用费用。工具契约、具体操作控制和费用管理由后续设计确定；pi 的版本、扩展机制和模型适配能力仍需核实，不把技术方向当成已经完成接入。

### 外部 AI 的便利入口

保留使用 DeepSeek、豆包等免费 AI 网页端的习惯，目标是减少重复搬运题目、资料和提问背景，并方便把成果带回工作台。

可以探索整理当前内容为提问、复制并打开目标 AI 页面等衔接方式。是否内嵌网页要按实际可用性判断，不将第三方网页可直接嵌入、自动交互或与 API 会话互通视为既定能力。

### 工作台外壳

侧边栏和顶部栏沿用既有美学基线，功能入口按本轮设计调整。日程提醒使用已有顶部通知栏，不新增独立通知模块。首页作为 Agent 工作区，不另设传统 dashboard。

所有模块与组件遵守保留现场的共同原则。滚动限定在主要内容区域内；桌面端 AI 与主内容并排，主内容适应剩余宽度。题库分类、备课目录与大纲、资源分类、班级选择、日程月份与安排编辑均已确定与 AI 共用右侧辅助栏，具体映射见工作台设计。

独立工作区域之间通过间隙分隔，操作靠近对应内容，减少跨区域的冗余标题、工具栏和解释小字。设置、帮助和更新日志采用适合自身内容的布局，不强行套用业务工作区与辅助栏框架。

## 基础交付要求

- **访问方式：** 通过网址使用，以电脑浏览器的完整体验为主，适配平板浏览和基本操作。数学动态演示可单独下载到教室电脑离线使用；这不表示整个工作台需要离线运行。
- **真实账户与持久数据：** 登录后使用自己的工作台，题目、文件、备课、作品、班级记录、日程和 Agent 对话真实保存。刷新、退出后重新登录不丢失内容，换设备也能访问；教师账户之间保持数据隔离。
- **保留工作现场：** 切换模块、打开 AI、取材再返回时，草稿、选择、筛选和滚动位置得到保留。保存失败有明确反馈，不能显示为已经保存。持久化、草稿恢复与不同设备上的现场恢复策略在行为契约中具体定义。
- **资料可带走和恢复：** 支持整体导出个人资料，并具备备份与误删恢复能力。恢复对象和关联、备份方式与恢复流程由后续契约确定。
- **支持页面可用：** 设置提供实际生效的个人偏好；帮助覆盖真实使用流程；更新日志记录实际发布变化，不用虚构条目填充。页面沿用 EMStudio 参考风格，不照搬其套餐、计费等商业内容。
- **视觉与易用性：** 独立区域间隙、操作归属、精简层级与文案、业务工具与 AI 共用右栏、区域独立滚动，均属于交付要求。运行成功或测试通过不代表视觉与易用性已经达到要求。

## 模块协作

一次教学过程可以依次使用这些能力：收集好题，组织备课内容，制作图示和演示，复用课件与素材，安排课程时间，课后记录进度和共性问题，再调整后续备课。

- 题库积累题目及其个人标记，资源库积累课件与素材，数学工坊积累数学作品。
- 备课将相关内容组织到课题、专题或课时中，同一份内容可以反复使用。
- 日程承载时间安排；班级教学承载实际进展与课堂反馈。
- Agent 可以串联这些能力，老师也可以从具体模块直接完成工作。

这些联系属于产品体验要求，页面设计的讨论结论见 WORKBENCH_DESIGN.md，具体数据模型与模块公共端口后续设计。

## 页面设计与外壳约束

详细布局和工作过程统一记录在 [工作台功能模块设计](WORKBENCH_DESIGN.md)，包括 Agent 首页、顶部日程、右侧辅助栏、独立滚动、所有现场保留，以及各模块取材、编辑、对照和返回的方式。这些设计共识需在真实前后端接通的产品中验证，不代表已完成视觉验收。

现有[外壳](../prototype/behavior/shell.md)、[导航](../prototype/behavior/navigation.md)、[侧栏](../prototype/behavior/sidebar.md)、[顶部栏](../prototype/behavior/topbar.md)行为说明记录既有原型状态。历史业务名称与首页样例不构成功能要求，新模块正文按本版范围设计。

- 如果保留学期入口，它主要提供课程安排和班级教学的时间语境。题库、数学作品和长期资料应跨学期积累，不被整体切换或清空。
- 侧栏垃圾桶用于收纳隐藏的模块入口，隐藏模块不等于删除题目或资料；业务内容的误删恢复需另行定义，不能用导航入口恢复代替。
- 日程提醒点击后标记已读并打开相应时间段，不给提醒文字加完成划线。首轮原型已接通这一行为；关闭工作台后的提醒补记依赖后续持久化与时间机制。

## 范围边界

当前不做学生个人的成绩、错题和薄弱点追踪，不扩展学生或家长端、学校排课、组织管理、出勤管理、独立课程标准管理或实体书籍管理。原型中现有的模块名称仅用于外壳交互展示，不构成本版功能清单。

MVP 不要求自动制作整套 PPT、自动登录任意网站抓题、外部 AI 网页自动化或会话互通、本地 Office 文件自动同步、HTML 直接嵌入 PPT、任意教室设备兼容。常用 Office 文件预览、Word 与 PDF 输出、约定环境中的演示离线使用仍是明确的交付要求。

长期迭代以改善上述能力为主，暂不扩展新的功能方向。

## 后续设计与协作约定

用户已完成 MVP 范围决策，后续范围内的行为细节、交互、数据规则、接口和技术方案由 Agent 自行讨论并落实，不再要求用户逐个按钮或实现细节拍板。用户将另行安排后续 Agent 协作，本次范围确认本身不代表协作或开发已经启动；既有提交、合并和外部操作授权规则继续有效。

采用行为驱动的契约设计：先写清用户场景、动作、可见结果、保存与再次使用、失败处理和跨模块去向，再推导数据与接口约定。前后端遵循同一份契约并行实现，尽早连接真实服务，并以同一组行为场景验收。具体布局和实现可以演进，已确认的交付能力不得自行删减。

以下事项交由后续设计解决，不再作为是否进入 MVP 的待选项：

- 题目、资源、作品与备课之间的引用或副本语义，以及源内容更新、删除和恢复的影响。
- 数学内容结构、编辑器、自动拆题与校对、Word/PDF 输出及 Office 预览的具体方案。
- pi runtime 的接入、扩展组织、模型配置，以及 Agent 与手动操作一致的工具契约。
- 数学制作 skill 与工具、课堂浏览器支持范围、离线资源打包与真实设备验证。
- 重复课程例外、提醒时间、保存失败、草稿和现场恢复、整体导出与备份恢复的具体行为。

后续验收以真实材料和真实持久数据走完整流程，包括收录后用于备课、制作作品后返回、输出文书、课后反馈、提醒返回，以及 Agent 跨模块操作。不能用独立页面能够点击或仅接口单独通过替代产品流程验证。
