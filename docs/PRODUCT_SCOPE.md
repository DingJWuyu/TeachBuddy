# 第一版产品范围

[返回主 README](../README.md) · [路线图](ROADMAP.md)

本文记录已经确认的第一版功能模块、相互关系和范围边界，是产品范围的详细说明。推进方向见路线图；各模块的页面、交互和技术方案在后续设计中细化。

当前原型已经完成账户入口（登录、注册、找回密码）、侧边栏和顶部栏的 UI/UX 设计，业务模块页面仍是占位。本文中的功能属于已确认的建设范围，尚未完成设计与实现。

## 产品定位与长期方向

TeachBuddy 是面向中国大陆高中教师个人的教学事务工作台。第一位使用者是一位重点高中高一理科强基班的实习数学教师。产品既要支持他的日常教学，也要让题目、课件、演示和教学经验逐渐形成属于他自己的积累。

通用模块围绕高中教师共同的工作设计；数学特有的需求主要由题库中的数学内容处理和数学工坊承担。强基班是当前使用背景，不据此扩展竞赛训练等独立功能方向。

第一版确定六个功能模块：**题库、备课、数学工坊、资源库、班级教学、日程**。Agent 是贯穿这些模块的超级入口。

长期围绕这六个模块及已确认的跨模块能力持续优化，改善完整性、易用性、可靠性和协作体验。暂不增加新模块或新的功能方向；下文保留的后续候选不进入当前计划。

## 功能模块总览

| 模块 | 核心用途 | 通用性 |
| --- | --- | --- |
| 题库 | 收集、自动整理、查找、自建和改编题目，积累个人标记与备注 | 管理方式通用，数学公式和配图需要专门支持 |
| 备课 | 按课题、专题或课时组织教学思路与材料 | 适用于高中各学科 |
| 数学工坊 | 制作与复用公式、静态数学图形和动态演示 | 数学特色模块 |
| 资源库 | 整理与复用课件、模板、图片、文档等教学资料 | 适用于高中各学科 |
| 班级教学 | 记录实际教学进度与班级共性问题，反馈给后续备课 | 适用于高中各学科 |
| 日程 | 在统一视图中安排课程、时间段和手动待办，并设置提醒 | 适用于高中各学科 |

## 1. 题库

让老师把不同来源的好题收集起来，整理为可查找、可编辑、可复用的个人题库。

- 接纳纸质教辅和试卷的拍照或扫描、网页截图、学科网等网站的题目、文字、Word、PDF 等来源的材料。来源范围保持开放，各来源的具体导入方式后续细化。
- 以自动提取、拆题和整理为默认目标，将材料中的题目组织为统一、可编辑的内容。原始材料和出处同时保留，方便对照、校正和再次处理；自动处理不完整时，仍能保存材料并由老师补充。
- 题干、选项、小问、配图、答案解析等内容按实际题目需要组织，不把编辑能力锁死在固定题型模板中。
- **题型与标签均由老师自定义**，支持创建、查看、修改和删除；不预设题型，也不预设知识点、解法或难度标签体系。自动整理应尊重老师自己的分类方式。
- 支持个人标记、备注和检索，让收藏的题目方便再次找到。
- 支持从零自建题目，也支持直接修改已有题目。
- 支持保留原题、复制一份进行改编，保留原题与改编题的联系，方便对照；直接修改与复制改编两种方式都要有。
- 支持把题目关联到备课内容及班级教学记录，积累使用场景和教学反馈。

自动识别的准确性、不同材料的拆题方式和校对交互需要用真实题目验证。题目向 PPT、Word 或练习材料复制、导出的具体形式仍待设计。

## 2. 备课

围绕一节课或一个专题组织教学设计，让相关材料能一起找到和复用。

- 按课题、专题或课时组织内容，梳理讲解思路、内容顺序和选题。
- 准备教案、导学案、讲解提纲及相关教学文书，兼顾老师自己参考、学生使用、指导老师或学校审阅等用途。
- 将题目、PPT、数学图示、动态演示及其他资料关联到对应的备课内容。
- 同一道题或同一份材料可以用于不同课题、课时，避免为了归档而重复保存多份。
- 结合课后留下的教学进度和共性问题，调整后续备课。
- 允许 Agent 结合已有材料参与选题、讨论讲法、梳理顺序和准备内容。

尊重老师继续手工制作 PPT 的习惯，以及已有的配色、版式和可复用元素。第一版通过组织材料、辅助构思和提供数学素材支持这一流程，不把自动制作整套 PPT 作为交付要求。教学文书的编辑方式与导出格式后续细化。

## 3. 数学工坊

帮助老师制作、修改、保存和复用数学表达与可视化作品。

- 编辑和制作数学公式。
- 制作静态数学图形，例如函数图像和几何示意图，方便用于 PPT、Word 等材料。
- 制作、修改、保存和展示动态数学演示，接纳老师已经使用的 AI 生成 HTML 的方式。
- 动态演示同时支持准备好的分步讲解，以及拖动图形、调整参数等自由操作。
- 作品既能独立保存，也能关联到具体课题、课时，供后续重复使用。
- 允许通过工作台 Agent 辅助创作，也保留接收外部 AI 制作成果的路径。

公式和图形的导出格式、在 PPT 或 Word 中继续编辑的能力、HTML 演示与课件的衔接方式后续设计。教室设备、浏览器及联网条件尚未验证，不将 HTML 直接嵌入 PPT 或在所有教室设备上运行视为已解决的能力。

## 4. 资源库

整理老师已有和持续积累的教学资料，让成果方便找到、再次使用。

- 管理 PPT 课件、模板、图片、文档和其他可复用教学素材。
- 保存已有的课件配色、版式和可复用元素所对应的资料，支持老师自己的制作习惯。
- 支持查找、整理和复用资料，并关联到备课内容。
- 支持接收外部工具和 AI 网页端产出的材料。

题目的专门编辑与管理由题库承担，数学作品的专门制作与交互由数学工坊承担。老师应能从相关课时找到这些内容，无需为了模块归属反复搬运文件。

实体书籍管理不在本版范围内。

## 5. 班级教学

记录实际发生的教学情况，让备课材料带上课堂使用后的经验。

- 按班级记录实际讲到哪里、哪些内容尚未讲完。
- 记录学生普遍卡住的题目、概念或讲解环节，以及下次需要补充的内容。
- 将记录关联到对应的课题、课时或题目，方便回看并用于下一次备课。

备课描述准备如何教学，班级教学记录实际进展和反馈。日程中的课程安排不直接等同于已完成授课。

学生个人的成绩变化、错题和薄弱点追踪仅保留为后续候选，当前不做。

## 6. 日程

以一张统一的日程表承载课程安排、自定义时间段和手动待办，让老师记录、安排自己的时间。

### 记录与安排

- 可以记录排课时间，也可以自由创建其他时间段和教学事务。
- 待办由老师手动记录，不预设教师任务清单，也不要求先归入某种任务类型。
- 允许先记下尚未安排时间的事项，之后再放进时间段。
- 一个时间段可以容纳多件事项，不要求为每件琐事分配精确时长。
- 同时支持任务的全局优先级，以及同一时间段内的执行顺序；两者可以独立调整。
- 课程可以关联备课内容和教学记录，普通记事不必建立关联。
- 课程重复安排、临时调课和具体视图交互在模块设计中细化。

待办记录本身保留在那里，不引入需要老师持续维护的任务进度、逾期、催办或自动顺延流程。任务状态不应额外占用老师的注意力，也不作为提醒是否触发的依据。

### 自选提醒

- 老师可以自行设置在某个时间段结束前或结束后，间隔多长时间发出提醒。
- 没有设置提醒的记录保持安静；提醒按设定时间触发，不判断事项是否完成。
- 时间段调整时，相对它设置的提醒随之调整。
- 通知文案说明老师设置的安排，不擅自将其中的事项描述为未完成任务。
- 提醒只进入工作台现有的顶部通知栏，不扩展到工作台外的通知渠道。
- 提醒到点时未打开工作台，下次进入时仍可在通知栏看到，并保留原定提醒时间；不连续弹出补发提醒。
- 点击提醒可以回到对应的时间段。

例如，15:00-16:30 的备课时间段，可以选择在结束前 10 分钟于 16:20 提醒，或在结束后 20 分钟于 16:50 提醒。这些是配置示例，不是默认提醒规则。

## 跨模块能力与外壳

### 工作台 Agent

Agent 是工作台的超级入口，可以结合老师的已有内容，串联各模块完成查找、整理、创建、修改和关联等任务。它属于第一版产品方向，不单列为第七个业务模块。

典型任务包括整理导入的试卷、寻找适合某节课的题目、保留原题进行改编、结合备课材料讨论讲解顺序，以及辅助制作数学演示。

老师也可以直接操作各模块。内置 Agent 通过 API Key 接入，当前意向使用 DeepSeek，由赠送者承担使用费用。Agent 的具体构建、操作边界和费用管理另行设计，本文件不确定这些实现细节。

### 外部 AI 的便利入口

保留使用 DeepSeek、豆包等免费 AI 网页端的习惯，目标是减少重复搬运题目、资料和提问背景，并方便把成果带回工作台。

可以探索整理当前内容为提问、复制并打开目标 AI 页面等衔接方式。是否内嵌网页要按实际可用性判断，不将第三方网页可直接嵌入、自动交互或与 API 会话互通视为既定能力。

### 工作台外壳

账户入口、侧边栏、顶部栏、首页等沿用工作台外壳的定位。日程提醒使用已有顶部通知栏，不新增独立通知模块。首页的信息组织基于本文件确定的产品需求继续设计。

## 模块协作

一次教学过程可以依次使用这些能力：收集好题，组织备课内容，制作图示和演示，复用课件与素材，安排课程时间，课后记录进度和共性问题，再调整后续备课。

- 题库积累题目及其个人标记，资源库积累课件与素材，数学工坊积累数学作品。
- 备课将相关内容组织到课题、专题或课时中，同一份内容可以反复使用。
- 日程承载时间安排；班级教学承载实际进展与课堂反馈。
- Agent 可以串联这些能力，老师也可以从具体模块直接完成工作。

这些联系属于产品体验要求，具体数据模型、模块公共端口与页面结构后续设计。

## 页面设计方向（待视觉验证）

以下方向来自对工作台[外壳](../prototype/behavior/shell.md)、[导航](../prototype/behavior/navigation.md)、[侧栏](../prototype/behavior/sidebar.md)、[顶部栏](../prototype/behavior/topbar.md)行为说明及三端截图的观察。它们指导后续页面探索，尚未作为最终页面或交互方案验收，也不增加六个模块之外的功能范围。

原型侧栏中的业务名称和首页 demo 都是用于确定外壳 UI/UX 的样例。首页 demo 将移除；在业务设计中，首页和模块正文均按空页面起点考虑，不沿用其业务信息架构。

### 视觉与空间

沿用现有外壳的白色界面、深色选中态、少量紫色强调、细边框及轻浮层。控件保持紧凑，题目、公式、图形的字号和间距按阅读与编辑需求单独设计。装饰性浅网格可以留在外围，实际编辑区和绘图画布应有清晰的底面。

页面以老师手头正在处理的内容为中心，避免给每个模块都套用统计卡片或相同的后台列表。宽屏按需展开辅助区域；平板和手机避免同时并列全局侧栏、内容列表、编辑区和 Agent，让主要内容保持可读、可操作。

| 模块 | 页面探索方向 |
| --- | --- |
| 题库 | 题目列表与当前题目预览配合，清楚显示公式与配图；编辑或原稿校对时再展开需要的区域 |
| 备课 | 以一节课的教学内容和讲解顺序为主要工作面，就地取用题目、课件与演示 |
| 数学工坊 | 画布占据主要空间，工具和参数靠边放置，展示时可收起编辑控件 |
| 资源库 | 根据资料类型选择缩略图或列表，帮助老师凭课件封面、图片和名称识别自己的内容 |
| 班级教学 | 围绕具体班级回看教学记录，呈现实际进度与需要补充讲解的内容 |
| 日程 | 时间安排占主要空间，尚未安排的事项按需展开，时段内直接显示事项顺序 |

### 连续的工作过程

备课页应允许就地查找、预览和选用题库内容，查看相关演示后方便返回原来的课时与编辑位置。外壳在导航中保持稳定的体验，应延伸到具体工作中，尽量保留草稿、筛选条件和选题位置。

Agent 可以探索可展开的工作区域，结合当前题目、材料或课时提供帮助。切换模块时应保留对话与引用内容，不直接套用当前短暂浮层的互斥及跳页关闭规则。宽屏侧边展开、窄屏单独呈现等方式需要用真实布局验证。

### 全局入口的含义

- 如果保留顶栏的日历入口，它应指向日程模块的同一份内容，避免形成两套时间安排。
- 如果保留学期入口，它主要提供课程安排和班级教学的时间语境。题库、数学作品和长期资料应跨学期积累，不被整体切换或清空。
- 侧栏垃圾桶用于收纳隐藏的模块入口。题目、文件等业务内容的删除应在各自页面中清楚表达，隐藏模块不等于删除资料。

### 通知交互的协调

当前原型点击通知会切换已读，并用删除线表示已读；本版已确定点击日程提醒回到对应时间段。后续需区分打开对应安排与标记已读的操作。

建议探索使用文字颜色或未读标记表达阅读状态，避免删除线让日程提醒被误解为事项已经完成。这是待验证的交互调整，不表示已修改原型中验收过的通知行为。

### 首页的设计顺序

建议先通过一节课验证选题、组织材料、制作图示和记录课后反馈的连续体验，再决定首页应提供哪些日程与继续工作的入口。首页的最终布局保持开放，不以现有 demo 为起点。

## 范围边界与待细化事项

当前不做学生个人的成绩、错题和薄弱点追踪，不扩展学生或家长端、学校排课、组织管理、出勤管理、独立课程标准管理或实体书籍管理。原型中现有的模块名称仅用于外壳交互展示，不构成本版功能清单。

后续工作集中在六个模块和已确认的跨模块能力内部：细化页面与使用流程、验证多来源数学题目的自动整理、确定文书与数学作品的编辑和导出体验、验证实际课堂展示环境，以及设计 Agent 的协作方式。

这些待细化事项不代表已经确定开发顺序、接口、编辑器、识别服务或课堂运行方案。第一版范围保持稳定，长期迭代以改善上述能力为主，暂不扩展新的功能方向。
