# 日程契约：安排、事项与提醒

精确字段和操作见[当前日程机器契约](../../apps/api/src/contracts/schedule-v2.openapi.json)（[v1 兼容契约](../../apps/api/src/contracts/schedule-v1.openapi.yaml)保留旧请求），交换预期见[日程案例](schedule-cases.md)，界面及实现归属见[日程规格](../features/schedule.md)。

旧客户端带有已退役 `course` 字段的请求，仅能按原账户、原幂等键和原请求体重放已经成功的回执；回执不再含教学关联。没有成功回执的新写入仍拒绝该字段，不创建关联或额外任务。当前请求和新客户端均使用下述独立日程契约。

## 共同协议

继承 [B11 身份、HTTP、幂等、冲突与未知结果](workbench.md)：可信 principal、同源 Cookie、来源/保护头、no-store、2 MiB 请求限制、严格请求与宽容响应、账户隔离、原子成功回执、无 TTL 的请求重放、版本冲突对照。无身份 401；不存在/外账户统一 404。所有写入携 Idempotency-Key；成功重放先于当前版本检查。UUID 是标识而非权限。所有日期时间计算使用服务端时钟；业务创建/更新/删除服务器 UTC 时间。

新增对象 version 从 1 开始，每次成功逻辑写入加 1，同体新键也加 1。PUT 为完整替换其可写内容，字段必填但允许空值的以 schema 为准；省略不等于清空。删除/恢复独立操作，不用 HTTP DELETE；被删除对象 GET 可读，普通修改 409 object-deleted。列表默认 active，可显式 deleted；不分页，按各自定义稳定排序。未知 query、重复 query、未知请求字段、隐式类型转换均拒绝。错误完整字段只见 schema。

## 安排、事项与排序

安排 Entry 是一个小聚合：标题、可排序事项、可选时间、可选周重复、一个可选提醒。API 兼容接受非空标题或至少一条事项；已有空标题对象展示首项摘要。界面新建任务及待安排要求非空标题后才创建，未命名草稿取消直接丢弃。事项含稳定 UUID、文字、优先级和可选布尔 completed；缺省或 false 表示未完成，true 表示完成，旧调用无需补字段。完成状态随保存、排序、跨任务移动、实例独立与重新读取保留。priority 为 low/normal/high，仅保留兼容语义，界面不提供优先级；数组顺序是段内顺序。任务自身没有完成/逾期字段，事项完成不改变任务时间、提醒或列表筛选。

安排与通知的 ID 由服务器创建；事项 ID 由客户端在首次输入时创建，修改/重排/移动保持。重复实例展开时保留模板事项 ID，显示身份为 entryId + originDate + itemId；不同周的同名事项不被合并成一件待办。改某次优先级只改该例外，整组修改只影响仍继承模板的实例。

编辑重复实例使用 POST /api/modules/schedule/entries/:id/occurrences/:originDate/detach，正文为完整非重复 Entry 内容和 expectedVersion。服务校验所有者、活动系列、有效未取消原日期、版本、内容后，在共享 mutations 事务中结算旧提醒、取消原日期、推进系列版本并创建 repeat=null 的独立 Entry，返回 201 和新 Entry。失败全部回滚；幂等重放返回同一新 ID。事项 ID、备注与标签保留。未改动的既有过期提醒允许保留，新 Entry 的提醒从当前时间生效，不补发过期提醒。后续日期继续继承原系列，独立任务不随系列删除而删除。已交付旧通知保留原实例历史身份。

time=null 表示未排期，repeat 与 reminder 均必须为 null。将重复安排更新为 time=null 时取消整组排期，同事务清除旧单次例外和实例提醒生效点，保留安排 ID、当前内容。未排期可以含多项，最简新增一项即可。界面不提供全局优先视图，保留的 priority 字段不参与任务列表排序。

移动单个事项使用 moveItem 原子操作，源必须为活动非重复 Entry。普通目标或 toEntryId=null 的新待安排保留既有请求字段；重复目标额外要求 toScope 与 toOriginDate：series + null 将事项插入原系列模板，保留系列 ID、规则及已有例外；instance + 有效未取消 originDate 将该次内容和原事项独立为新的 repeat=null Entry，加入移动事项并取消原日期，推进系列版本。已独立 Entry 不随系列移动更改。toIndex 对应模板或所选日期有效事项数组，移动后不超过 200 项，ID 保持。响应 to 为实际接收 Entry，重复目标请求附 toOriginDate 供打开有效实例，独立目标为 null。源与目标校验、提醒结算、实例独立、源事项移除及幂等结果均在共享 mutations 事务中完成，任一校验失败或版本冲突全部回滚，重放不复制事项或系列。源移空时有标题保留，无标题软删除。目标时间、提醒不改写。

## 账户时区与日期

T52 拥有账户的 schedule-settings，timeZone 为 IANA 名称，首次读取未设置账户返回 Asia/Shanghai、version=1；初始化须幂等。产品通过现有设置更新接口采用系统时区。更新设置在同一事务中将账户所有有时间的安排（含软删除安排和 override 内容）迁移到目标时区，保留当地日期、开始钟点、持续分钟、重复规则及其余内容；实际瞬间按目标时区重新计算。每个实际迁移的 Entry 版本加 1，未排期不变；设置和所有安排已一致时为无操作，不增版本。普通编辑所用的版本保护仍有效。迁移前结算旧时区已到期提醒，迁移后重置受影响任务及系列的提醒启用时刻，重新计算的过去提醒不补发；历史通知保留原 dueAt。其他账户不变。

日期用有效公历 YYYY-MM-DD，支持 1900-01-01 至 2100-12-31；time.startTime 是分钟精度 HH:mm（00:00 至 23:59），durationMinutes 是实际经过的 1 至 1440 分钟。跨午夜显示两个日期；结束瞬间 = 开始瞬间 + durationMinutes，不能用浏览器随意解析本地日期。时间网格可拖选，接口仍以日期/开始时刻/持续分钟表达，编辑结束时间时转换为实际分钟。

周重复依据安排自身 timeZone 的当地星期/时间逐周生成，不在 UTC 上固定加 168 小时。夏令时重叠取较早的瞬间，缺失时刻向前移动该次跳时的间隔，例如 02:30 跳到 03:30；持续分钟保持。界面保留输入的钟点，并显示实际调整后的时刻，不能静默把不存在的 02:30 当成有效瞬间。时区无效 422 invalid-time-zone；非法日期/时间 422 invalid-input。没有 DST 的上海时间走同一规则。

范围查询 from/to 均含首尾日，以账户显示时区的首日 00:00 至末日次日 00:00 构成半开区间。安排按实际区间相交返回（start < rangeEnd 且 end > rangeStart）；恰好在首日 00:00 结束不属于该范围。允许任意连续合法日期，不强加 7/31 天服务端上限，查询排序为 startsAt、entryId、originDate 升序。移到范围内的例外必须被找到，即使原始日期不在范围内。

## 重复和单次例外

本节的周重复与不可变系列限制属于基础请求；携带日历字段的扩展请求按[日历扩展](#日历扩展)处理频率、系列起日和类型变化。实例身份、版本、删除和通知原则共同适用。

每个重复安排每周一次，首日就是 time.date，repeat.until 为含首日的最后原始日期，必须 >= time.date。无重复用 null；暂不引入 RRULE、多星期规则或“此后全部”。基础请求的重复模板首日及重复/非重复种类在首次保存后不变；普通编辑保留模板时区，系统时区同步可统一迁移；非重复安排可自由改日期/时区、排期或移回未排期。整组可改起始时刻、时长、结束日期、标题、事项和提醒。改变重复首日/星期或种类通过新建安排与删除旧安排，UI 明确执行两件事，不伪称改了一次。

实例身份为 `(entryId, originDate)`，originDate 是该系列原始排课日；非重复为 `(entryId, null)`。调课改变实际 time，但身份不变。周例外只有 override 或 cancelled；override 保存完整可编辑内容且 repeat 不可再次定义，按 originDate 覆盖模板，取消这次不生成新的 Entry。读取返回实例实际时间、模板版本、是否例外；指定单个实例可返回取消/删除状态供通知定位。

整组 version 同时保护模板和全部例外，每次单次操作也使它加 1，避免两设备改同系列互相覆盖。整组更新保留已有例外的全部内容，提醒也保留；缩短 until 隐藏原始日期不再符合规则的例外，伸长后恢复原例外。隐藏不表示删除它的数据；例外列表包含 eligible=false 供确认。早于首日或不符合每周节律的原始日期为 404；符合节律但超出当前 until 的单实例读取返回 outside-series（即使没有存过例外），以便旧通知解释缩短后的课程。其写操作返回 422 invalid-input、field=/originDate、reason=out-of-range；需先延长整组再编辑/恢复该次。

“恢复原安排”删除该日例外并重新采用当前模板，不将调课后的日期作为新原始日期。取消例外的 content=null，单实例读取返回当前模板的可辨认内容及 cancelled 状态；override 的 content 非空。隐藏状态优先于取消，整组 deleted 优先于两者。没有例外时再次 inherit 仍算一次版本化写入。取消、隐藏或整组删除的实例不会触发新提醒。源 Entry 删除后所有实例显示 deleted，恢复原 ID 与例外，不回放停用期间提醒。

当前界面删除任务调用 `POST /api/modules/schedule/entries/:id/delete`，请求 `{expectedVersion}`，成功返回 `{id, version}`。服务在同一事务中校验账户与版本、结算已到期提醒，并移除任务、系列例外和提醒生效点；通知及成功幂等回执保留。删除后不可恢复，重复请求按原键原体返回原结果，不重新执行。历史通知指向已永久删除对象时显示找不到任务。旧 `/deletion` 软删除/恢复操作继续兼容，当前界面不提供其入口。

## 日历扩展

当前扩展字段和操作见[日程扩展机器契约](../../apps/api/src/contracts/schedule-v2.openapi.json)，样本见[扩展样本](../../apps/api/test/fixtures/contracts/schedule-v2-samples.json)。

日历请求可携带 `calendar: {allDay, notes, tags}`：`allDay` 为布尔值，纯文本 `notes` 最长 50000 字符，`tags` 为最多 30 个不重复标签 UUID。安排和实例读取总是提供此对象；基础请求省略它时保留原值。全天安排要求 00:00 开始及整天时长，结束按安排时区的当地午夜计算。带 calendar 的单次时长上限为 366 天；基础请求仍为 1440 分钟。

重复规则可在 `until` 外指定 `frequency`（daily/weekly/monthly/yearly）、`interval`（1 至 999）、`weekdays`（0 表示周日，周规则至少一天）、`monthly`（date/weekday）和 `count`（0 表示不按次数截止，最多 10000）。规则按安排当地日期展开；不存在的月日期或闰日跳过，月星期按首日的第几个星期定位。日历更新允许已有任务切换重复类型和调整系列起日；基础请求保留上述不可变系列限制。已有单次例外按原始日期保留，只有仍符合系列规则的实例进入范围查询。

标签接口为 `/api/modules/schedule/labels` 的 GET/POST 与 `/:id` 的 PUT。创建提交 `{name, color}`，名称去空白后 1 至 60 字符，颜色为 `#RRGGBB`；更新额外携带 `expectedVersion` 和 `deleted`。读取仅含本账户活动标签，写入沿用公共身份、版本、幂等与事务规则；删除标签不删除任务。此扩展的运行校验归 `apps/api/src/modules/schedule/schema.js`，真实 HTTP 兼容与重启验证见 `apps/api/test/teaching-time-calendar.test.js`。

## 提醒、修改与重启

每段/每次只设一个 reminder：可选 anchor=start/end（省略为 end，兼容旧配置）、side=before/after 与非负分钟数；0 表示所选起点时刻。dueAt = 对应 startsAt/endsAt ± minutes。修改 anchor 也须重算到期资格。未设置为 null；创建或显式新启用/调整到期时间时，非重复/单次例外必须 dueAt > 服务端 now，否则 422 reminder-not-future。重复模板需至少一个仍符合规则的实例 dueAt > now，过去实例不获得提醒资格。纯文字变更允许保留过去配置。删除、恢复整组或 inherit 操作允许恢复过去配置但保持安静，不为此拒绝恢复。

提醒使用持久 armedAt：首次启用为提交时间；取消后恢复、修改时间/重复范围/提醒、恢复例外/整组会从当前提交时间重新生效。纯标题、事项变化不重置。模板改变只作用于未 override 的实例，独立例外保留自己的生效点。dueAt <= armedAt 的历史实例不补发；隐藏后重新显现的例外也从恢复可见的提交时间生效。删除/禁用不让历史被新计算覆盖。

提醒标题投影固定为同一个 `projectReminderTitle(entry)`：先取 `entry.title` 去首尾空白后的文本；若为空，取 `entry.items[0].text` 去首尾空白后的文本；最后按 Unicode code point 取前 300 个字符，不追加省略号。该投影只用于 `ReminderCandidate.title` 和 `Notification.title`，不改已保存的标题或事项；合法空标题安排一定有首项事项，因此投影结果非空且符合 300 字符上限。

通知唯一键为可信账户 + entryId + originDate（单次用 null 的稳定哨兵），不是 dueAt、标题、版本或轮询时刻；一条实例一生最多生成一条通知。到期入库时保存原定 dueAt、`projectReminderTitle(entry)` 的结果、readAt=null；单条与批量通知动作接受 read、unread、dismiss；read 写入已读时间，unread 将 readAt 清为 null，dismiss 仅写 dismissedAt。切换已读态不改变 dueAt、标题、实例身份或唯一痕迹，清空后的通知不重新生成。

**修改前先结算**：T52 对任何安排/例外/删除/恢复/事项移动的成功变更，在同一 mutations 事务中先调用 T53 注入的 captureDue，以同一个服务端 now 结算旧安排中 `armedAt < dueAt <= now` 的提醒，再写新状态。校验失败则整个事务回滚。即使工作台没打开，已经到点的旧提醒也不会被随后调课抹掉。T52 的独立替身可验证调用顺序；T53 必须接入持久实现才具备完整行为。

| 操作发生时点 | 通知结果 |
| --- | --- |
| 到期前改时间/提醒、取消某次或删除整组 | 旧未来时刻不产生通知；按新生效安排计算，取消/删除保持安静 |
| 到期后（包括关闭期间）改时间、清除提醒或删除 | 先持久保存原到期通知，原 dueAt/标题/已读态保持；不再为同实例生成第二条 |
| 发出后修改标题、改时段、恢复、服务重启 | 原通知不改；点击解析当前目标，显示当前安排或取消/删除状态 |
| 清空通知、重复进入、并发查询 | dismissed 通知不再展示且不再生成；总共仍只有一条唯一记录 |
| 关闭工作台/服务停止期间到期 | 再次查询时扫描当前有效实例至服务端 now，补写缺失通知，显示原 dueAt，不显示补写时间冒充提醒时间 |

T53 仅在站内通知查询/写入及 schedule 变更时结算；浏览器工作台可见时每 30 秒查询，回到前台/登录恢复立即查询；时钟由服务端控制，后台浏览器不承担可靠计时。无需常驻任务、队列、Web Push 或通知中心模块。已到期列表按 dueAt 降序、ID 升序；点击旧通知通过当前 occurrence 解引用，不需要保留整个安排的历史版本。
