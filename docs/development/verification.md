# 验证原则

按改动影响选择最短的真实用户流程。修复缺陷先在当前代码中从 UI 或公开 API 复现，再验证修复后的同一路径。构建、接口测试与浏览器检查分别说明其覆盖范围；自验、独立验收和用户验收不能互相代替。

涉及保存、身份、文件或恢复时，检查重新读取、刷新或重启后的结果，并覆盖账户隔离、失败反馈、冲突与重复请求。涉及 UI 时用普通点击、键盘、拖动、上传和下载走真实服务；同时检查桌面与适用窄屏、空态、长内容、遮挡、独立滚动和减弱动效。DOM 强制点击只适合定位机制，不能证明用户能操作。

范围内的产品场景见 [产品范围](../product/scope.md)与 [Gherkin 场景](../product/)。当前缺口和暂缓环境见 [状态](../plans/status.md)。测试输出统一写 `test-results/evidence/`，该目录被 Git 忽略；需要保留的输入样本在 `apps/*/test/fixtures`、`apps/web/e2e/fixtures` 或 `docs/contracts`。
