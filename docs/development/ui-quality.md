# 界面设计与验证

UI 工作依据 [产品范围](../product/scope.md)、[工作台设计](../product/workbench.md)和当前真实页面。保持已有外壳及已确认的 EMStudio 风格；弹出、关闭和展开、收起都要渐进。按真实用户流程验证，不能从原型或构建结果推定可用性。

## 美学原则

控件保持紧凑、轻量，避免大方按钮、厚重阴影和过大的内边距。没有直接参考时，先量 EMStudio 中最接近的控件，再沿用其尺寸与间距。

实测锚点（EMStudio 登录态页面，1440×900，读 `getComputedStyle` 与 `getBoundingClientRect` 实测）：

| 项 | 值 |
| --- | --- |
| 导航行 / 菜单项 | `36px`（导航）、`30px`（菜单） |
| 行内边距 | `10px`（导航行）、`6px 12px`（菜单项） |
| 正文字号 | `14px / 20px`，字重 `500`（导航）/ `400`（菜单） |
| 最小标签字号 | `10px / 15px`，大写，`0.5px` 字间距，70% 不透明 |
| 面板内边距 | `4px`（支持菜单） |
| 面板宽度 | `167px`（支持菜单）、`156px`（自建菜单） |
| 圆角 | `6px`（账户行）、`8px`（导航行）、`10px`（浮层）、`12px`（卡片/面板） |
| 卡片阴影 | `0 4px 12px 0 #0000000d, 0 2px 4px -1px #00000008`，不用大 blur |
| 细线 | `1px #e3e3e3`；面板细线用 **inset 阴影**绘制以免占用布局 |

**避免的样式**：

- 对角 `clip-path` 翻页动效
- 拖拽时列表抽动、插入线乱跳
- 空面板做成大空框
- 侧栏内的全宽大表单
- 给动作加多余的解释小字
- 按钮做得又大又方

**渐进交互**：

弹窗、菜单、浮层、气泡、抽屉和展开区域在出现与关闭时都应平滑过渡。

做法：

- 透明度加缩放一起动，只做淡入会显得"糊"，只做缩放会显得"跳"。
- 缩放从 `0.96` 到 `1`，位移 `4px` 到 `0`，时长 `180ms`，用已有的 `--tb-ease`。
- `transform-origin` 必须落在触发它的那个控件上：右侧锚定的浮层从右上角长出来，居中的菜单从顶部中心长出来。起点错了，动画方向就和控件位置对不上，比不做动画更别扭。
- 关闭时使用对应的短暂退场，再卸载内容；展开和收起同样保持连续。
- `prefers-reduced-motion: reduce` 下直接取消动画落到终态，不要改成更短的动画。

实现注意：动画的 `transform` 会覆盖元素自身的 `transform`。带 `translateX(-50%)` 居中的元素必须写一条自带的 keyframes，把 `-50%` 带进 `from` 和 `to`，否则动画期间元素会水平跳位。

**界面文案**：

文案只说明用户可执行的动作和真实状态。开发或原型说明留在代码和文档中，不进入产品界面。

删掉这类文案之后必须重新排版，不能留下空档：删一行字会改变面板高度和留白比例，要重新量一次间距，让图标、标题、动作之间的留白均匀。

**间距原则**：

- 相关元素之间的间距要**等大**。
- 调整间距时**钉住锚点**，只移动该动的那一个，不要把整组上移或下移。
- 相等间距用**解方程**得出精确值（例如两侧间距都是 `17.89px`），不要目测。

**独立区域与操作归属**：

- 独立工作区域之间用可见间隙分隔，露出背景，让列表、正文、对照材料各自形成清晰的组件。不要在所有区域外再包一层无用途的大框，也不要把每个小内容块都套成卡片。
- 相关操作放在它所作用的区域。题库的收录、自建属于找题与管理区域，当前题目的编辑属于题目区域；无需为它们额外设置横跨两个工作区域的顶部工具栏。
- 标题、当前对象和常用操作可以就近组合，避免重复标题与层层顶部。空面板的大小应服务于工作布局，不用空框填满页面。
- 文案只保留帮助辨认内容、理解必要字段、判断操作后果和恢复错误的信息。页面用途介绍、复述按钮含义、解释内部实现等小字应删除；删除后重排留白。
- 对每个按钮、标题和说明做消融检查：去掉后仍能顺利完成任务，就应考虑去掉。以老师完成实际任务为判断依据，不能只为了让模块显得功能齐全而增加控件。

**业务右栏与支持页面的边界**：

- 五个业务模块与日程使用共享右侧辅助栏，当前工具与 AI 互相切换，不再叠加第二列。桌面端右栏占据布局空间，主内容适应剩余宽度，两边仍可操作。
- 普通浏览、切题、调整日期范围不抢走 AI。明确进入编辑，例如拖选时间段，可以切换到对应工具，同时保留 AI 对话与草稿。
- 首页是 Agent 完整工作区，与业务页右侧助理延续同一对话和引用内容，不额外设置传统 dashboard。
- 设置、帮助、更新日志采用各自适合的布局，不强行套用业务工作区大框和工具/AI 分栏。设置按内容分组，帮助以目录与正文组织，更新日志按更新内容组织；参考截图中的筛选项等应根据真实内容需要取舍。
- EMStudio 截图提供布局与风格参考，其中的订阅、套餐、学生统计和其他模块不因此进入产品范围。

**区域滚动与保留现场**：

- 外壳稳定，列表、文稿、预览、时间网格和助理对话等主要区域各自滚动；操作一个区域不应带动整页或另一区域。
- 滚动以完整阅读或操作区域为单位，不给每个小卡片增加滚动条。设置正文、帮助正文等可以各自作为一个连续滚动区域。
- 所有模块都保留现场，包括工作对象、日期范围、选择、搜索筛选、草稿、滚动位置、目录展开、面板开合、调整后的布局和 AI 对话。取材、对照、编辑、切模块后返回均应延续原工作。
- 真实内容与 Agent 对话必须持久保存，刷新、重新登录和换设备后仍可访问。保存失败必须如实反馈；页面内组件保持挂载不等于完成数据持久化。

## 参考来源与边界

- **视觉参考是真实登录态的 EMStudio**（`emstudio.pro`），不是推测。取值一律以实测为准：目测和印象会系统性偏大偏重，与实测冲突时信实测值。
- **必须排除**：Pro 试用、升级至 Pro、AI Magic 额度、Storage 用量、订阅套餐等商业化内容。
- **参考没有的状态要外推**：从同一套令牌和交互语法长出来，不能像另一套设计系统。

**采集真实参考的方法**：

量真实登录态页面的数值时，用 DevTools remote debugging 读 `getComputedStyle` 与 `getBoundingClientRect`，不要凭截图目测。已知的坑：

- Chrome 152 的 `/json/version` 与 `/json/list` 返回 `404`，HTTP 发现接口不可用；带 `Origin` 头的 CDP WebSocket 握手被 `403` 拒绝，所以 `playwright.connectOverCDP` 不可用。不带 `Origin` 头的裸 `ws://` 握手返回 `101`，浏览器级 ws 路径从 `~/.config/google-chrome/DevToolsActivePort` 第二行读取。
- `chrome-devtools-axi` 配 `CHROME_DEVTOOLS_AXI_AUTO_CONNECT=1` 附着的是独立的 headless 实例，不带用户登录态，`CHROME_DEVTOOLS_AXI_BROWSER_URL` 同样受限。用户登录态在 `Profile 1`，不在 `Default`。
- **每次建立 CDP 连接，Chrome 都会弹一次调试授权确认。** 把所有采集合并进单个长连接脚本，不要反复打扰用户。
- **探针命中的可能是定位容器，不是面板本身。** Radix 一类的容器是 `background: transparent`、`border-radius: 0`、`box-shadow: none`，直接读它会得出「圆角 0、无阴影、透明底」的错误结论，面板样式要用截图像素测量补齐。
- **像素测量要从面板内部向外扫。** 各弹层的压暗比例不同（`50%`／`20%`／不压暗），同一个亮度阈值不可能同时成立。

## 验证方法

**测试失败时先核对场景、版本和真实用户操作，再定位原因。** 区分脚本与产品缺陷；证据不足时不要削弱断言。

已经踩过的坑，写脚本前先过一遍：

1. **断言等待可观察的结果。** 用 `dispatchEvent` 触发状态更新后同步读 DOM，可能看到上一帧。优先用自动重试断言等待目标状态，不依靠固定时长的 sleep 判定成功。
2. **操作前确认当前状态。** 多次点击同一个开关会来回切换；点击前先读 `classList` / `aria-expanded`，需要时先归位。
3. **按用户路径触发可用控件。** `pointer-events: none` 的元素不可点；侧栏收起键需要先 hover。DOM `.click()` 只能用于机制探查，不能用来绕过可点击性并宣称用户操作通过。
4. **采样动画要在动画期间。** 动画 320ms 时在 120ms 之后采样就只剩终态。用 `requestAnimationFrame` 在页面内采样，不要用外部 sleep。
5. **测"普通行"不要拿"选中行"当样本。** 第一行常带 `is-active`，字重和内边距都不同。
6. **面板可能已经开着。** 读内容前先确认开合状态，否则读到空。
7. **合成事件下不复现的问题，不等于问题不存在。** 真实指针事件的采样频率与 `dragover` 目标重定向可能与合成事件不同。
8. **改了 CSS 必须在同一轮跑生产构建。** dev 模式不经过 lightningcss，会掩盖整类错误。本项目曾因一个悬空选择器（选择器末尾逗号后直接跟注释和 `@keyframes`）让构建失败，而 dev 下完全正常。
9. **不要用批量字符串替换改 CSS。** 本项目的三个回归缺陷都来自一次批量加前缀的替换：`display: grid` 被整行删掉导致布局塌陷、漏改一条同优先级规则导致汉堡线泄漏到桌面端、选择器被截断。改完**必须逐条看 diff**。
10. **构建/验证要跑在当前代码上。** 汇报"构建通过"前确认它覆盖了本轮改动，不要依赖上一条提交的结果。
11. **拖拽不要用 `mouse.down` + `mouse.move` 验证。** 本机 headless 与 headed 都不触发 `dragstart`，整个拖拽序列一个事件都不发，看起来像功能坏了。可用两条路：`page.dragAndDrop()` 走完整手势验证落点行为；中间态（如垃圾桶变红）用 `dispatchEvent(new DragEvent(...))` 逐个事件补齐，因为前者的拖拽一气呵成，读不到中途状态。两者结论要分开陈述，不要用后者冒充"真实拖拽通过"。**合成 `DragEvent` 的坐标键是 `clientX` / `clientY`**：写成 `{x, y}` 再展开，指针会停在 `(0, 0)`，所有落点都被解析成"左上角"，断言看起来在跑其实测的是别的位置。
12. **区分客户端跳转与文档加载。** 品牌、顶栏、侧栏与弹层的普通点击走历史 API，只有正文替换；要等 URL 与目标元素，不要等文档加载。刷新后是否恢复登录由当前[账户行为](../../prototype/behavior/auth.md)的记住我与会话状态决定，不再使用“刷新必回登录”的旧假设。验证“不重载”时，先断言文档标识存在，再比较跳转前后的值，不能让两个 `undefined` 被判为通过。跨刷新保留的布局和引导状态要另外验证存储，不能从客户端跳转推断其持久性。
13. **分段验证脚本的段号要有一处权威清单。** 用 `--only=<n>` 的脚本，`if (wanted(n))` 的门号、注释里的段号和文档里引用的段号三者很容易各自漂移。把段号清单写在脚本头部，未知段号必须报错退出；分段与失败结果不得覆盖完整通过的结果。

**汇报要求**：失败和残留问题要如实说，包括"这条我在构建产物里验证不到"这种局限。用户明确表示过"你这个自己设计的东西"式批评是可以接受的，但隐瞒不行。

## 产品行为与验收

- 已确认范围见 [MVP 产品范围](../product/scope.md)。先写清场景、操作、结果、保存、失败恢复与跨模块去向，再据此形成前后端共同遵守的数据和接口契约。具体交互与实现由 Agent 在该范围内收敛。
- 页面中的入口应能解释其作用对象，并把用户带到下一步。引用来源、从备课取材后返回、作品制作后带回等联系必须通过可发现的交互验证，不能只在文档里描述联系。
- 前后端可以基于契约并行实现；验收必须使用真实服务、文件和持久数据。固定回答、虚构文件封面、临时内存关联不能替代 Agent 操作、文件内容预览和跨模块保存。
- 至少覆盖真实材料收录、备课取材与输出、数学作品制作与离线展示、资源更新、课堂反馈、重复课程与提醒，以及 Agent 实际跨模块操作。刷新或重新登录后的结果、失败后的现场与反馈、误删恢复和备份恢复也需验证。
- 视觉、行为、数据可靠性分别提供证据。构建通过只能证明构建结果；接口通过不能代替教师完整使用流程；原型行为记录不作为正式 MVP 已完成的证据。
