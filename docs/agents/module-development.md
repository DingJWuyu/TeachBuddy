# 开发约定

接手、执行或派发任务时读本页；当前进度、工作树和权限读[项目状态](../plans/run-state.md)。用户本次指令及已生效授权优先，旧任务安排不自动延续。

## 接手与完成

1. **确认目标与现场。** 核对负责范围、指定 worktree、Git 分支/HEAD、暂存区、未提交及未跟踪源码。能说清本轮改什么、哪些成果须保留后再动工。只收到“负责某模块”时先接手说明，不自行选新功能；明确执行目标则在授权内持续完成。
2. **按任务读取。** 从[功能索引](../README.md#功能规格)进入本模块规格，并按根[项目入口](../../AGENTS.md#项目入口)核对本任务的必读条件；变更共享语义再读其契约，涉及 UI 再读[设计与验证规则](../rules/design-and-verification.md)。产品范围由规格和用户要求决定。班级任务不自动包含同页日程，阅读相邻模块也不授予写权。
3. **明确交付条件。** 用用户实际入口、操作和最终成果描述完成条件，固定输入、修改范围及提交/保留 diff 方式；沿已有任务包执行，普通开发无需用户填模板。用户无需阅读代码或管理派工来确认基本可用。缺少影响行动的关键条件才澄清，常规实现选择自主完成。
4. **验证后交付。** 验证受影响的真实使用路径与必要回归，核对已集成和运行版本，更新相关行为与状态。按[回执](#回执)区分完成、失败、未验和剩余事项，最后按[集成后的清理](#集成后的清理)完成现场收尾。

## 实现原则

- 优先复用成熟库与既有能力；文档解析、数学渲染等已有成熟实现的领域，自建须有具体能力缺口。以正确、简单、稳健和可维护为主要取舍，不因开发成本降低质量。
- 面向单用户采用直接、完整的实现，高内聚低耦合；一次性工作先走最短可验证路径，实际阻塞或重复需要出现后才增加机制。
- 已有证据表明当前方案无法满足目标时，由当前执行者在授权范围内重新评估并调整或替换方案，继续实现和验证，不因已有投入而坚持原方案。
- 分阶段交付保留完整目标和剩余范围，每批交付可实际使用的能力；按当前规格保护既有功能，旧测试预期的处理见[验证指南](../acceptance/README.md#选择验证)。未知、低置信和无法支持的输入如实保留，不伪造数据或成果。
- 保持已确认的 UI/UX，操作按任务渐进呈现。主动处理本模块明显视觉、交互、lint 和测试不稳定问题；跨模块及公共文件交总控指定唯一写者。

## 开发与验证

- 修 bug 先按用户真实路径 E2E 复现，留下触发条件和失败证据，再定位与修复。失败区分产品、环境、输入和脚本，同一输入重复失败先取得新证据。
- 按[SETUP](../SETUP.md#新的隔离环境)使用独立端口、库、文件目录和构建产物。实际代码、工具、身份与产物须对应本次候选；尊重用户浏览器及登录现场。
- 按[验证指南](../acceptance/README.md)选 HTTP/数据库、真实浏览器和实际文件输出。涉及保存时刷新/重开读回；涉及 Word/PDF 或离线成果时实际打开。界面检查截图、焦点、裁切、溢出及受影响主题/尺寸，不能只凭响应成功或文件存在。
- UI 不写单元测试，其他单元测试仅在必要时使用；资源库禁止新增任何单元测试，使用真实浏览器与 HTTP/数据库集成。
- 验收判据不由已有测试数量倒推；作者自验、独立验收、真人反馈分别记录。旧候选仅能证明未变化且具名的范围，缺少证据与确认失败分开。

## Git 与运行现场

新一轮模块开发由总控按根[Git 规则](../../AGENTS.md#git-规则)及[项目状态中的有效阶段授权](../plans/run-state.md#工作现场与授权)确定分支起点，创建新的 session、分支和 worktree；同一轮任务内返工复用本轮现场，未分配时先确认归属。未集成的源码、固定输入及有效证据须保留，记录可接续的版本和位置。

公共文件同一阶段只有一个写者。总控负责集成冲突，业务 session 不互相派活或扩大任务。Git 操作按根 AGENTS 和本次授权执行，提交不自动添加 agent co-author；未提交及未跟踪源码均属成果，不能覆盖或把已集成增量重复应用。

preview 直接运行集成源码，获准改动会进入用户体验；模块在隔离实例自测。工具、环境和需要手动重启的变更交总控协调，入口见[运行指南](../SETUP.md)。测试数据的处置范围按项目状态；代码、固定输入、证据与私有配置按用途保护，不能因旧数据可丢弃而降低新保存/历史/导出的正确性。

代码和文档属于同一交付，按[维护文档](../README.md#维护文档)更新权威位置。沟通使用中文、普通短横线；问句默认信息请求，明确执行指令优先；暂停、先回答等要求限定当前动作。

### 集成后的清理

总控在集成验证通过的同一轮交付前完成以下步骤，清理属于完成条件，不延后到下一轮开发：

1. **确认成果已保留。** 核对任务提交已进入集成基线，工作树没有待保留的未提交或未跟踪成果，相关执行者与临时服务已停止使用现场。经 cherry-pick 或 squash 集成时核对补丁、冲突处理及最终内容；不能只凭分支名称或 `git branch --merged` 判断。删除前确认入库文件不依赖待删分支或其独有提交。
2. **移除已完成现场。** 删除本轮已完成任务的临时 worktree 和本地任务分支；只有分支、没有独立 worktree 的任务也须清理分支。保留 main、当前授权的集成分支与持续使用的工作树。临时产物按验证指南清理，固定输入和有效证据按用途保留；远端操作仍按本次授权执行。
3. **核对剩余项。** 用 `git branch --list`、`git worktree list` 和保留工作树的 `git status` 确认实际结果，并在回执中报告。因未集成、验证失败或继续使用而保留的任务现场，在项目状态中注明归属、保留原因、下一动作和清理触发条件，交付时列为未完成收尾项。

## 编排

仅总控在派发、恢复或接收任务时展开本节；模块执行者沿本次任务即可。依赖与权限允许时并行推进，一条工作线等待用户不阻塞其他已授权工作；大规模 subagent 工作流按根 AGENTS 先取得明确批准。

先把目标拆成可在实际入口使用的完整批次，依赖满足即集成并验证，及时暴露跨模块问题；分批不缩减用户已要求的完整范围。收到回执后，总控核对候选和证据，继续安排缺口修复、获准集成与收尾；作者提交或单批通过不是总目标完成。

自主推进至约定结果，只有缺少无法自行取得的关键输入、用户专属操作或授权时才暂停受阻部分，并说明已完成什么、具体缺什么和可继续的工作。已授权的下一步直接执行；讨论、明确暂停及 main/远端等权限边界继续有效。交付前由 agent 准备可用入口和必要示例，完成技术回归，用户主要判断实际效果与偏好。

方案取舍遵循根[编排与协作](../../AGENTS.md#编排与协作)。关键不确定性先做能改变决策的最小验证；比较方案使用同一输入和结果判据。增加处理链或机制时说明它解决的实际失败、增量收益与运行维护负担；移除后结果仍达标则优先更简单的方案。证据足够作出选择后进入实现，不为罗列方案继续扩展调查。

任务只携带目标、固定输入、必读资料、写入/运行边界、完成条件与回执位置。输入用 commit + path，未提交或外部材料按需记录摘要；共同文件标明唯一写者、消费者和兼容条件。具体 session、模型/effort、版本及阶段记录留本次任务目录，不积累到长期规则。

独立核验按完整功能或相关修复批次触发：作者自验通过、候选版本固定后，由独立 session 核验一次。阶段集成后补验跨模块组合与尚缺证据的范围；返工复验修复项及其影响范围，不按每次编辑、提交或测试另开一轮。固定代码 diff 审查使用 code-review 的 Standards/Spec 两轴，先核对固定基线和实际修改范围，`<fixed-point>...HEAD` 不包含未提交成果；普通文档整理做引用、事实和阅读路径自检，不追加重复审查。

同一问题在首次候选与两次有新证据的修复后仍验证失败时，按表中困难接手配置接手一次。每轮保留候选、失败证据与据此作出的修正；失败按三轮完整候选验证计算，原始 bug 复现、开发中的单次命令报错和重复执行同一命令不单独计轮次。环境问题先补运行条件，输入或契约问题交责任方。

额度中断保留原模型、session 和产物，作者自验与独立验收仍分开。等待主动回执或等待通知；正常等待期间推进独立工作，无可推进事项则使用等待机制，不反复读取终端、Git diff 或产物目录催进度。只有明确失败、进程退出或超过任务约定的无进展界限时，才针对该异常检查日志与状态；时间经过和消息已投递不代表结果。

## 回执

一份回执足以接续即可：目标及实际 session/model/effort、输入与产物版本、修改范围、实际验证和证据、剩余事项与下一步。记录运行环境和身份；审查补固定 diff 及结果。明确已实现、已集成、已验证的范围，区分通过、失败、跳过和未验。

成功后清理临时材料；未完成时保留现场和可接续回执。固定样本与用户成果按用途保留。新会话以当前 Git 基线、[项目状态](../plans/run-state.md)和仓库内规格及验证入口接手，不以另一台机器的本地目录作为前置条件。
