# 开发约定

接手、执行或派发任务时读本页；当前进度、工作树和权限读[项目状态](../plans/run-state.md)。用户本次指令及已生效授权优先，旧任务安排不自动延续。

## 接手与完成

1. **确认目标与现场。** 核对负责范围、指定 worktree、Git 分支/HEAD、暂存区、未提交及未跟踪源码。能说清本轮改什么、哪些成果须保留后再动工。只收到“负责某模块”时先接手说明，不自行选新功能；明确执行目标则在授权内持续完成。
2. **按任务读取。** 从[功能索引](../README.md#功能规格)进入本模块规格；变更共享语义再读其契约，涉及 UI 再读[设计与验证规则](../rules/design-and-verification.md)。产品范围由规格和用户要求决定。班级任务不自动包含同页日程，阅读相邻模块也不授予写权。
3. **明确交付条件。** 固定输入、可观察结果、修改范围及提交/保留 diff 方式，沿已有任务包执行；普通开发无需用户填模板。缺少影响行动的关键条件才澄清，常规实现选择自主完成。
4. **验证后交付。** 验证受影响的真实使用路径与必要回归，核对已集成和运行版本，更新相关行为与状态。按[回执](#回执)区分完成、失败、未验和剩余事项，最后清理无用临时产物。

## 实现原则

- 优先复用成熟库与既有能力；文档解析、数学渲染等已有成熟实现的领域，自建须有具体能力缺口。以正确、简单、稳健和可维护为主要取舍，不因开发成本降低质量。
- 面向单用户采用直接、完整的实现，高内聚低耦合；一次性工作先走最短可验证路径，实际阻塞或重复需要出现后才增加机制。
- 分阶段交付保留明确边界；已交付能力须可用，既有功能和断言保持有效。未知、低置信和无法支持的输入如实保留，不伪造数据或成果。
- 保持已确认的 UI/UX，操作按任务渐进呈现。主动处理本模块明显视觉、交互、lint 和测试不稳定问题；跨模块及公共文件交总控指定唯一写者。

## 开发与验证

- 修 bug 先按用户真实路径 E2E 复现，留下触发条件和失败证据，再定位与修复。失败区分产品、环境、输入和脚本，同一输入重复失败先取得新证据。
- 按[SETUP](../SETUP.md#新的隔离环境)使用独立端口、库、文件目录和构建产物。实际代码、工具、身份与产物须对应本次候选；尊重用户浏览器及登录现场。
- 按[验证指南](../acceptance/README.md)选 HTTP/数据库、真实浏览器和实际文件输出。涉及保存时刷新/重开读回；涉及 Word/PDF 或离线成果时实际打开。界面检查截图、焦点、裁切、溢出及受影响主题/尺寸，不能只凭响应成功或文件存在。
- UI 不写单元测试，其他单元测试仅在必要时使用；资源库禁止新增任何单元测试，使用真实浏览器与 HTTP/数据库集成。
- 验收判据不由已有测试数量倒推；作者自验、独立验收、真人反馈分别记录。旧候选仅能证明未变化且具名的范围，缺少证据与确认失败分开。

## Git 与运行现场

新一轮模块开发由总控从当前 preview 集成基线创建新的 session、分支和 worktree；旧 `old - ` session 只供查阅，不继续派活，也不从旧模块分支接续。同一轮任务内返工复用本轮现场，未分配时先确认归属；完成集成与验证后清理临时工作树，必要成果按恢复索引保留。

公共文件同一阶段只有一个写者。总控负责集成冲突，业务 session 不互相派活或扩大任务。Git 操作按根 AGENTS 和本次授权执行，提交不自动添加 agent co-author；未提交及未跟踪源码均属成果，不能覆盖或把已集成增量重复应用。

preview 直接运行集成源码，获准改动会进入用户体验；模块在隔离实例自测。工具、环境和需要手动重启的变更交总控协调，入口见[运行指南](../SETUP.md)。测试数据的处置范围按项目状态；代码、固定输入、证据与私有配置按用途保护，不能因旧数据可丢弃而降低新保存/历史/导出的正确性。

代码和文档属于同一交付，按[维护文档](../README.md#维护文档)更新权威位置。沟通使用中文、普通短横线；问句默认信息请求，明确执行指令优先；暂停、先回答等要求限定当前动作。

## 编排

仅总控在派发、恢复或接收任务时展开本节；模块执行者沿本次任务即可。依赖与权限允许时并行推进，一条工作线等待用户不阻塞其他已授权工作；大规模 subagent 工作流按根 AGENTS 先取得明确批准。

任务只携带目标、固定输入、必读资料、写入/运行边界、完成条件与回执位置。输入用 commit + path，未提交或外部材料按需记录摘要；共同文件标明唯一写者、消费者和兼容条件。具体 session、模型/effort、版本及阶段记录留本次任务目录，不积累到长期规则。

## 回执

一份回执足以接续即可：目标及实际 session/model/effort、输入与产物版本、修改范围、实际验证和证据、剩余事项与下一步。记录运行环境和身份；审查补固定 diff 及结果。明确已实现、已集成、已验证的范围，区分通过、失败、跳过和未验。

成功后清理临时材料；未完成时保留现场。固定样本与用户成果按用途保留，旧现场按[恢复索引](../plans/worktree-archive.md)定位。
