# 编排者：接任与推进

角色是管理任务、依赖、授权和交接。文档写得足以接任，不依赖某个模型的记忆。用户明确交给根亲自执行的工作由根完成，例如当前文档重构。

## 接任

1. 读根 AGENTS 与[当前台账](../plans/run-state.md)。确认工作树、当前授权、暂停项和正在执行的任务。
2. 核对工作树的分支、HEAD 和未提交变更。当前长期开发树是 preview，原库 main 保留；不要把旧任务的绝对路径当可用目录。
3. 只读当前未完成任务的任务包、最近回执及固定产物。记录没有证据的空缺，不通读所有 transcript 或原回执。
4. 得出一个明确动作：继续现有任务、处理已知失败、派一个就绪任务，或等待用户。无新授权时按台账等待。

接任完成的标志：能回答“在哪里工作、允许做什么、哪些仍暂停、谁在执行、下一个动作依赖什么”，且每项均能定位到当前记录。

## 派发

1. 按用户目标选[模块入口](../README.md#模块入口)。恢复 DAG 范围时才读 [DAG](../plans/mvp-dag.md)相关阶段和完成门槛。
2. 指定目标、工作目录、固定输入、写入边界和适度的完成条件。使用[短任务包](../plans/task-package.md)，不教执行者逐步实现，不把猜测写成规格。
3. 按[模型路由](../plans/execution-protocol.md#模型与固定派发)选实际模型，记录任务、session、输入和回执位置。没有成功启动证据就不标 RUNNING。
4. 当前只保留一个开发 worktree：同一分支只安排一个实现/集成写者；只读调查可并行。确需新 worktree 时先取得符合当前约束的授权，不恢复旧批量派发方式。
5. 等待主动回执，不设 check、不轮询。若本次没有其他独立且获准的工作，结束本轮等待。

## 接收与决定

| 收到的情况 | 直接动作 |
| --- | --- |
| PASS | 核对任务身份、固定版本、改动和实际验证等级；只推进满足依赖的部分 |
| 有候选但未集成 | 给唯一集成写者固定提交与验证影响；用户数据不随代码覆盖 |
| FAIL | 按问题归属安排修复或设计裁决；不再审整个已通过范围 |
| 外部条件不足 | 记录所缺输入、谁提供、解除条件；推进其他获准工作 |
| usage limit | 保留现场并报告，不自动降级模型或另开同任务 |
| 明确 model at capacity | 按已有许可接续同会话和模型；不重置业务尝试或产品调用窗口 |
| 退出码 0 但无报告 | 先核对实际产物，不能当 PASS；已有成果可补回执，不从头重做 |
| 重复 / 迟到回执 | 按 task、revision、attempt、session 去重；旧版本不放行新候选 |

普通文档和状态更新做必要自检，不新增例行审查。代码审查与实际用户流程验收不同；执行者已有内部审查后，不再派同内容的 diff review。

## 维护什么

- [run-state](../plans/run-state.md)：当前授权、活动任务、阻塞与下一动作。任务结束后从活动表移除，不累积逐轮日志。
- [run-inputs](../plans/run-inputs.md)：当前仍有效的候选、证据及未完成边界。报告已失效时注明影响，保留原始证据。
- [DAG](../plans/mvp-dag.md)：完整范围依赖与节点汇总。局部通过不把完整节点染绿；暂停有独立状态。

实际进度优先于过程数量。功能重复失败时先复用成熟实现；有明确新证据才重试同一路线。对用户报告可用结果、真实阻碍和下一步，不用回执数量代替产品进展。
