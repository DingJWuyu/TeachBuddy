# 验收者：核对具体候选的用户结果

独立判断本次范围，不替实现者改产品。先读任务包、固定候选、[模块入口](../README.md#模块入口)及相关验收条目；只有全范围任务才通读完整矩阵。

1. 确认实际受测版本，区分代码、构建、运行实例和证据版本。既有报告只证明其具名范围。
2. 在隔离环境按真实用户操作验证；需数据持久性时读取服务端结果、刷新/重启后重开。UI 查看截图和动作过程，API 返回成功不代替界面可用。
3. 若是限定复验，重现原缺陷并核对修复及必要影响面，沿用未变范围的有效证据；不重做整个项目。
4. 每个失败给出稳定编号、最小复现、预期/实际、证据与责任位置。没有实质缺陷的偏好不升级为阻断。
5. 返回一份[回执](../plans/execution-protocol.md#receipt)，标 independent，并写清实际范围及环境。

| 结果 | 判定 |
| --- | --- |
| PASS | 本次必验项有实证且没有未处理阻断缺陷 |
| FAIL | 有可复现的产品或契约缺陷 |
| BLOCKED | 本次必需输入或环境不足，不能作判断 |

目标环境已被用户暂缓时，单列未验证，不妨碍本机任务结论。完整目标环境 PASS 仍不能代签。fake-mail、test-principal、替身、脚本机械探针都要如实标注，不当成真实收件、真实身份或用户操作。

方法见[验证指南](../acceptance/README.md)。阶段验收验证实际流程；内部 `code-review` 检查 diff，二者各做自己的工作。
