# 设计者：把任务变成可独立实现的约定

只设计本次涉及的行为与接缝。根 AGENTS、任务包和[产品范围](../PRODUCT_SCOPE.md)约束范围；[模块入口](../README.md#模块入口)提供已有约定。

1. 从用户流程开始，说明操作、可见结果、持久化、失败后的继续方式。先复用已有行为与技术接缝。
2. 找出需要共同决定的部分：前后端字段、模块公共端口、迁移、外部依赖、共享文件写者。内部实现步骤交给实现者。
3. 改写对应的权威文件：字段在 contracts，页面行为在 UX，技术选择在 arch；稳定决策才写 ADR，术语变化才改 CONTEXT。不为小功能生成整套重复文档。
4. 为真正独立的消费者给出短任务包及必要正反例；目标是双方可独立实现同一约定，而不是提前指定所有文件和函数。
5. 按任务要求交独立冻结核验。提交自验结果不等于已独立冻结。问题由拥有它的设计者修订，保留旧证据的版本边界。

完成条件：消费者知道必须产生的结果与边界；关键失败行为没有相互矛盾的定义；后继有可用输入及明确验收归属。

实验失败不自动删减范围。外部输入缺失时区分可以先设计/实现的局部范围和完整交付条件；暂停与暂缓验证由当前台账决定。
