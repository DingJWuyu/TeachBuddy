## 工作现场与授权

用户体验直接运行 `TeacherWorkspace-preview` 源码，入口与维护方式见[SETUP](../SETUP.md#已有本机实例)。原 `TeacherWorkspace` 的 main 不在本轮开发范围；当前分支、HEAD 及未提交文件用 Git 核对。

总控负责各专属 session 的收发消息、公共文件唯一写者、集成与冲突。题库、备课、资源、数学、班级分别保留同级 `TeacherWorkspace-{questions,lessons,resources,math,classes}`；旧现场见[恢复索引](worktree-archive.md)。作者树保留的旧 diff 已有集成成果，但整树未必已同步为 preview 的干净基线；不能直接再次应用或 reset，接续先核对源码和冻结增量。AI/Agent 开发暂停，其 worktree 与原 main 保持。

当前集成基线已完成文档校准、代码清理、必要架构改进及日程、导航和材料修复的独立验收。用户授权总控自主安排专属 session、工作树及技术决策；当前并行推进 OCR 破损文字疑点处理、设置语言切换与删除账户，数据处理协议继续占位。日程和原五个作者现场待命。当前任务包、实际 session、精确基线与回执在 preview `.scratch/ocr-settings/`，上轮集成证据在 `.scratch/product-next/`。

## 开发基线

当前代码可继续开发：共享静态目录驱动 Web 的页面、导航及辅助栏；六模块通过同步只读端口提供资料包业务值；文件模块统一拥有固定预览来源读取。代码入口及职责见[SETUP](../SETUP.md#代码结构)，用户体验沿 preview 源码更新。

当前组合的 shared/API/Web 构建通过，完整 API 为 391 通过、0 失败、2 项因固定旧库缺省跳过。本轮根独立验证日程原交互及新增19项、导航和归档8项；最终组合另验导航/日程/备课归档9项，以及材料4条上传、校对入库或服务器保存刷新路径。本轮产品变更的 Standards、Spec 两轴审查均无遗留发现；这些局部通过不替代下表的产品缺项和目标环境验收。

本轮详细范围、固定代码、命令和未验边界见 preview `.scratch/product-next/integration-receipt.md`；清理及架构依据见 `.scratch/codebase-cleanup/receipt.md`。识别回放不代表重新调用模型，真实推理和消费结果在对应回执分别记录。旧业务树接续前仍须先核对与 preview 的差异，不能直接重复合入。

### 可选增强与明确暂缓

以下属于能力边界或待选增强，不自动进入核心待办：任意裸 TeX 纠错、教学环节自动划分、所有极端版式无损转换、精确单元格框选、OCR 生成 PDF 文字层、跨页/语义搜索、通用几何约束求解、复杂三维和多参数动画。现有原页/区域定位若不足以完成实际校对，或常用材料必须大量重录，则按具体失败纳入核心缺陷。

受管文件物理回收继续暂缓；业务条目永久删除与磁盘回收不同。已由用户移除的设置入口、自动整套 PPT 及其他范围外能力不因旧文档或测试重新恢复，范围以[PRODUCT_SCOPE](../PRODUCT_SCOPE.md)为准。

## 接续顺序与完成条件

日程、导航账户同步及本轮材料修复已集成，材料两轴审查无遗留，原 PDF 严格判据与图边反例保留。具体版本及最终组合验收见本轮任务目录。共用 OCR 已通过的真实样本和消费结果按影响范围复用，不因扩大验证范围就预设原方案失败，也不把已知 F 缺口归给人工验收。

1. 先处理表中可复现的核心问题或明确选择的缺项；当前资料足够时 agent 自行验证，不把技术回归全部交给用户。
2. 本轮资源原件→题库→含数学作品的备课→班级记录已有真实认证保存、重读和五模块浏览器结果；复用这些切片补完整工作日的缺项。目标设备单列，不阻塞有条件的本机工作。认证恢复专项可独立验证，不等待整站交付。
3. 全模块 Agent 保持暂停；恢复后再补其业务与数据/现场组合。手动模块的正常开发不等待 Agent。
4. 完整工作日汇合材料、数学、教学、身份和数据的具名结果，按矩阵独立验收；选定实际部署环境并取得对应动作许可后，验证同一交付版本，再由用户验收。

每个事项只有满足其具名结果才改变状态；保留问题归属、证据及下一动作。缺材料/环境标待验证，用户选择标待决定，代码已合入但未验证不写验收完成。
