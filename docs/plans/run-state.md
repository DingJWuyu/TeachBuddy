## 工作现场与授权

用户体验直接运行 `TeacherWorkspace-preview` 源码，入口与维护方式见[SETUP](../SETUP.md#已有本机实例)。原 `TeacherWorkspace` 的 main 不在本轮开发范围；当前分支、HEAD 及未提交文件用 Git 核对。

总控负责五个模块 session 的收发消息、公共文件唯一写者、集成与冲突。题库、备课、资源、数学、班级分别使用同级 `TeacherWorkspace-{questions,lessons,resources,math,classes}`；旧现场见[恢复索引](worktree-archive.md)。作者树保留的旧 diff 已有集成成果，但整树未必已同步为 preview 的干净基线；不能直接再次应用或 reset，接续先核对源码和冻结增量。AI/Agent 开发暂停，其 worktree 与原 main 保持。

当前完成文档校准与精简，业务 session 待命；下一步执行下节代码库整理专项，再继续产品开发。合 main、push、公开部署、费用和模型窗口按对应授权执行；旧实验额度不延续。测试业务数据可丢弃，不以旧库、草稿保留或历史迁移作为开发前置；代码、未提交成果、固定输入、有效证据和私有配置须保留。

## 当前专项：代码库整理与架构改进

目标是交付可以继续开发的干净代码基线：入口和职责明确、必要实现集中、开发验证链路可靠、现有行为保持。当前已完成三路核查与隔离构建/API 基线，正在清理遗留实现、恢复默认浏览器回归并改进静态目录和资料包读取归属；用户 preview 尚未切换候选。总控自主决定清理、架构方案及集成取舍，不以用户挑选候选或逐项批准技术方案为前置。任务证据见 preview `.scratch/codebase-cleanup/receipt.md`。

- 删除前查清静态引用、动态注册、脚本、运行加载、测试及固定版本兼容用途；没有搜索命中不等于没有消费者。目录移动、改名、文件拆分和减少行数本身不构成收益。
- 架构改进以实际修改或验证的困难为依据。评估 module 的 interface 是否要求调用者知道过多内部细节，调整 seam 是否能提高 depth、locality 和 leverage；用 deletion test 判断抽象是否有用，只有实际变化的实现才引入 adapter。通用框架、额外分层和预想扩展不作为目标。
- 下表已有的日程缺项、Agent 暂停及人工验收保持各自状态。整理中发现的真实 bug、明显 UI 问题、lint 或测试失败须复现并处理；缺失的新功能不借整理名义扩入。暂停的 Agent 可检查现有消费者及回归，不恢复工具扩展开发。

### 执行顺序

1. **固定现场与验证基线。** 核对 preview 的分支、HEAD、未提交成果、工作树和实际运行入口，以启动时的集成版本固定输入。记录已有构建、静态检查和核心 HTTP/浏览器流程的结果，区分代码失败、环境缺失和尚未验证。运行使用隔离端口、数据及输出目录；验收前的代码不直接进入用户实例。完成条件：每项后续改动都有可比较的代码与运行基线。
2. **并行核查三条线。** 遗留与入口核查确认冗余实现和实际消费者；开发与验证核查确认启动、配置、工具、构建和测试可用性；架构核查结合近期代码修改，沿材料输入/识别/消费/输出及模块公共端口等真实路径检查职责和耦合。三者只读源码，各自只写独占任务产物。完成条件：覆盖范围和未覆盖项明确，候选均带路径、调用关系或复现证据、影响及验证方法。
3. **总控裁决并排序。** 合并重复发现，分别确定直接清理、先复现修复、必要架构改进和保留的项目。优先处理运行或验证阻塞，再处理有实际收益的结构问题；不因数量或体量小而优先。每个架构候选说明现状、目标、消费者、替代方案、失败语义及验证方式，必要时由另一 agent 提出反例。按 `improve-codebase-architecture` / `codebase-design` 形成临时可视化候选报告；用户已委托决策，候选选择和方案质询由总控完成，不停在等待用户选择。完成条件：本轮实施项与保留理由明确，报告只是中间产物。
4. **分批清理和重构。** 从固定 preview 基线创建临时分支/worktree，按依赖先后实施，每批有独立可验证结果。实际 bug 先沿用户路径 E2E 复现；结构改动先固定须保持的可观察行为。同步修改消费者，移除替代后的旧路径，避免长期保留双套实现。公共文件指定唯一写者，作者自验后提交。完成条件：本批目标行为和必要回归通过，代码与相关文档一致。
5. **独立审查、验收和集成。** 对固定提交按 `code-review` 做 Standards/Spec 审查，独立验收受影响的真实路径。总控负责冲突和集成后的组合验证；后续批次按依赖同步已验收的集成版本，不重放旧作者树增量。发现回归修复后再接续，测试通过后仅在新改动或新证据需要时补验。完成条件：审查发现已处置，preview 的集成版本与通过验证的候选一致。
6. **全局收尾并交接开发。** 核对剩余入口、调用关系、构建/启动、受影响的跨模块路径及文档指向；按下节逐项验收。永久说明只更新原有权威文档，过程记录放任务产物。清除本轮临时实例、无用输出和已集成临时 worktree；保留固定输入和可核查证据。完成条件：留下干净提交、最终回执、准确剩余事项和可直接执行的下一项产品任务。

执行中出现的新问题按上述步骤纳入；完成已选改进并达到验收条件后收尾，不通过不断提出假设性重构延长任务。

### 分工与接续

总控负责范围、决策、派发、公共文件、冲突和最终验收。原五个业务 session 保持待命，需要历史事实时由总控询问；本专项使用临时 subagents，不新增长期模块 session。

| 阶段与任务 | 模型 | effort |
| --- | --- | --- |
| 第一波：遗留与入口核查 | gpt-6-astra | medium |
| 第一波：开发与验证链路核查 | gpt-6-astra | medium |
| 第一波：架构核查与方案 | gpt-6-astra | high |
| 明确方案后的实现与清理 | gpt-6-astra | low |
| 复杂设计、困难修复或复杂逻辑审查 | gpt-6-astra | high |
| 常规独立核验与验收 | gpt-6-astra | medium |

第一波三个核查任务并行；实施阶段最多同时推进两个互不依赖的改动，实际写入使用独立 worktree，不假设 subagent 自动隔离。技能内部助手按[开发约定](../agents/module-development.md#模型与固定派发)继承调用方，其他路由及失败接续也沿该约定执行。

本专项详细发现、任务包和证据统一放 preview `.scratch/codebase-cleanup/`，总回执为其中的 `receipt.md`，执行时创建。记录固定输入、实际 agent/model/effort、验证命令与结果、集成提交和下一动作，使中断后可接续。专项结束后，本节收敛为当前结论、剩余问题和证据入口，不长期积累执行步骤与派发安排。

### 最终验收

- 各范围均有核查结论；已确认无用途的旧入口、重复实现和过渡路径已移除。保留项有当前消费者或具体必要性，不能用“可能有用”搁置判断。
- 实施的架构改进有调用链和真实行为证据，能说明哪些知识与修改集中到了所属 module，哪些调用者不再承担内部细节；独立审查没有遗留阻碍继续开发的问题。
- 干净检出的候选按已有说明配置后可构建和启动；实际存在的静态检查及应运行测试通过，发现的失败与不稳定性有处理结果。跳过、未验及外部环境限制单列，不记作通过，不削弱有效断言换取通过。
- 受影响的保存/刷新/重开、身份与数据隔离、模块往返、文件转换及输出按实际范围验证；涉及 UI 核对真实页面，涉及输出实际生成并打开。广泛共享改动补验各消费者，不以单个模块成功代替。
- 用户 preview 运行最终集成源码；源码热更新和服务重启链路按影响范围验证，私有配置与原有成果完整。工作树干净，无遗漏的作者增量、冲突或本轮临时运行进程。
- [剩余事项](#剩余事项)能准确区分产品缺项、观察、技术缺陷及人工验收。不得把发现的开发阻塞简单挪到待办后宣告完成；专项完成不代表全部产品功能或目标设备验收完成。

### 可选增强与明确暂缓

以下属于能力边界或待选增强，不自动进入核心待办：任意裸 TeX 纠错、教学环节自动划分、所有极端版式无损转换、精确单元格框选、OCR 生成 PDF 文字层、跨页/语义搜索、通用几何约束求解、复杂三维和多参数动画。现有原页/区域定位若不足以完成实际校对，或常用材料必须大量重录，则按具体失败纳入核心缺陷。

受管文件物理回收继续暂缓；业务条目永久删除与磁盘回收不同。已由用户移除的设置入口、自动整套 PPT 及其他范围外能力不因旧文档或测试重新恢复，范围以[PRODUCT_SCOPE](../PRODUCT_SCOPE.md)为准。

## 接续顺序与完成条件

下一轮先完成[代码库整理专项](#当前专项代码库整理与架构改进)，再按以下顺序恢复产品开发。

1. 先处理表中可复现的核心问题或明确选择的缺项；当前资料足够时 agent 自行验证，不把技术回归全部交给用户。
2. 材料质量与本机输出汇合后验证真实数学/备课/班级往返；目标设备单列，不阻塞有条件的本机工作。认证恢复专项可独立验证，不等待整站交付。
3. 全模块 Agent 保持暂停；恢复后再补其业务与数据/现场组合。手动模块的正常开发不等待 Agent。
4. 完整工作日汇合材料、数学、教学、身份和数据的具名结果，按矩阵独立验收；选定实际部署环境并取得对应动作许可后，验证同一交付版本，再由用户验收。

每个事项只有满足其具名结果才改变状态；保留问题归属、证据及下一动作。缺材料/环境标待验证，用户选择标待决定，代码已合入但未验证不写验收完成。
