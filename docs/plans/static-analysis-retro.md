# 静态检查与本轮复盘落实

## 目标与授权

用户在 2026-10-21 确认接入 Knip + Oxlint，并落实本轮复盘的其余改进。结果须保持现有功能与仓库健康；工具配置以准确、低噪声、少量维护为准，不为静态工具开发测试套件、自制检查框架或批量迁就规则改写业务。

本轮原始要求与完成证据一一核对：

| 要求 | 完成条件与归属 |
| --- | --- |
| 发现无用代码和明确代码问题 | 根 package 脚本、锁定开发依赖和 Knip/Oxlint 配置可从干净检出运行；入口、公开端口、动态加载、固定样本准确归属，具名报告经核对，无无理由的批量忽略 |
| 完成判断回到完整委托 | 开发约定要求派发与最终审查读取原始目标及有效调整；已有唯一任务记录继续使用，不新增重复治理文档 |
| 全面检查有覆盖依据 | 验收入口要求从真实入口、状态、消费者展开，独立审查检查遗漏；既有规则只补实际缺口 |
| 验证可靠且不浪费 CI | 保留实际行为断言与已有时序 Lessons；已知修改收敛后集中验收，不给每次编辑跑整套检查 |
| 按任务性质和影响处理范围 | 明确的小问题可顺手修；影响大且需要用户取舍的问题才进入 buffer；跨文件不自动等于需要决策，协作仍保持唯一写者 |
| 读取与证据管理节制 | 按任务定位章节，长日志先摘要和失败片段；CI 日志与大现场分开取用，保留必要失败证据；完成时清理可重建临时产物 |
| 问题说明可被用户理解 | 裁决请求包含模块/入口、操作、实际结果及建议变化 |

已采纳的 buffer 定义优先于旧文档“范围外一律收录”。已明确授权的任务内必要工作仍由 agent 完成，不借 buffer 转移责任。学期与反馈收件两个既有未决项保留。

- 起点：`5a69610f49ba48545cd23ff5bc13257a55f2de0e`，远端 trunk 无增量。

- 静态工具执行者：fresh context，`gpt-6.1-sol / medium`；唯一负责工具配置、根及 API/Web package、lock 和经消费者核对的机械清理。依赖归属按实际直接消费者修正，已有 SDK 固定版本保留；先报告告警分类与规则取舍，不靠改业务逻辑消除告警。
- 文档执行者：fresh context，`gpt-6.1-sol / medium`；负责开发约定、验收入口、代码标准、buffer 的既有权威位置。总控负责本记录、台账、CI 与 GitHub 工作流页，交叉信息通过回执同步。
