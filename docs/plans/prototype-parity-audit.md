# 全站原型对照清查

## 目标与前置

用户要求在原型功能差异收口完成后，再独立进行一次全站 UI/UX 对照。前置任务已由 [PR #48](https://github.com/DingJWuyu/TeachBuddy/pull/48) 完成独立审查、CI、preview 集成与现场清理，具名结果见[运行台账](run-state.md#核查入口)。本任务已可启动，尚未开始扫描；不将前一任务的定点验证当作本任务已完成。

目标是全站页面、布局、文案、动效与交互状态匹配 `docs/design-system/teachbuddy-app/` 和设计规范，保留用户已经裁决的差异。代码库、文档与运行入口继续保持健康。学期和反馈仍按根 [buffer](../../buffer.md) 暂缓，不擅自补产品需求；搜索无匹配仍保持简单空结果。

## 授权与边界

- 修复本轮对照发现的真实偏差，复用原型设计与现有模块职责，不自创审美、不增添说明或多余入口，不恢复已替代实现、无效测试或过时文档。
- 原型通常只读。只有用户已裁决偏离原型、且确实改变原型呈现或模拟行为时，才同步对应原型源码及必要构建产物。每处记录裁决与具体差异，沿设计规范使用现成组件、翻译和令牌，不顺带改版。
- 已知需核对的裁决是班级归档“先恢复上级，再恢复子项”。先判断原型是否需要同步，不能把实现错误反向写入原型来消除差异。
- 仅做真实接口接线必需的适配，不将服务器约束、未实现业务或外部环境不足伪装为已完成。新的产品取舍集中记录并交用户，不由检查者自行增加后端能力。
- 固定基线取前置任务完成后的 trunk，固定设计输入取同一基线的 Design System。按原有 Git 授权创建隔离现场、集中独立审查、PR CI、集成 preview；main、发布、真实模型费用与外部投递不在范围内。

## 执行与记录

启动时核对实际 Git、运行现场及设计输入，建立按真实页面与状态列出的覆盖表。八个产品分区及公共浮层都要有具名覆盖：账户与身份、工作台与设置、首页和助理、题库、资源库、数学工坊、日程、班级，以及帮助、归档、资料包和支持入口。

按独占目录派发 fresh-context 执行者，对照源码与可运行页面；总控拥有共享样式、组件、路由、翻译、文档、Git 和原型同步清单。每条发现应有实际触发、原型依据、实现位置和结果，区分视觉、交互、数据接线及明确批准的差异。公共成因集中修复，避免模块各自打补丁。

检查包括正常、空白、编辑、加载、失败、确认、返回和刷新状态；按相关界面覆盖中英文、深浅色、宽窄容器、辅助栏开合、键盘和焦点、拖拽及动效。复用现有样例与隔离 fixture，展示结果以实际页面为准。测试只保护值得长期维护的行为，修复后定点复核；大阶段集中验收，完整已配置回归交 CI，不反复本地全跑。

执行期间覆盖更新本记录的基线、分工、进度、发现及证据入口；跨阶段和接续事实不能只留聊天或忽略目录。正式行为、契约和运行信息只维护其权威文档，本页保留任务事实。

## 完成条件

1. 所有页面与主要交互状态都有具名原型对照结果，不能以首页截图或测试数量代替全站覆盖。
2. 发现的范围内偏差全部修复并复核；批准差异与暂缓事项明确，不用空 buffer 冒充完成。
3. 需要同步的原型改动都有用户裁决依据，遵守原设计规范，实际运行核对且未产生其他偏差。
4. 替代实现及失效内容清理，相关文档、链接、输入和构建路径保持准确。启动时同时核对根入口对已移除 `docs/rules/design-and-verification.md` 的过时指引，按 AGENTS 保护规则处理，不重建重复规则体系。
5. 固定候选独立 Standards/Spec 审查、必要验证、PR CI、preview 集成与核对完成，更新运行台账，保留有效证据并清理临时现场。
