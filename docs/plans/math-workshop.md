# 数学工坊后续开发边界

选择下一次数学任务时读本页；实际能力与验证入口读[数学规格](../features/math.md)，进度、缺口和授权统一读[项目状态](run-state.md)。界面规则读[设计与验证](../rules/design-and-verification.md)，任务接手与派发读[开发约定](../agents/module-development.md)。

## 范围

后续按独立数学模块设计，以制作、编辑、管理、导出和演示的完整流程为范围。班级教学的现有联动保留，暂不设计或扩展，也不将完善这些联动列为数学新功能的完成条件；实际影响既有联动时补验对应路径。这不授权拆分独立应用或重建公共支持能力。

一个入口、同一份作品承接公式、二维/三维构造、参数与教学步骤。自然语言是主要制作方式，直接手动制作也须有清楚入口。沿用已认可的布局与渐进呈现，保持全局顶栏原星芒图标；数学侧栏使用自有视觉。数学产品不恢复独立的“草稿”管理界面，自动保存、失败重试、未知结果、取消及冲突保护继续可靠工作。

GeoGebra 沿用固定源码构建的本地引擎；网页助理通过浏览器扩展连接正常 DeepSeek 账号，保留私有登录配置。正式分发所缺条件与后续扩展优化候选仅在项目状态维护，不自动扩大为全站 Agent 开发。

## 接续与完成

从最新 `preview/integration` 为已选定的完整改动目的创建短期现场，不恢复已删除的数学工作树作为前置。数学总控负责模块内讨论、派发与验收；项目总控负责公共文件、跨模块协调和最终集成。

按改动影响验证真实制作、保存重开、输出和必要的既有联动，复用未变化部分的具名证据。浏览器模型替身、本机真实模型与目标设备验证分别记录。满足任务判据后同步规格及项目状态，并按[集成后的清理](../agents/module-development.md#集成后的清理)完成收尾。
