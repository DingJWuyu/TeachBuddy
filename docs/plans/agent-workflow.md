# Agent 开发闭环改造

本页是当前工程改造的目标、阶段和完成依据。接手续做或判断整体完成时读取；全局现场与授权查[运行台账](run-state.md)。用户已确认原任务与访谈共识并授权实施，当前正在全仓调查。基线为 `71b6abf8aba732591906712f33eab520d00a80c0`，实施分支为 `refactor/agent-workflow-health`。

## 使用结果与范围

用户通过会话交代任务或指定 Issue，讲清需求后，Agent 能依据仓库持续推进实现、验证、审查及已授权交付。简短 prompt 和中途换接手者不应导致目标缩减、进度丢失或质量下降；用户不承担工程派工、技术调查和测试设计。

参照 Magpie 当前真实实现，吸收其有效文档组织、代码边界、验证与复盘机制。全面核查本仓受 Git 管理的业务代码、共享底座、文档、测试、脚本、配置、契约及固定输入，并按实际缺口改造；结构和文档职责清晰本身就是目标，不能只处理已经产生运行故障的部分。保留已有功能、数据及已认可体验，既有未实现产品需求不自动进入本轮。

现有集成是可复用基线，其具体证据见[核查入口](run-state.md#核查入口)。选择保留某部分须有核查依据；完成几个选定修改包不等于覆盖本任务。

## 已明确的工作方式

- 需求不清楚先追问，不能猜测开工；明确的 Issue 可作为需求依据，含糊 Issue 在原线程追问。技术事实由 Agent 查明。任务由用户交代或指定，本轮不建设自动发现、领取 Issue 的常驻调度或社区运营。
- 文件围绕完整职责聚合，接受稍大但职责完整的文件；同一业务规则有明确维护归属。拆分须有实际职责边界，不以文件短、层数多或全模块套同一模板作为质量指标。
- 文档优先按规格、契约、验收等类型组织，通过索引进入；各类只描述自己的责任，分类不拆得过细，值得合并则合并。按需要声明职责、维护方式与格式，部分文档可有模板，不强制每份都使用模板。
- Agent 只修改明确分配的范围。范围外值得改进之处和问题记入根 `buffer.md`，交用户、总控或后续 session 判断；条目本身不授予修复权限。本轮范围内的必要缺口不能移入 buffer 后算完成。
- `buffer.md` 仅保留尚未判断或安排的发现。正式纳入 Issue 或任务后移出，已解决或不采纳也移出；历史由 Git 和正式任务保留。允许有实际观察或明确源码依据的待核实线索，区分已知与未知；纯假设不收录，不为填写条目强迫范围外调查或测试。文件须有收录、去重、维护与移除规则。
- 重大 UI/UX 改动先让用户看可交互原型，既有模式内的小改直接实施。本轮保持已认可产品体验。
- 本地按受影响范围定点验证，大阶段集中审查与验收；复用有效证据，候选变化、失败或未解疑点才补验。淘汰过时或不保护实际行为的测试，避免理论极端情况和重复全量执行。
- 从实际交付和失败中沉淀可核查的经验，维护适用规则，减少后续重复返工。优先复用成熟工具和已有机制，不为完成流程另建任务控制平台或重复校验层。

具体文件布局、接口拆分、测试选择和派工由总控依据源码与参考项目决定，不逐项转交用户。main 合并、正式发布、公开部署、费用及外部账户继续沿运行台账的授权边界。

## 目标与完成判据

| 目标 | 必须获得的结果 | 完成依据 | 当前状态 |
| --- | --- | --- | --- |
| 需求接手 | 会话与指定 Issue 都能形成明确范围；歧义先解决，工程判断自主 | 可追溯的需求依据和实际任务接手记录，能区分未决需求与可实施内容 | 待整体验证 |
| 长程推进 | 原始目标、依赖、当前状态、阻塞、完成证据和下一步有唯一、可接手的任务记录 | 中途接手者无需旧聊天补课，能识别尚未完成的目标并正确续做 | 待整体验证 |
| 代码及文件职责 | 全仓目录和文件归属经过核查；不合理重叠、散落、跨边界访问和失效内容得到处理 | 完整覆盖记录、具体保留/调整依据、实际依赖核查与受影响功能验证 | 待全仓核查 |
| 文档体系 | 类型少而清楚，权威事实唯一，入口与维护方式明确，内容符合实现 | 文档归属核查、合并/删除后的引用与消费者完整、新 Agent 按任务获取足够信息 | 待全仓核查 |
| 验证与交付 | 测试保护当前行为，环境可重建，检查分工和独立审查能实际执行 | 有意义的回归、实际运行与输出证据；候选、审查及合入版本一致 | 待整体验证 |
| 经验复用 | 有依据的经验能在后续相关任务中被读到、应用并维护，避免规则持续堆积 | Lessons 与编码标准的职责、更新和升级路径清楚；实际交付中核对适用经验 | 待整体验证 |
| 范围外发现 | buffer 是可判断的发现入口，不是第二套任务进度或扩大范围的许可 | 职责与维护规则入库，收录、去重和转入正式任务的路径可用 | 待实现 |
| 实际自主交付 | 无会话前情的新 Agent 完成真实任务，经历中断接手，最终交付并保持库健康 | 至少一个涉及实际代码修改和运行验证的有价值任务走通完整链路；记录输入、交接、结果与必要人工介入 | 待演练 |

审计先建立全仓覆盖面，再按风险和职责深入。当前健康的实现保留，不为制造改动重排全部目录；文件数量、行数、删除量和测试通过数均不能单独证明目标完成。

## 阶段与依赖

```text
核对完整目标
  -> 全仓覆盖与 Magpie 对照，建立目标到实际缺口的对应关系
  -> 按职责和依赖实施，公共文件指定唯一写者，作者定点验证
  -> 用改造后的仓库做 fresh agent 实际交付与中断接手演练
  -> 对完整目标集中核验，补齐必要审查与 CI，获准集成并清理
```

调查与互不冲突的实施线可以并行；下游依赖的文档、接口或验证入口就绪后再交接。演练使用本轮有实际价值的任务，不增加无关产品功能；不得将只读问答、测试发现列表或作者自述替代实际执行。独立审查既检查改动质量，也核对本页所有目标的覆盖与未解缺口。

整体完成须同时满足上表、保留功能的必要验证、已授权集成和现场清理；有范围内必要缺口时继续推进或明确阻塞，不自行缩减原始目标。真实模型、邮件、设备等不受本轮替身验证证明的范围沿既有专项记录。

## 维护与接续

总控维护本页，每个大阶段或实质变化后覆盖更新当前状态，不追加互相冲突的历史状态。任务拆分后逐项关联上表目标、依赖和完成证据；稳定规范落入其权威文档后，本页使用链接，避免保存第二份规则。执行日志、模型回执和临时产物归任务证据，必要运行步骤不得依赖本机忽略目录。

下面的检查面共同覆盖本仓所有受管文件。每一面先确认文件归属和实际消费者，再深入职责或依赖存在疑点的部分；保留决定同样需要依据。后续实施项由具体发现确定，不用目录重排数量代表完成。

| --- | --- | --- | --- |

| B - 工作约定与文档 | 需求接手、长程记录、文档职责、buffer、经验与原型规则；同步全部引用与消费者 | A 的文档/参考结论；用户偏好已明确 | 总控先维护目标和现场，正式整理方案待调查结果 |
| C - 代码职责 | API、共享能力、Web、扩展的职责、接口及文件归属；保留业务行为 | A 的代码结论；先确定公共写入者及迁移依赖 | 待形成有事实依据的实施包，保留健康实现 |
