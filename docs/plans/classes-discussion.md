# 班级重做讨论（临时）

继续讨论新“班级”模块时读本页。这里保存当前共识与尚未确定的问题，供用户和 agent 接续；不是已实现能力、完整开发规格或执行删除的授权。完整讨论收敛后统一更新对应章节，不在每次确认单个选项时写入，也不累积对话流水账。

本轮只维护这份临时文档。现有[班级教学规格](../features/classes.md)、[产品范围](../PRODUCT_SCOPE.md)、代码、数据、导航与接口保持原状；实际能力和开发授权仍查[项目状态](run-state.md)及本次用户指令。获准实施后再同步正式规格、契约和验收依据，合并本页的有效内容。

## 定位与重做边界

- 新模块称为“班级”，目标是：**帮助老师记住班里的每个人，以及这个班正在经历的教学。**
- 分为“学生”和“班级整体”两部分。两部分的核心用途及 AI 接入边界已形成下述共识；具体输入处理、交互和接口仍待设计。
- 工作台供老师课后自己整理、回顾和思考，不在课堂中操作；座位图服务于课后的学生浏览和座位整理，不引入课堂点名、随机抽人等工具。
- 面向老师个人的实际便利，不覆盖教师生活的全部事务，也不扩展为学校或领导的管理系统。功能与录入负担保持简单，遵循 less is more。
- 用户已明确：现有“班级教学”可整体删除，由新“班级”替代；旧功能不构成新模块必须保留的需求。**当前只记录这个重做方向，尚未执行删除或重做。** 本轮也不绘制新草图。

## 学生：已达成的共识

### 座位图与个人页面

- 用对应实际教室的座位图展示学生，形象亲切；学生卡片或具体视觉形式尚未确定。
- 支持拖拽调整座位；点击学生进入个人页面，查看这个学生的信息、记录和成绩。
- 座位只是展示与入口，个人记录属于学生本人，不因换座位改变归属。

### 基本信息与自由记录

| 内容 | 约定 |
| --- | --- |
| 姓名 | 必需。 |
| 生日、兴趣、性格等 | 老师自行选择是否填写。性格使用自写描述，没有预置选项或强制标签；不要求补全学生画像。 |
| 自由记录 | 保存老师想记住的事，例如学生说过的话、一次交流、约定、学习观察或值得留下的瞬间。 |
| 组织方式 | 一件事完整写在一起，按时间回看，不要求选择类别或拆到多个栏目。 |
| 使用频率 | 随需要记录，不设置必须完成的每日评价、定期评语或逐人更新任务。 |

亲切感来自老师能用自己的方式记住学生；具体信息布局、记录编辑与检索交互待设计。

### 成绩的使用目标与输入

成绩帮助老师观察学生的正式考试表现，跨考试回看变化，并根据具体题目与结果判断相关问题是否改善。“可观测性、可评测性”是讨论目标，不表示系统已经能自动判断学习能力或知识掌握程度。

**成绩功能只围绕有正式试卷的考试。小测验、日常作业及其手工对错录入排除在当前范围之外。**

| 输入 | 当前约定 |
| --- | --- |
| 全班成绩 Excel | 包含总分和逐题得分，是核心输入。按一场考试集中导入，供班级和各学生共用，避免逐个学生重复填写。 |
| 电子试卷原卷 | 是核心输入，通常为 Word 或 PDF，也可能是图片。用于回看题目与对应成绩。 |
| 学生手写答卷 | 不作为功能成立所必需的输入，不依赖辨认每个学生的手写过程。 |

用户确认能取得成绩 Excel 和电子原卷；尚未检查真实样例。纸质成绩单不是额外必需输入，不围绕阅卷平台页面取数。文件导入、题目定位及成绩对应的具体实现尚未确定。

### 一场考试，同时服务学生和班级

- 一场考试的题目、逐题得分、总分是共同事实，电子试卷与 Excel 一次提供，学生与班级从不同角度查看同一批结果。
- 学生侧观察个人历次成绩、排名和相关题目的表现；班级侧的观察范围见下方“班级整体”。
- 考试与学生对应关系、考试时间、题目满分等比较背景需要明确；实际字段、导入校对和统计口径待结合样例确定。
- 跨考试观察是核心需求，不限于查看单次成绩。单次考试中的班级表现可作为个人表现的参考；排名纳入，当前讨论至少包含班内排名及其变化。

### 老师自己的题目标签

- 标签表达题目考查什么，例如“函数单调性”；老师在使用中自行填写、保存并长期复用，不依赖我们预设固定的地区、教材或知识分类。
- 创建一次后，自己的后续考试和不同班级都能复用。输入时提示已有标签，减少同一内容被不同名称分散；支持整理名称、合并重复标签。
- 一道题可以有多个标签。题目标注针对试卷做一次，全班共用，不要求逐个学生重复标注。
- 老师接受为试题补充或确认考查内容，不需要先建立完整知识体系或逐题撰写分析。
- 题目标签只组织考试证据；学生自由记录继续随手写，不增加分类要求。

### 统一的“成绩”观察视图

- 逻辑入口是“成绩”；是否独立页面、是否需要点击进入及具体布局尚未确定。
- 在同一视图中查看可视化趋势，通过标签和考试切换观察范围或查看明细；不把二者设计为必须二选一的产品入口。
- 整体观察包括历次分数、得分率、排名与班级参考；按标签回看相关题目的表现，按考试查看具体题目、得分与原题。
- 采用“整体变化、缩小范围、查看具体证据”的简单组织方式。趋势区、选择控件和明细区是讨论中的呈现思路，图表数量、种类、默认状态和布局未定。
- 图表描述已有考试结果：标签下的相关题目得分率不等于知识掌握度；综合题失分不能直接归因于所有标签；没有考到不记为零分。不同满分、难度及考查内容下的结果需保留背景，不凭曲线自动宣布能力提升或下降。

## 班级整体：已达成的共识

班级整体由**班级成绩观察 + 班级记录**组成。

### 班级成绩观察

- 复用同一批正式考试材料，查看班级整体成绩变化、题目与标签下的表现，支持跨考试回看。
- 将成绩分布纳入核心信息，结合平均水平理解全班情况，并能进一步查看具体学生。只看平均值不足以辨认大多数学生与少数学生的表现差异。
- 支持老师自己所教班级在**同一次考试、同一份试卷**下的横向对照，包括整体及具体题目表现。默认查看当前班级，需要比较时选择其他班级。
- 比较复用已有成绩与试卷，不要求老师另填分析。图表与统计口径待具体设计，不增加自动学习能力评级。

### 班级记录

- 老师课后自由记录这个班值得记住的事：教到哪里、共同遇到的问题、某种讲解的效果、尚未处理的事情或下一堂课的想法。
- 进度随手描述即可。老师自己掌握上下文，无需为维护进度上传教材、整理章节树或逐项更新已讲/未讲状态。
- 一件事完整写在同一条记录里；进度、观察和下一步想法可以自然连在一起，不要求填写独立栏目或先选类别。
- 旧班级教学的字段、资料关联和回顾工具不自动成为新方案的需求；记录的具体布局与回看方式另行设计。

## AI 接入：已达成的共识

### 入口与触发

- 老师在侧边栏 AI 助理中主动提问，助理再按需要读取数据、调用工具并给出分析与建议；不在导入考试后自动生成分析报告。
- 交互参照数学工坊的侧栏助理。数学工坊当前有专用适配，具体事实见[数学网页 AI](../features/math.md#geogebra-数学画布与网页-ai)，不据此假定新班级工具已接通。
- 班级的记录、成绩观察和证据回看在没有 AI 时也应独立成立。AI 接入消费模块已有能力；缺少接入支持时先设计必要接口，不为 AI 另加录入要求或扩展本轮模块范围。

### 数据与操作职责

- 班级模块拥有学生资料、学生与班级记录、试卷、成绩、标签及其业务操作，提供相应查询和统计能力。
- AI 助理负责理解问题、选择相关数据和工具、形成分析与建议。图表与 AI 使用同一套统计结果，分数、排名等由程序计算。
- AI 分析结果先留在对话中。老师明确要求保存时，助理可以调用模块的记录功能，例如将讨论后的下一堂课想法写入对应班级记录；分析本身不自动写入业务记录。
- 精确工具清单、读写参数、上下文传递及现有助理的接入缺口在实现设计时核对，不把讨论中的能力当作已实现接口。
