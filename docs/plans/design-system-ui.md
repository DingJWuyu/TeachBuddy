# Design System 前端迁移

接手、派发或验收本次全站 UI/UX 重构时读本页。总控维护当前目标、职责、依赖和证据；阶段结束、输入变化、阻塞或交接时覆盖更新。范围外功能差异只维护根 [buffer](../../buffer.md)，本页链接其条目，不建立另一份差异台账。工程通则沿[开发约定](../agents/module-development.md)、[代码标准](../code-standards.md)与 [Lessons](../../LESSONS.md)执行。

## 目标与固定输入

- 用户要求：把新版原型所有页面、状态、交互和动效一比一迁入正式前端，保持代码库和文档结构清晰，可持续维护。
- 设计输入：`5ef44923` 中的 [design-system](../design-system/README.md) 与 [teachbuddy-app](../design-system/teachbuddy-app/index.html)。原型组件、补丁与最终打包产物共同提供定位依据，原件保持不变。
- 实现基线：`5ef44923`；它在 `fa931d93` 上仅保全用户新输入和删除旧 `docs/rules/design-and-verification.md` 的动作。
- 工作现场：`TeachBuddy-ui`，分支 `feat/design-system-ui`。所有实施者在该任务工作树内按下表独占文件，Git 与集成由总控负责。preview 用户实例、main、资源库旧工作树、私有数据和凭据不属于并行写入范围。
- 目前状态：输入固定，开始并行源码迁移；尚未实现、验收或集成新版前端。

## 本次硬边界

1. 实现输入给出的全部效果，保留文案、层级、操作、动画、主题、语言和容器响应式；前端不自行增加说明、控件、页面或另一种设计。未覆盖状态记 buffer。
2. 已有能力接现有接口；原型新增、改变、隐藏或删除的功能与后端差异集中进 buffer。后端业务实现、存储、契约及接口行为不擅自增删改。班级页面开放沿单一模块目录装配，开放配置由总控协调。
3. 缺少后端支持的能力可保留前端本地模拟及其演示状态。模拟按账户和职责隔离，不能冒充已有接口、拦截全站网络或将演示数据混入真实保存；回执明确真实、模拟、未覆盖。
4. 被替代的旧视图、旧交互、重复样式和过期测试同批退役；仍有效的非呈现能力继续消费。数学旧源读取兼容不等于保留旧界面。不存在第二套旧版回退或复制 bundle 作为产品入口。
5. 行为、职责或入口变化同批更新其权威文档并删除失效内容；不恢复已删除的旧设计规则，不重复建立设计事实副本。按 writing-for-agents 维护唯一事实。
6. 自己引入的错误、遗漏、结构混乱和本任务完成所需问题留在任务内解决，不以 buffer 代替完成。
7. 局部只做定点反馈，大阶段集中验收与独立审查，CI 承担其完整回归。不逐次编辑跑全量，不写 UI 单元测试、实现镜像测试或臆想边缘用例。

## 实现安排与写入归属

## 依赖与持续推进

```text
固定输入与任务记录
  -> 公共导出/样式 + 各模块源码与接口梳理并行
  -> 外壳/账户/设置与六业务工作线并行落地
  -> 总控持续汇总，处理跨模块接线和旧实现清理
  -> 固定完整候选，集中视觉/交互/真实数据验收与独立审查
  -> PR/CI/preview 集成、体验核对、文档与现场收尾
```

模块作者在 `.scratch/design-system-ui/<工作线>.md` 留中间回执即可，必要接手事实由总控及时收进本页。禁止提交他人的半成品；作者完成写入后回报文件、覆盖项、缺口、实际验证与后续动作。一个等待不阻塞无依赖工作。公共接口如必须变动，由总控同步全部消费者。
