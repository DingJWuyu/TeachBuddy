# 单次任务包

给执行者的 prompt 保持短：背景、结果、必要资料、边界和完成条件。实现方案由执行者决定。编排者完整项目上下文不转抄给每个 worker。

## 可直接填写

```markdown
# <任务 ID / revision / attempt>

目标：<用户从哪里开始，完成后获得什么结果>。
工作位置：<唯一工作树、固定基线、当前分支或候选>。
边界：<负责模块；共享写者；本次 Git/运行权限>。
必读：<角色页>；<对应领域页及具体契约/行为章节>。
完成：<与本次目标对应的真实操作、保存或失败恢复；必要影响回归>。
回执：<输出路径>，记录版本、实际结果、证据、未决及下一步。
```

失败接续只补原复现与未完成项，不重讲整个项目。UI 任务补参考与动效规则，后端任务补相关接口与数据约束；普通文档任务不套产品验收。

## 由根保存，不堆进 prompt

任务、revision、attempt、session、实际模型/effort、启动状态、固定输入、候选、回执路径及已用权限。记录可放本树 `.scratch/<任务>/`；当前待办只在 [run-state](run-state.md)维护。

任务包必须能让执行者判断何时结束，但不新增用户未要求的苛刻门槛。具体的字段与接口交契约，具体方法交执行者。资料尚未生成时明确写待输入，不给不存在的路径冒充已完成契约。

模块阅读入口见[文档地图](../README.md#模块入口)，角色步骤见[协议](execution-protocol.md)。
