# 单次任务包

供设计者和编排者准备派发。prompt 只保留最小必要信息：清晰背景、目标、边界、适用规则和适度的完成条件。实现方法交给执行者，不把编排者脑测的步骤、额外限制或尚未确认的产品要求写成命令。

已有契约和规则按需引用，不复制全文，不要求每个 session 通读 DAG。完成条件来自已确认行为及与本次工作相关的质量要求；不为了“全面”再添一套验收门槛。缺少内部文件名或实现步骤不构成任务包缺口。

## 最小模板

```markdown
# <任务及版本>

- 背景与目标：为什么做，本次需要交付什么结果。
- 工作边界：工作目录、负责的模块或目录、相关权限；有共享文件时说明写者。
- 必要资料：当前任务真正需要的契约、行为、运行入口或 skill。引用已有来源。
- 完成条件：用户可观察的结果和适合本次任务的验证；实现路径自主决定。
- 回执：产物版本、实际结果、验证与未决问题，保存到指定位置。
```

仅在实际需要时补充失败复现、样本、环境限制或特殊规则。调查和文档任务不套产品实现的全部检查；用户要求的冷启动实验不得额外提示阅读路线。

## 编排记录

以下信息由编排者在台账或任务记录中保存，不必全部塞进给 worker 的 prompt：

- 任务版本、attempt、实际 harness/model/effort、session 和回执位置。
- 固定输入版本与候选版本；Git 管理的资料用 commit + path，未提交材料或外部样本才按需记录校验值。
- 依赖、并行 worktree、共享写入归属、已有授权和下一步负责人。
- 额度中断时记录原因及保留成果，不自动降级；困难实现升级 Astra high 时记录失败证据、已尝试方法和可接续的成果。

任务记录可放在 `.scratch/dag-dispatch/<节点>/<attempt>/task.md`。模型路由、回执和恢复规则见[执行协议](execution-protocol.md#orchestration)，当前状态见[运行台账](run-state.md)。不为任务包创建分发工具。

## 按需补充

- 前后端实现引用同版公共契约；接口内部如何实现由各执行者决定。模块或目录边界足够明确时，不必预列所有文件。
- UI 工作引用相关 UX 和设计规则；纯后端任务只读相关接口与数据要求。
- `code-review` 需要固定基线和进入候选提交的变更；沿用 skill 的双轴审查，不重复外派同内容审查。
- 阶段验收提供受测版本、相关场景和可运行入口；普通文档修正做必要自检即可。

产品行为或公共契约存在真实缺口时交设计者处理；实现方法、内部步骤和普通技术细节由执行者自主判断。
